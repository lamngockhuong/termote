Termote puts the terminal sessions of your machine, and the Claude Code or Codex running in them, on your phone or
another computer. It is one binary: the PWA, the terminal stream, the API and the login all live in it. You install
it with one command, then `termote start` registers it as a service of your user and starts it.

## Prerequisites

[tmux](https://github.com/tmux/tmux) on Linux or macOS (`sudo apt install tmux`, `brew install tmux`), or
[psmux](https://github.com/psmux/psmux) on Windows (`winget install psmux`); Herdr, Zellij and herdr-core work too
([backends](/installation/native/#prerequisites)), and [container mode](/installation/docker/) needs Podman or Docker
instead. No sudo or administrator rights are needed: everything goes into your home directory.

## Install

<Tabs>
  <TabItem label="Linux / macOS">

    ```bash
    curl -fsSL https://termote.ohnice.app/install.sh | sh
    termote start
    ```
  </TabItem>
  <TabItem label="Windows (PowerShell)">

    ```powershell
    irm https://termote.ohnice.app/install.ps1 | iex
    termote start
    ```
  </TabItem>
</Tabs>

<Steps>
1. The installer picks the newest stable release (1.0 or later), downloads the archive for your platform, checks its
   `.sha256` (always; there is no way to skip it) and puts the `termote` command on your PATH. It never starts
   anything.

2. `termote start` detects the terminal backend, creates the admin password and prints it once (in a terminal only), registers the
   server with your OS's service manager and starts it. See
   [what `termote start` does](/installation/native/#what-termote-start-does).

3. Open the URL it prints, by default http://127.0.0.1:7680 (Windows: http://127.0.0.1:7690), and log in as
   `admin` (or the name set with `--user`) with that password. Forgot it? `termote show-password`.

</Steps>

<Aside type="tip">
  If `termote` is not found right after the install, open a new terminal. On Linux/macOS the installer prints the
  `export PATH=...` line to add when `~/.local/bin` is not on your PATH yet.
</Aside>

## Open Termote on Your Phone

<Image src={screenshot} alt="Termote on a phone: the Sessions sheet lists each workspace and its agents, with how many wait on you" width={293} densities={[1, 2]} class="phone-shot" />

<Steps>
1. Make it reachable from the phone: `termote start --lan` on your home network, or
   `termote start --tailscale <host>` for HTTPS through [Tailscale](/installation/tailscale/), away from home too.
   The option is saved for the next start.

2. Run `termote url --qr` (or `termote panel`) and scan the QR code with the phone's camera, then sign in with the
   same name and password. To skip the password on the phone, [pair it](/usage/devices/) with a one-time code.

3. Add it to the home screen (Safari: **Share → Add to Home Screen**; Chrome: **Add to Home screen** or
   **Install app**) to open it like an app. On an iPhone or iPad, agent
   [notifications](/usage/settings/#notify-when-an-agent-needs-me) work only from the Home Screen app.

4. Open a pane running Claude Code or Codex, and switch to [Agent Chat](/usage/agent-chat/) to read and answer it.
</Steps>

## Pin a version, or repair an install

Set `TERMOTE_VERSION` to install one exact release (`X.Y.Z`, or `X.Y.Z-rc.N` for a pre-release):

<Tabs>
  <TabItem label="Linux / macOS">

    ```bash
    curl -fsSL https://termote.ohnice.app/install.sh | TERMOTE_VERSION=1.0.0 sh
    ```
  </TabItem>
  <TabItem label="Windows (PowerShell)">

    ```powershell
    $env:TERMOTE_VERSION='1.0.0'; irm https://termote.ohnice.app/install.ps1 | iex
    ```
  </TabItem>
</Tabs>

Without `TERMOTE_VERSION`, the installer leaves an existing install alone and tells you to run `termote update`.
With it, the installer puts that version beside the existing one and switches to it, which is also how you
rescue an install that no longer runs. Your config is kept either way.

`GH_TOKEN` or `GITHUB_TOKEN`, when set, only raise the GitHub API rate limit the installer uses to find the
newest release.

## Pre-releases

The installer, like `termote update`, only picks a pre-release (`X.Y.Z-rc.N`) when you name it with `TERMOTE_VERSION`
(or `termote update --version X.Y.Z-rc.N`). Without it, you get the newest **published** stable release (1.0 or later): a
release still waiting to be published already has its tag, but none of its files can be downloaded yet. The same
goes for a pre-release you name: until it is published, the install fails with `still publishing`.

This site serves the installer of the last stable release. To run a pre-release's own installer, take it from its tag
and still name the version:

<Tabs>
  <TabItem label="Linux / macOS">

    ```bash
    curl -fsSL https://raw.githubusercontent.com/lamngockhuong/termote/v1.13.0-rc.1/scripts/install.sh | TERMOTE_VERSION=1.13.0-rc.1 sh
    ```
  </TabItem>
  <TabItem label="Windows (PowerShell)">

    ```powershell
    $env:TERMOTE_VERSION='1.13.0-rc.1'; irm https://raw.githubusercontent.com/lamngockhuong/termote/v1.13.0-rc.1/scripts/install.ps1 | iex
    ```
  </TabItem>
</Tabs>

To go back to a stable release, run `termote update`. Until the final `X.Y.Z` is out, this is a downgrade (a
pre-release counts as newer than the release before it), which `update` makes with a warning.

<Aside type="caution" title="Coming from Termote 0.x">
  There is no upgrade from 0.x: 1.0 does not read the config or anything else 0.x left behind. Uninstall 0.x
  first, following the archived [0.x native](/0.x/installation/native/#uninstall) or
  [0.x container](/0.x/installation/docker/#uninstall) page, then install 1.0 as above.
</Aside>

## Commands

Flags use the same syntax on every OS, PowerShell included (`termote start --lan`).

| Command                   | What it does                                                                  |
| ------------------------- | ----------------------------------------------------------------------------- |
| `termote start [options]` | Save the options, register the service and start it                          |
| `termote stop`            | Stop the server (it starts again at the next login)                           |
| `termote restart`         | Stop and start with the saved options                                         |
| `termote status`          | Show what the running server reports (alias: `health`)                        |
| `termote logs [service]`  | View logs: `server`, `all` (default), `follow`, `clean`                       |
| `termote show-password`   | Show the saved username and password                                          |
| `termote pair [options]`  | Make a one-time code that signs a new device in (`--role view\|full`, `--name`) |
| `termote devices`         | List the paired devices; `devices revoke <id>` signs one out                  |
| `termote update`          | Update to the latest release, rolling back if the new one does not come up    |
| `termote uninstall`       | Remove the service, the command and the install (`--purge`: config and logs too) |
| `termote container <cmd>` | Run the server in a container: `up`, `down`, `logs [-f]`, `status`           |
| `termote link` / `unlink` | Create or remove the `termote` command in `~/.local/bin`                      |
| `termote version`         | Show the version                                                              |
| `termote serve`           | Run the server in the foreground (what the service runs)                      |
| `termote`                 | Interactive menu                                                              |

`termote help` prints the same list with every option. The old `install` command is gone: typing it only
points you to `termote start` and `termote container up`.

## File Locations

| What            | Linux / macOS                                                  | Windows                                                    |
| --------------- | -------------------------------------------------------------- | ---------------------------------------------------------- |
| Install root    | `~/.local/share/termote` (`$XDG_DATA_HOME/termote`)            | `%LOCALAPPDATA%\termote`                                   |
| Versions        | `versions/<v>/bin/termote`                                     | `versions\<v>\bin\termote.exe`                             |
| Current version | `current` symlink to `versions/<v>`                            | `current.txt` plus the `bin\termote.cmd` launcher          |
| Command         | `~/.local/bin/termote`                                         | `%LOCALAPPDATA%\termote\bin`, added to your user PATH      |
| Config          | `~/.config/termote/config` and `secret` (`$XDG_CONFIG_HOME`)   | `%APPDATA%\termote\config.json` (password DPAPI-encrypted) |
| Logs, PID file  | `~/.local/state/termote/` (`$XDG_STATE_HOME`)                  | `%LOCALAPPDATA%\termote\state`                             |
