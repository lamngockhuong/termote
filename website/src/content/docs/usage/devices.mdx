Everyone signs in with the one saved password. To let another device in without handing that password
over, pair it: you make a one-time code, the new device types it, and from then on that device signs in
by itself. Each paired device has a name and a role, and you can sign it out on its own without
changing the password. Pairing needs sign-in, so it is off with `--no-auth`. What a paired device can
and cannot be trusted with is on [Security Model](/usage/security/).

## Pair from the terminal

```bash
termote pair                      # a view-only device (the default), signed in for 30 days
termote pair --role full --name "Work phone"
termote pair --expires 7d         # 12h, 7d, 2w: 1 hour to 400 days
termote pair --expires never      # no time limit
```

It prints a code like `ABCDE-FGHJK`, a link and a QR code. The code works once and expires after 5
minutes. The device it pairs stays signed in for 30 days unless `--expires` says otherwise; past that it
is signed out and has to be paired again. On the new device, scan the QR code, open the link, or open `/pair` on your Termote address and
type the code. If you gave no `--name`, the new device is asked for one, else it is named after its
browser.

## Pair from a signed-in device

On a device with full access, open **Settings > Devices > Pair a device**, pick **View only** or full
access, how long it **Stays signed in for** (30 days unless you pick another, or **Never**), optionally
name it, and show the code or QR code to the new device. The same list shows each paired device with its
role, when it was last used, who paired it and until when it is valid, with a **Revoke** button.

Only the password pairs a full device: signed in with it, or `termote pair` on the server. A paired
device pairs view-only devices only, and a device with a time limit pairs none that outlasts it (no
**Never**).

<Aside>
  An iOS home-screen app does not share cookies with Safari, so a scanned QR code cannot sign it in. Open
  the app's sign-in page and use **Have a pairing code?**.
</Aside>

## List and revoke

```bash
termote devices                   # id, name, role, paired, last used, valid until, paired by
termote devices revoke <id>       # sign it out and close its open terminals
```

Revoking takes effect at once, and also revokes every device the revoked one paired. Logging out on a
paired device revokes only that device: the devices it paired stay, listed as paired by a removed
device. A new password (`termote start --fresh`) signs out every paired device. After revoking a full
device, also run `termote start --fresh`: it had a shell (see [Security Model](/usage/security/#if-a-device-is-lost)).

A device paired with **Never** stays signed in until you revoke it, so give Termote a host name of its
own: a cookie is shared by every service on the same host name.

## View only

A view-only device can watch the terminal, the Chat view and Files/Changes, and nothing else: the server
refuses every write, and the interface hides the controls that would write, under a **View only** banner.

- **Terminal:** it cannot type, resize or scroll the shared view. With tmux it follows each session's
  active window; with Herdr it picks tabs on its own device but cannot scroll the history.
- **Needs tmux 3.2 or later:** with an older tmux, or psmux, the terminal is not available to a view-only
  device and the banner says so. Chat and Files still work.
- **Files:** only for a pane inside a git repository, and never a file marked as sensitive (`.env`,
  keys, and so on).
- **Chat:** it reads the conversation and any open dialog, but cannot answer it.
- **Everything the agent printed is readable.** Pair a view-only device only with someone you would let
  look over your shoulder.
- No push notifications, and at most 2 open terminals per view-only device.

## Container

`termote container up` keeps the paired devices in a volume named `termote-state-<uid>`, so they survive
`container up` and `update`. `termote container down` keeps it; `termote uninstall --purge` removes it.
