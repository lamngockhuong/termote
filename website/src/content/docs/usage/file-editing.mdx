A text file opened in [Files](/usage/files/) or [Changes](/usage/changes/) can be edited and saved there; a file can also be created, deleted, renamed or moved from Files.

## Editing a File

The pencil button (**Edit**) in a text file's bar turns its text into an editor, with
**Cancel** and **Save** in place of the other buttons. It is meant for small changes, such as
turning `status: review` into `status: approved` in a record's front matter, without asking the
agent or typing `sed`.

On a computer with a mouse the editor shows line numbers and colors the code, and has the keys
below. On a phone or a touch tablet the text is in a plain text box, as it always was. If the
editor cannot load (the connection dropped), the plain text box takes its place with
`Could not load the editor` and **Retry**: what you typed is kept either way.

| Keys                                   | What they do                                                  |
| -------------------------------------- | ------------------------------------------------------------- |
| Ctrl+S (Cmd+S on a Mac)                | Save                                                          |
| Ctrl+F (Cmd+F on a Mac)                | Find in the file; Enter or F3 goes to the next match, Escape closes |
| Ctrl+H                                 | Find and replace (Cmd+Alt+F too on a Mac)                     |
| Ctrl+G                                 | Go to a line                                                  |
| Ctrl+D (Cmd+D on a Mac)                | Select the next occurrence of the selection                   |
| Alt+drag, Ctrl+Alt+↑/↓ (Cmd+Alt+↑/↓ on a Mac)                 | Several cursors                                               |
| Ctrl+Z, Ctrl+Shift+Z (Cmd+Z, Cmd+Shift+Z on a Mac)                   | Undo, redo                                                    |
| Tab, Shift+Tab                         | Indent, unindent                                              |

Ctrl+H and Ctrl+G are the Ctrl key on a Mac too: Cmd+H hides the browser there, and Cmd+G finds
the next match. Tab indents inside the editor; to move the focus out with the keyboard, press
Ctrl+M (Shift+Alt+M on a Mac), then Tab. Font size, tab size, line wrapping and Vim keys are in
Settings → Files (see [Settings](/usage/settings/#editor)). With Vim keys on, the keys are Vim's
(`/` finds, `:w` saves), except Ctrl+S, which still saves.

A search result opens the editor at the match when the file is being edited, and Edit in
Changes opens it at the first change of the diff.

- A Markdown file is edited beside its preview (see [Editing Markdown](#editing-markdown)). A CSV or TSV file shown
  as a table is edited in the table (see [Editing a Table](/usage/file-previews/#editing-a-table)); shown as its
  source, or opened from Changes, it is edited as its source.
- Ctrl+S (Cmd+S on a Mac) saves. Cancel, or Back, with unsaved changes asks
  `Discard changes?` first.
- Line breaks stay as the file had them: a file with Windows line breaks (`\r\n`) keeps them.
- The text being edited stays while you switch views or tabs, or the panel closes and opens
  again. Each file keeps its own unsaved changes, so several files can be edited at once; a file
  edited from Changes shares its text with the same file in Files. It is kept only in the page's
  memory, never in the browser's storage, so closing or reloading the
  app loses it (a phone may close an app left in the background).
- In **Changes**, the diff of a file the working tree still has as text has the same Edit button
  (**Edit working copy** on the staged side: the working tree's file is what is saved). After
  saving, the diff of what is not staged shows, read again; when the file then matches the
  index, the list shows with `No changes left in <file>`.

When saving does not go through, your text stays in the box:

| Shown                                                 | What to do                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `The file changed on the host since you opened it`    | Something (often the agent) wrote the file meanwhile. **Reload** reads it again and drops your text; **Copy my text** copies it first. A save never overwrites the other change. |
| `This pane's folder changed`                           | The pane moved to another directory. Copy your text, then Cancel to see the file there.             |
| `Not sure the file was saved. Saving again is safe.`   | The connection dropped or the server did not answer within 30 seconds. Save again: the same text is not a conflict. |
| `The server can't write this file`                     | The file is read-only, belongs to another user, or its folder cannot be written                    |
| `The file system there is read-only`                   | The file is on a read-only disk or mount, such as a container volume mounted read-only             |
| `The host's disk or quota is full`                     | The host's disk, or your disk quota, has no room left                                              |
| `Line 3 has "😀", which Shift-JIS can't hold`          | The file's encoding has no such character (see [Encodings](#encodings)). Change it, or save as UTF-8 |
| `Reload the app to save this file`                     | The text was kept by an older version of Termote, for a file that is no longer UTF-8. Copy your text, reload the app and open the file again |

Some files have no Edit button, because the server would refuse the save: a symbolic link (or a
file reached through a linked folder), a file with several hard links, a file that mixes line
break styles or holds a NUL character, a file over 1 MiB, an image, a file that would not encode
back to its own bytes (see [Encodings](#encodings)), and a file in Termote's own data or upload
folders. A file that may contain secrets can be edited once it has been shown.

<Aside type="caution">
  A save replaces the file with a new one in the same folder. If the agent writes the same file
  in the instant between the last check and the replacement, its change is lost. The new file
  keeps the old one's permissions, but not extended attributes or ACLs.
</Aside>

A view-only session (once that role exists) has no Edit button. Until the server enforces roles,
this is only hidden in the app.

### Editing Markdown

A Markdown file being edited shows in one of three layouts, picked with the button next to
**Save** (in the **More actions** menu on a phone) and remembered on this device:

| Layout                           | What shows                                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| Source and preview (the default) | The editor on the left, the file rendered on the right                                           |
| Source                           | The editor alone                                                                                 |
| Preview                          | The rendered file alone. The editor is only hidden: undo and the cursor are still there when it comes back, and Ctrl+S still saves |

- Side by side needs a mouse and a Files view at least 768 px wide: widen the side panel, or open
  the file in a window of its own. Narrower, or on a touch screen, the button switches between the
  source and the preview, and the layout picked comes back once there is room.
- The preview follows what you type a moment after you stop (a little later in a draft of more
  than 65,536 characters). A Mermaid diagram keeps its last picture while its source is typed, and is drawn again
  once the source has not changed for a moment; a source that cannot be drawn yet says why under
  the diagram's bar.
- Side by side, the two scroll together: scroll either one, and the same part of the file comes to
  the top of the other.
- A link of the preview opens the other file; Back returns to the draft, with the editor where it
  was.
- A draft of more than 262,144 characters shows as its source, with
  `Too large to preview: shown as source`.

#### Pasting an Image

Paste an image (a screenshot, a picture copied from another app) into the editor of a Markdown
file, and it is saved on the host next to the file: in the file's `assets` folder when there is
one, else in the file's own folder, named `pasted-<date>-<time>.png` (or `.jpg`, `.gif`, `.webp`).
`![Uploading …]()` stands at the cursor while it is sent, then turns into a link to the image,
relative to the file, such as `![pasted-20261027-090507](assets/pasted-20261027-090507.png)`. Undo
takes the link out; the image stays on the host.

- PNG, JPEG, GIF and WebP, up to 10 MB and 40 megapixels. HEIC (an iPhone photo) is refused: share
  the photo as JPEG.
- Copying from a spreadsheet or a web page puts text on the clipboard too: that pastes as text.
- No folder is made and no file is replaced: when the name is taken, the image gets `-2`, `-3` and
  so on.
- Several images pasted in a row are sent one after another.
- When the draft is discarded, or the placeholder deleted, before the image arrives, no link is
  added: a message says where the image was saved. A save meanwhile writes the placeholder into the
  file, and the message says so.
- A folder that may hold secrets (`.ssh` and the like) takes an image only when the file being
  edited was shown on purpose.
- The preview never loads an image: it shows as a link, `image: <name>`, that opens it in Files.

### Encodings

The second line of a text file's bar names its encoding after its size, such as
`12.0 KiB · Shift-JIS`. Files reads and saves:

- UTF-8, with or without a byte order mark (`UTF-8 with BOM`);
- UTF-16 LE and UTF-16 BE with a byte order mark;
- Shift-JIS and EUC-JP, recognised when their bytes are valid and enough of the text is Japanese
  (kana and kanji).

A save writes the file back in its own encoding, with its byte order mark and its line breaks:
the bytes you did not edit stay exactly as they were.

- Tap the encoding to read the file again as another one (**Reopen with encoding**). This is how
  a UTF-16 file without a byte order mark, or a short Shift-JIS file without kana, opens: it shows
  as `Not previewable`, with **Open with encoding…** under its name. Reopening is off while the
  text being edited has unsaved changes (`Save or discard your changes first`). The choice lasts
  for that tab only: a file opened in a new window, or opened again later, has its encoding found
  again.
- **Save as UTF-8**, in the same menu for a file not in plain UTF-8, asks first, then writes the
  file as UTF-8 without a byte order mark. Tools that read it in the old encoding then show its
  text wrongly.
- A few Shift-JIS files decode but would not encode back to the same bytes: characters of the IBM
  extension area, such as 髙 and 﨑, have two codes. Such a file has no Edit button, and the menu
  says `Can't be edited in this encoding`; save it as UTF-8 to edit it.
- A file with bytes that are not valid in its encoding (a damaged file, or one read as the wrong
  encoding) shows them as �. It cannot be edited, nor saved as UTF-8, since those bytes would be
  lost: the menu says `Can't be edited: some bytes are not valid in this encoding`. Try another
  encoding.
- In Shift-JIS and EUC-JP, characters an iPhone, iPad or Mac types that the file holds in another
  form are saved in that form: 〜 → ～, − → －, ‖ → ∥, ¢ → ￠, £ → ￡, ¬ → ￢, — → ―, ¥ → ￥. Any
  other character the encoding cannot hold, such as an emoji, stops the save with its line:
  `Line 3 has "😀", which Shift-JIS can't hold. Change it or save as UTF-8`. It is never replaced
  by `?`.
- Other encodings (Windows-1252, Latin-1, GBK, Big5, ISO-2022-JP and so on) are not read: such a
  file shows as `Not previewable`. A short one can pass for Shift-JIS by chance; Reopen with
  encoding shows it as another one, and saving cannot damage it unnoticed, since the save writes
  back exactly the bytes you did not edit.

## Creating a File

The **New file** button (a page with a plus) at the top of Files asks for a path from the pane's
directory, such as `docs/notes/today.md`. It starts with the folder you last tapped in the tree.
**Create** makes an empty file, and every folder on the path that is missing, then opens it in
the text box to type its contents and **Save**, in a tab of its own. The button shows over the
tree only, not while a file is shown.

- An existing file or folder is never replaced: the box says
  `A file or directory of that name already exists`, with **Open it** to open that one instead.
- A name that usually holds secrets (`.env.local`, for example) asks
  `This name usually holds secrets. Create it anyway?` once; the new file then opens without
  asking to show it.
- When the connection drops before the server answers, the box says
  `The file may have been created. Refresh to check.`, and **Refresh** reads the tree again.

**New folder**, in a folder's menu or the tree's (see [Right-Click Menus](/usage/files/#right-click-menus)),
asks the same way and makes an empty folder, which then shows open in the tree. The same names are
refused, and the same answers given, as for a file.
- Closing the box while **Create** runs does not stop it: the file is still made and shows in the
  tree, but it does not open.
- The folders made for the path stay when a later step fails, as with `mkdir -p`. A new file left
  empty stays too.

| Shown                                          | Why                                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `Part of this path is a file, not a directory` | A folder on the path is a file                                                                      |
| `Part of this path is a symbolic link`         | A folder on the path is a symbolic link: nothing is ever created through one                        |
| `Files can't be created there`                 | A path Termote never serves (see [Never Shown](/usage/security/#never-shown)), or its own data or upload folders    |
| `The server can't create a file there`         | The folder cannot be written                                                                        |
| `The file system there is read-only`           | The folder is on a read-only disk or mount, such as a container volume mounted read-only            |
| `The host's disk or quota is full`             | The host's disk, or your disk quota, has no room left                                               |
| `This name can't be used`                      | An empty part (`a//b`, a trailing `/`), a part that ends in a dot or a space, a control character such as a line break, more than 32 levels or 1024 bytes, or on Windows one of `<>:"\|?*` |

<Aside type="caution">
  A new file can be one that another tool reads or runs by itself, such as
  `.claude/settings.local.json`, `.vscode/tasks.json` or a file under `.github/workflows`.
  Anyone who can sign in to Termote can already run commands in the terminal, so this allows
  nothing new, but check what you create in such places.
</Aside>

A view-only session (once that role exists) has no New file button either; until the server
enforces roles, it is only hidden in the app.

## Deleting a File

A file or an **empty** folder can be deleted from Files, three ways: **Delete** in the **⋯** menu
of a row in the tree (with a mouse the button shows on hover or focus; on a touch screen it is
always there), the Delete key on a focused row, or the **Delete** button in the header of an open
file (not while it is being edited). A dialog shows the full path and asks first; **Cancel** has
the focus, so pressing Enter does not delete.

- A deleted file is not erased: it moves to Termote's trash on the host. A toast says
  `Deleted <name>` with **Undo** for 10 seconds, which puts it back where it was (it never
  replaces anything now there). A deleted empty folder is made again by Undo.
- The trash keeps a file for 7 days, at most 1 GiB in all (the oldest go first), and never
  removes one younger than an hour. After the toast is gone, open the [Trash](#the-trash) to get
  it back.
- A folder that is not empty is not deleted, and neither is the root itself.
- Deleting asks the server to check that the file is still the one you saw. If something (often
  the agent) changed it meanwhile, nothing is deleted.
- On another file system than the trash's (WSL's `/mnt/c`, a mounted volume, the container's
  `/workspace`), the file cannot be moved to the trash. The dialog then asks a second time,
  `Delete permanently? This cannot be undone.`, and only after that deletes it, with no Undo. In
  the container, every delete under `/workspace` is permanent in this way.
- A file whose name usually holds secrets is marked `This is a sensitive file` in the dialog.

| Shown                                                              | Why                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `The folder is not empty`                                           | Only an empty folder is deleted                                    |
| `The file changed since it was read`                                | Something changed the file after the dialog read it                |
| `Part of this path is a symbolic link`                              | Nothing is deleted through a link, and a link itself is not deleted |
| `This file has several hard links; delete it from a terminal`       | Another name would keep the file                                   |
| `The server can't delete this`                                      | The file belongs to another user                                   |
| `The file system there is read-only`                                | The file is on a read-only disk or mount                           |
| `Too large to delete here; use the terminal`                        | The file is over 512 MiB                                           |
| `Deleting is not available on this server`                          | The server has no usable trash                                     |

A view-only session (once that role exists) has no Delete button; until the server enforces
roles, it is only hidden in the app.

<Aside type="note">
  `termote uninstall` keeps the trash and prints its path; `termote uninstall --purge` removes it
  too. See [Uninstall](/installation/native/#uninstall).
</Aside>

### The Trash

The **Trash** button in the Files header (a full session on a server with a trash, also with a
file open and in a Place) opens a sheet listing what was deleted under the folder shown, newest
first: the name and its folder, whether it was a file, a folder or a discarded change in
[Changes](/usage/changes/#staging-unstaging-and-discarding), when, its size and `Removed by <date> at the latest`. The list is
read each time the sheet opens.

- **Restore** puts an entry back where it was, never replacing anything there. A sensitive file
  asks first. A discarded change puts the discarded text back over the file, only while the file
  is still what the discard left; an open tab of the file and Changes read it again.
- **Delete permanently** removes one entry for good, after asking. This works for something
  deleted a moment ago too.
- **Empty trash** removes the entries the sheet shows, after asking, and no other: something
  deleted meanwhile, on this device or another one, stays (and its Undo still works). When more
  than 500 entries are kept, only the 500 newest show and are emptied; the list is read again and
  the older ones show next.
- An entry already restored or removed elsewhere leaves the list with
  `Already restored or removed`.
- Only a full session sees the Trash: a view-only one has no button.

<Aside type="caution">
  The Trash shows only what was deleted while the folder shown was the root. Something deleted
  from another folder, before a `cd` into a subfolder or from a Place or repository that holds this
  folder, is in that folder's Trash: open it there. A file on another file system than the trash
  is deleted for good, so it is never in the Trash.
</Aside>

## Renaming or Moving a File

A file can be renamed from Files: **Rename** in the **⋯** menu of its row in the tree, or the
**Rename** button in the header of an open file (not while it is being edited; a file with unsaved
changes is renamed from its row). On a phone, a finger resting on a row opens the same menu. The
dialog shows the path from the pane's directory with the name, without its extension, selected.

- Change the folders in the path to move the file. A folder that does not exist yet is created.
- Nothing is ever replaced: if a file or folder of the new name exists, the dialog says so and
  offers **Open it**.
- The file's open tab, its unsaved changes and its editor in Changes follow it to the new path,
  in every pane showing the same directory. Saving afterwards writes the new path.
- A toast says `Renamed <old> to <new>` (or `Moved <name> to <folder>`) with **Undo**, which
  renames it back. Folders made for the move stay. A file whose old name the server would not
  accept as a new one (one ending in a dot or a space) has no Undo.
- Changes then shows a deleted file and an untracked one, as after `mv`, until you stage them;
  Termote does not run `git mv`.
- Only files are renamed, not folders or links.
- A file whose name usually holds secrets, before or after, is renamed after a second ask.

| Shown                                                   | Why                                                                        |
| ------------------------------------------------------- | -------------------------------------------------------------------------- |
| `A file or directory of that name already exists`       | The new path is taken; nothing was replaced                                |
| `This file no longer exists`                            | Something removed or moved the file after the tree was read                |
| `<path> has unsaved changes. Save or discard them first` | The file at the new path is being edited                                   |
| `The file changed while it was being renamed`           | Something replaced the file during the rename; nothing was moved           |
| `Can't move a file to another file system`              | The new folder is on another disk or mount; a file is never copied         |
| `The file is open in another program on the host`       | Windows: another program holds the file open                               |
| `Part of this path is a symbolic link`                  | Nothing is renamed through a link                                          |
| `The server can't rename this file`                     | The file or its folder belongs to another user, or the folder is protected |
| `The file system there is read-only`                    | The file is on a read-only disk or mount                                   |

A view-only session has no Rename.
