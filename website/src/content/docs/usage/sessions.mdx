Termote models terminals as three levels — **group → tab → pane** — regardless of backend.
With the default tmux backend a group is a tmux session and a tab is a tmux window; panes are
only used by the Herdr backend.

With tmux, every session on the tmux server appears as a group, including sessions you started
yourself outside Termote (`tmux new -s work`): anyone signed in to Termote can switch to them and
type into them. Termote's own session (`main` unless `TMUX_SESSION` says otherwise) is always
listed first. Each device remembers which session it shows; within a session, every device
attached to it shares the current window.

## Default Session

Fresh installs start with a single **Shell** session (group). Create additional groups as
needed for different workflows (e.g., Claude Code, Copilot, builds).

## Managing Sessions

### Desktop

- **Switch**: Click session in left sidebar or in the **session tabs** in the header row (if enabled)
- **Edit**: Double-click session name, or hover and click pencil icon
- **Remove**: Hover and click X icon (requires 2+ sessions), then confirm with "Close session"
- **Add**: Click "New session" in the sidebar, or the "+" after the session tabs
- **Collapse sidebar**: Click the collapse icon (top-right of sidebar) to show icons only — maximizes terminal width
- **Fullscreen**: Click the fullscreen button in the header to enter fullscreen mode
- **Session tabs**: Browser-like tabs that share the header row, for quick tab switching on desktop. Can be toggled via Settings → Sessions → "Show session tabs"

### Mobile

- **Switch**: Tap the session chip in the header ("Open sessions menu") to open the sessions list as a bottom sheet, then tap a session. The sheet opens scrolled to the current session
- **Current session**: The top of the sheet shows the current session with **Edit** and **Delete** buttons, so neither needs a scroll or a swipe. Delete asks for confirmation and is hidden when only one session is left
- **Edit**: Swipe left on session, tap Edit
- **Remove**: Swipe left on session, tap Remove, then confirm with "Close session"
- **Add**: Tap "New session" in the header of the sessions sheet; once it is created, the sheet closes on the new session
- **Sessions waiting on you**: When another session has an agent waiting on you, the session
  chip shows how many, in red, in place of its arrow

### What runs in a session

Each session in the sidebar and in the mobile sheet shows the commands running in its panes under
its name (`bash, vim`), and the Herdr pane strip shows each pane's command under the pane's name.
Only the first word of each command's name is shown (`npm`, never `npm run dev`), never its
arguments. The confirmations to close a session, a pane or a group add what will be stopped
(`Running: bash, vim.`), as the last poll saw it, so a command started a few seconds earlier may
be missing. An idle pane shows its shell (`bash`).

### Groups: tmux sessions and Herdr workspaces

When the server can manage groups, every group has a header with a **⋯** menu, even a single
tmux session:

- **New**: **New tmux session** (tmux) or **New workspace** (Herdr), under **New session** in the
  sidebar or at the top of the mobile sheet, asks for a name and a directory: an absolute path on
  the host, or empty for your home directory. Its first tab opens once it is created. A name
  already taken, a relative or missing directory, or a file is refused with the reason, and what
  you typed stays.
- **Rename**: in the **⋯** menu; the name is edited in place. Termote's own tmux session (`main`)
  cannot be renamed.
- **Close**: in the **⋯** menu; it asks first and says how many tabs end with it. Closing
  Termote's own tmux session starts a new, empty one right away, and every device viewing it
  reconnects to that. A Herdr workspace with worktrees is closed in Herdr, or after removing
  them.

The directory check only catches mistakes: the shell that opens can still `cd` anywhere. On
Windows, the directory must be on a drive letter (`C:\work`), and psmux names and directories
cannot contain `#`.

### Reordering tabs and workspaces

Tabs keep the order they were made in until you move them, and Termote shows the order the
backend keeps, so Herdr's own tab bar and sidebar agree with it.

- **Desktop**: drag a tab in the sidebar above or below another tab of the same group; a line
  shows where it lands. With a tab focused, **Alt+↑** and **Alt+↓** move it one place.
- **Mobile**: the **Current session** row of the sessions sheet has **↑** and **↓** buttons that
  move the tab on screen within its group.
- **Herdr workspaces**: **Move up** and **Move down** in a workspace's **⋯** menu, or drag its
  header on desktop. A repository's workspace moves together with its worktrees, as in Herdr; a
  linked worktree cannot be moved on its own.

The controls are hidden while the agent filter or "blocked first" sorting is on, since the list on
screen is then not the real order; a line in their place (the **Current session** row, a
workspace's **⋯** menu) says what to turn off to get them back. Not supported: tmux sessions (tmux has no session order), tmux
older than 3.2, psmux on Windows, Herdr older than 0.8.0, and Herdr on Windows for now.

<Aside type="caution">
With tmux, a tab's id is its window number, and moving a window renumbers the windows it passes.
Termote keeps your unsent Chat message, attached images and unsaved file edits with their window,
but a link to a tab (or another device's saved selection) that named a renumbered window opens
another tab afterwards.
</Aside>

### Filtering by Agent Status

When at least one session runs a coding agent, a filter bar appears above the session list (in
the desktop sidebar and in the mobile sessions sheet):

| Filter      | Lists                                       |
| ----------- | ------------------------------------------- |
| `All`       | Every session                               |
| `Needs you` | Sessions with a pane whose agent is blocked |
| `Working`   | Sessions with a pane whose agent is working |
| `Agents`    | Sessions running any coding agent           |

- Each filter shows how many sessions it lists. Counts are per session, not per pane, and a
  session with one blocked and one working pane counts under both.
- While a filter is on, groups with no matching session are hidden, and groups with one are
  shown open. Clearing the filter puts every group back the way you left it.
- With no match, the list says so and offers **Show all**.
- The collapsed desktop sidebar lists only the matching sessions too, and a dot on its expand
  button shows that a filter is on.
- The filter is saved on this device. With no agent in any session, the bar is hidden and every
  session is listed, whatever filter was saved.
- To keep blocked sessions at the top of each group instead, see
  [Blocked Sessions First](/usage/settings/#blocked-sessions-first).

## Deep Links

Every screen has an address you can copy and open later or on another device:

```text
<base>/#/s/<group>/<tab>[/<pane>][?view=terminal|chat|files]
```

- `group`, `tab` and `pane` are the IDs from `/api/mux/snapshot`. With tmux and Termote's own
  session, `group` is the session name and `tab` the window index (`#/s/main/0`); another session
  uses tmux's session id, `group` `$3` and `tab` `$3:1` (URI-encoded), which stays the same when
  the session is renamed but changes when the tmux server restarts. There is no `pane`. With Herdr they are the IDs
  Herdr assigns to the workspace, tab and pane.
- Opening a link selects that group, tab and pane once the session list has loaded. An unknown ID
  keeps the current session and shows a toast.
- `view` is used only when that view is available; otherwise the terminal opens.
- A link only selects. It never sends keys and never creates or closes a session. With tmux,
  selecting changes the current window, which every client of that tmux session shares.
- Switching session, tab or pane updates the address bar without adding history entries, so
  copying the address is enough. **Copy link** in the **More** (⋯) menu copies it to the
  clipboard.
- `termote url` prints a link from the command line, and the [Herdr plugin](/usage/herdr-plugin/)
  opens one on the Herdr pane you are on.

## Herdr Backend

Native installs ([`termote start --mux herdr`](/installation/native/#herdr-backend)) and the container
([`termote container up --mux herdr`](/installation/docker/#terminal-backend)) can use Herdr instead of tmux.
It changes the session model in two ways:

- **Panes**: a Herdr tab can have more than one pane. When it does, a **pane strip** appears
  below the tab bar to switch between them; a tmux tab never shows this strip (it never has
  more than one pane). Each pane shows the command it runs under its name. To close a pane, click the X next to its name (shown on the streamed pane,
  and on the others on hover or on touch screens), then confirm with "Close pane". The other panes
  of the tab stay open; a tab's last pane is closed by closing the tab.
- **Agent status badges**: each pane can show a small icon — idle, working, blocked, or done —
  reflecting the coding agent Herdr detected in that pane. Badges refresh at most once per the
  configured **Session poll interval** (Settings → Sessions), not instantly.

<Aside type="caution">
  Selecting a tab or pane in the PWA never changes what is shown on the Herdr desktop — it only
  changes which pane this client streams. There is no "show on desktop" action. In the container,
  Herdr runs inside it and sees only the container's terminals.
</Aside>

## Connection Indicator

The header displays a real-time connection status indicator showing your link to the server:

| Status        | Indicator | Meaning                                     |
| ------------- | --------- | ------------------------------------------- |
| Connected     | Green dot | Server online, terminal responsive           |
| Connecting    | Blue dot  | Establishing connection to server            |
| Disconnected  | Red dot   | No connection to server (clickable to retry) |
| Error         | Red X     | Connection error occurred                   |

The indicator auto-detects disconnects on both the snapshot polling and the terminal
WebSocket. Click it when disconnected to manually retry.

<Aside type="tip">
  Sessions survive network disconnects. Reconnect to pick up where you left off.
</Aside>

## tmux Commands

```bash
# List windows (sessions)
tmux list-windows

# Create new window
tmux new-window -n myproject

# Switch to window
tmux select-window -t 0

# Kill window
tmux kill-window -t 0
```

### Worktrees (Herdr)

With Herdr 0.9.2 or later (not yet on Windows), a workspace in a git repository can open git
worktrees as workspaces of their own, from its **⋯** menu:

- **New worktree** asks for a branch, a base and an optional name. A new branch is made from the
  base (**Current HEAD** by default, or one of the repository's local branches); a branch that
  exists is checked out as it is, so the base is hidden. Herdr picks the folder
  (`~/.herdr/worktrees/<repo>/<slug>`, the branch in lowercase letters, digits and `-`, so
  `feat/x` and `feat-x` would share one and the second is refused), and the new workspace opens once it is made.
- **Open worktree** lists the repository's other worktrees: one already open is shown, a closed
  one is opened.
- **Remove worktree**, on a worktree's own workspace, names its branch and folder and asks first.
  It deletes the folder, files git ignores (`.env`, `node_modules`) included, and closes the
  workspace; the branch is kept. A worktree with uncommitted or untracked changes is asked about a
  second time: removing it then loses those changes and ends its terminals first.

A worktree's workspace shows its branch next to its name. Creating and removing run git with your
own config, hooks included, as typing the command would. Branch names with spaces, control or
invisible characters are refused.

## API Endpoints

Sessions are managed via termote's `/api/mux/*` endpoints:

| Endpoint                       | Method      | Description       |
| ------------------------------- | ----------- | ------------------- |
| `/api/mux/snapshot`             | GET         | List all groups/tabs/panes |
| `/api/mux/tabs`                 | POST        | Create tab (body: `{groupId, name}`) |
| `/api/mux/tabs/{id}/select`     | POST        | Switch tab (or, for Herdr, the streamed pane) |
| `/api/mux/tabs/{id}`            | PATCH       | Rename tab (body: `{name, key}`; the tab's `key` refuses a stale id with 409) |
| `/api/mux/tabs/{id}?key=`       | DELETE      | Remove tab (same `key` check) |
| `/api/mux/tabs/{id}/move`       | POST        | Move a tab within its group (body: `{index}`; answers its new `id`) |
| `/api/mux/groups/{id}/move`     | POST        | Move a Herdr workspace (body: `{index}`) |
| `/api/mux/panes/{id}`           | DELETE      | Close a pane (Herdr only, else 501) |
| `/api/mux/groups`               | POST        | Create a group (body: `{name, cwd}`) |
| `/api/mux/groups/{id}`          | PATCH       | Rename a group (body: `{name}`) |
| `/api/mux/groups/{id}`          | DELETE      | Close a group and everything in it |
| `/api/mux/worktrees?groupId=`   | GET         | A workspace's worktrees and local branches (Herdr) |
| `/api/mux/worktrees`            | POST        | Create a worktree (body: `{groupId, branch, base, label}`) |
| `/api/mux/worktrees/open`       | POST        | Open a worktree (body: `{groupId, branch}`) |
| `/api/mux/worktrees/{id}`       | DELETE      | Remove a worktree workspace (body: `{force, path, branch}`) |

## Troubleshooting

### Session not persisting

1. Check tmux is running: `tmux list-windows`
2. Check termote logs: `termote container logs` (container) or `termote logs server` (native)

### WebSocket / terminal errors

1. Check termote logs: `termote container logs` or `termote logs server`
2. The terminal WebSocket is `/api/mux/stream`, served by termote itself
3. Check server health: `termote status` (container: `termote container status`)
