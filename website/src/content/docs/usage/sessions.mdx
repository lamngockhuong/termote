Termote models terminals as three levels — **group → tab → pane** — regardless of backend.
With the default tmux backend a group is a tmux session, a tab is a tmux window and a pane is a
pane of that window.

With tmux, every session on the tmux server appears as a group, including sessions you started
yourself outside Termote (`tmux new -s work`): anyone signed in to Termote can switch to them and
type into them. Termote's own session (`main` unless `TMUX_SESSION` says otherwise) is always
listed first. Each device remembers which session it shows; within a session, every device
attached to it shares the current window.

## Default Session

Fresh installs start with a single **Shell** session (group). Create additional groups as
needed for different workflows (e.g., Claude Code, Copilot, builds).

## Managing Sessions

### Desktop

- **Switch**: Click session in left sidebar or in the **session tabs** in the header row (if enabled)
- **Edit**: Double-click session name, or hover and click pencil icon
- **Remove**: Hover and click X icon (requires 2+ sessions), then confirm with "Close session"
- **Add**: Click "New session" in the sidebar, or the "+" after the session tabs
- **Collapse sidebar**: Click the collapse icon (top-right of sidebar) to show icons only — maximizes terminal width
- **Fullscreen**: Click the fullscreen button in the header to enter fullscreen mode (not shown where the browser cannot go fullscreen, such as iPhone)
- **Session tabs**: Browser-like tabs that share the header row, for quick tab switching on desktop. Can be toggled via Settings → Sessions → "Show session tabs"

### Mobile

- **Switch**: Tap the session chip in the header ("Open sessions menu") to open the sessions list as a bottom sheet, then tap a session. The sheet opens scrolled to the current session
- **Current session**: The top of the sheet shows the current session with **Edit** and **Delete** buttons, so neither needs a scroll or a swipe. Delete asks for confirmation and is hidden when only one session is left
- **Edit**: Swipe left on session, tap Edit
- **Remove**: Swipe left on session, tap Remove, then confirm with "Close session"
- **Add**: Tap "New session" in the header of the sessions sheet; once it is created, the sheet closes on the new session
- **Sessions waiting on you**: When another session has an agent waiting on you, the session
  chip shows how many, in red, in place of its arrow

### What runs in a session

Each session in the sidebar and in the mobile sheet shows the commands running in its panes under
its name (`bash, vim`), and the Herdr pane strip shows each pane's command under the pane's name.
Only the first word of each command's name is shown (`npm`, never `npm run dev`), never its
arguments. The confirmations to close a session, a pane or a group add what will be stopped
(`Running: bash, vim.`), as the last poll saw it, so a command started a few seconds earlier may
be missing. An idle pane shows its shell (`bash`).

### Groups: tmux sessions, Herdr workspaces and Zellij sessions

When the server can manage groups, every group has a header with a **⋯** menu, even a single
tmux session:

- **New**: **New tmux session** (tmux), **New workspace** (Herdr) or **New Zellij session** (Zellij), under **New session** in the
  sidebar or at the top of the mobile sheet, asks for a name and a directory: an absolute path on
  the host, or empty for your home directory. Its first tab opens once it is created. A name
  already taken, a relative or missing directory, or a file is refused with the reason, and what
  you typed stays.
- **Recent**: above the name, the dialog lists the groups created last with a directory (up to
  20, five until **Show more**), the same list on every device. A tap fills in the name and the
  directory; you still press **Create**. A name an open group uses becomes `name-2`, `name-3`, …
  The ✕ beside an entry removes it on every device. A group made in the home directory is not
  listed, and a view-only device does not see the list.
- **Rename**: in the **⋯** menu; the name is edited in place. Termote's own tmux session (`main`)
  and the Zellij session `main` cannot be renamed.
- **Close**: in the **⋯** menu; it asks first and says how many tabs end with it. Closing
  Termote's own tmux session starts a new, empty one right away, and every device viewing it
  reconnects to that (the same holds for the Zellij session `main`). Closing a Zellij session
  deletes it: Zellij cannot resurrect it. A Herdr workspace with worktrees is closed in Herdr, or
  after removing them.

The directory check only catches mistakes: the shell that opens can still `cd` anywhere. On
Windows, the directory must be on a drive letter (`C:\work`), and psmux names and directories
cannot contain `#`. A Zellij session name cannot contain `/`, start with `-`, be `help` or
`options`, or be too long for Zellij's socket path.

### Split windows (tmux)

A tmux window split into several panes shows a **pane strip** below the tab bar: one button per
pane, with the command it runs and its agent badge. The terminal always shows the whole window,
so picking a pane gives it tmux's focus: what you type goes there, and the Chat and Files views
follow it. That focus is tmux's own and shared with every client: the tmux client on your
desktop moves too, and when the focus changes on the desktop, Termote follows at its next poll.
On a view-only device the strip only shows the panes. To close a pane, click the X next to its
name and confirm; a window's last pane is closed by closing the tab. psmux (Windows) shows one
pane per window.

### Pane layout

The **Pane** menu in the header (the split icon) changes the layout of the tab on screen, acting on
the pane shown:

- **Split right** and **Split down** open a new pane beside or under it, in its directory.
- **Zoom** makes the pane fill its tab; choose it again to bring the other panes back.
- **Swap with next pane** trades places with the next pane of the pane strip.
- **Resize left/right/up/down** (desktop only) moves the pane's edge by 5 cells. The menu stays
  open, so you can click again.
- **Close pane** closes the pane shown after a confirmation, once the tab has another pane.

Split, zoom, swap and resize are also in the command palette, under **Panes**, with **Previous
pane** and **Next pane**, which you can give a key in Settings → Shortcuts. The menu is not
shown on a view-only device, nor on a backend without these actions: psmux (Windows), Herdr
older than 0.9.3 or on Windows, and Zellij 0.45.0. The palette still lists the commands there, greyed out with the
reason.

The backends differ in a few ways:

- **tmux**: a split leaves the focus where it was, so the pane shown stays the same. Zoom gives
  the zoomed pane tmux's focus, for every client, your desktop's included.
- **Herdr**: on a computer, a tab of 2 to 4 panes shows its panes side by side, as the Herdr desktop
  arranges them (see [Herdr Backend](#herdr-backend)), and the menu offers everything. Where
  Termote shows one pane at a time (the pane strip: a phone, more panes, the setting off), zooming,
  swapping and resizing would change only the Herdr desktop, so the menu offers **Split right**,
  **Split down** and **Close pane** alone, and the palette greys the others out ("Changes only the
  Herdr desktop"). While the tab is zoomed, **Zoom** ends the zoom. After a split, Termote works on
  the new pane; Herdr's own focus stays put.
- **Zellij**: after a split, Termote shows the new pane. Swap turns the panes of the tab around one
  place, so the pane strip keeps its order while the panes move on screen. Zoom moves every client
  viewing the tab, your own Zellij included, to the zoomed pane. Through the API, a split into a
  directory other than the pane's own is refused (Zellij ignores it).

### Reordering tabs and workspaces

Tabs keep the order they were made in until you move them, and Termote shows the order the
backend keeps, so Herdr's own tab bar and sidebar agree with it.

- **Desktop**: drag a tab in the sidebar above or below another tab of the same group; a line
  shows where it lands. With a tab focused, **Alt+↑** and **Alt+↓** move it one place.
- **Mobile**: the **Current session** row of the sessions sheet has **↑** and **↓** buttons that
  move the tab on screen within its group.
- **Herdr workspaces**: **Move up** and **Move down** in a workspace's **⋯** menu, or drag its
  header on desktop. A repository's workspace moves together with its worktrees, as in Herdr; a
  linked worktree cannot be moved on its own.

The controls are hidden while a search, the agent filter or "blocked first" sorting is on, since the list on
screen is then not the real order; a line in their place (the **Current session** row, a
workspace's **⋯** menu) says what to turn off to get them back. Not supported: tmux and Zellij sessions (neither has a session order), tmux
older than 3.2, psmux on Windows, Herdr older than 0.8.0, and Herdr on Windows for now.

<Aside type="caution">
With tmux, a tab's id is its window number, and moving a window renumbers the windows it passes.
Termote keeps your unsent Chat message, attached images and unsaved file edits with their window,
but a link to a tab (or another device's saved selection) that named a renumbered window opens
another tab afterwards.
</Aside>

### Searching Sessions

With more than one session, a magnifier in the desktop sidebar's header (and in the mobile sessions
sheet's header, next to **New session**) opens a search box above the list. Type part of a name and
the list keeps only the sessions that match.

- A session matches on its name, its description, its group's name and branch, the agents it runs,
  the processes in its panes and their labels. Case and Vietnamese diacritics do not matter, and
  with several words each must match.
- The search narrows the [agent filter](#filtering-by-agent-status): a session must match both.
  Groups with no match are hidden and groups with one are shown open, as with the filter.
- **Enter** opens the first session in the list and **↓** moves to it (desktop). **Esc** clears
  the box, and on an empty box closes it.
- On desktop the search stays after you pick a session, so you can move between the matches. The
  sessions sheet opens on the whole list each time.
- The search is not saved, and it never takes keys away from the terminal: it reads keys only
  while its box has focus.

### Filtering by Agent Status

When at least one session runs a coding agent, a filter bar appears above the session list (in
the desktop sidebar and in the mobile sessions sheet):

| Filter      | Lists                                       |
| ----------- | ------------------------------------------- |
| `All`       | Every session                               |
| `Needs you` | Sessions with a pane whose agent is blocked |
| `Working`   | Sessions with a pane whose agent is working |
| `Agents`    | Sessions running any coding agent           |

- Each filter shows how many sessions it lists. Counts are per session, not per pane, and a
  session with one blocked and one working pane counts under both.
- While a filter is on, groups with no matching session are hidden, and groups with one are
  shown open. Clearing the filter puts every group back the way you left it.
- With no match, the list says so and offers **Show all**.
- The collapsed desktop sidebar lists only the matching sessions too, and a dot on its expand
  button shows that a filter is on.
- The filter is saved on this device. With no agent in any session, the bar is hidden and every
  session is listed, whatever filter was saved.
- To keep blocked sessions at the top of each group instead, see
  [Blocked Sessions First](/usage/settings/#blocked-sessions-first).

## Deep Links

Every screen has an address you can copy and open later or on another device:

```text
<base>/#/s/<group>/<tab>[/<pane>][?view=terminal|chat|files|changes][&solo=1][&file=<path>[&staged=1][&orig=<path>]]
<base>/#/overview[?solo=1]
```

- `group`, `tab` and `pane` are the IDs from `/api/mux/snapshot`. With tmux and Termote's own
  session, `group` is the session name and `tab` the window index (`#/s/main/0`); another session
  uses tmux's session id, `group` `$3` and `tab` `$3:1` (URI-encoded), which stays the same when
  the session is renamed but changes when the tmux server restarts. There is no `pane`. With Herdr they are the IDs
  Herdr assigns to the workspace, tab and pane. With Zellij they come from the session name, so
  renaming a session outside Termote changes them (renaming it in Termote keeps your selection).
- Opening a link selects that group, tab and pane once the session list has loaded. An unknown ID
  keeps the current session and shows a toast.
- `view` is used only when that view is available; otherwise the terminal opens.
- `file` opens a file in the **Files** view (`view=files`), or its diff in **Changes**
  (`view=changes`; `staged=1` for the staged side, `orig` for a rename's old path). The path is
  relative to the pane's directory, URI-encoded, and the server opens it under that directory as
  it does any other file: a path that leaves it, or a file that is not there, shows "File not
  found or not allowed" and nothing else.
- `solo=1` opens the link in a focus window (see [Open in a New Window](#open-in-a-new-window)).
- A link only selects. It never sends keys and never creates or closes a session. With tmux,
  selecting changes the current window, which every client of that tmux session shares.
- Switching session, tab or pane updates the address bar without adding history entries, so
  copying the address is enough. **Copy link** in the **More** (⋯) menu copies it to the
  clipboard.
- `termote url` prints a link from the command line, and the [Herdr plugin](/usage/herdr-plugin/)
  opens one on the Herdr pane you are on.

### Open in a New Window

On a desktop (a mouse and a wide screen), a file, a diff, a tab, a pane or the agent overview can
open in a window of its own, next to the one you work in:

- **A file**: **Open in new window** in the file's header in the Files panel.
- **A diff**: the **Open in new window** button next to **Copy path** in the Changes panel.
- **What is on screen** (the pane, its tab, or the overview): **Open in new window** in the
  **More** (⋯) menu, or the **Open in new window** command of the command palette.
- **Any tab or pane**: in the command palette's tab list (`@`), <kbd>Ctrl</kbd>+<kbd>Enter</kbd>
  (<kbd>⌘</kbd>+<kbd>Enter</kbd> on a Mac) opens the highlighted one in a new window instead of
  switching to it.

Installed as an app (Chrome or Edge), it opens a new app window; in a browser, a new tab.
<kbd>Shift</kbd>+click asks for a separate, sized window instead. A blocked pop-up says so. Phones
and tablets have no second window, so the action is not offered there.

The new window is a **focus window** (`solo=1` in its address): it shows only that target, without
the sessions sidebar, the tab bar or the pane strip. A file or diff fills the window; restoring its
panel shows the terminal next to it. It keeps nothing on the device: the main window's open file
tabs, selected tab, pane views and unsaved drafts stay as they were, whatever you open or close in
the focus window. Settings such as the theme or the font size are this device's and are saved as
usual. **Open in main window** in its header hands the target back to the window that opened it (or
a new one when that window is gone) and closes the focus window. A focus window opens no further
windows and does not switch to another tab or pane: those actions are offered in the main window.

Files open editable, as in the main window. When the same file is open in both and one saves first,
the other's save is refused with "changed on the host", as with any other change made elsewhere.

<Aside type="caution">
  With tmux, a focus window on a tab that is not the current window of its session switches that
  session's window, for every client attached to it, including the main window and other devices
  (see [the link rules](#deep-links) above). Herdr and Zellij pick the pane per window and are not
  affected.
</Aside>

Each window that shows a terminal holds one terminal stream; a focus window on a file holds none
while the file covers the terminal, and Herdr's side-by-side panes hold one each. The server keeps
at most 16 streams with Herdr and 8 with tmux and Zellij, and closes the oldest for a new one. Only that window's stream closes, never the session or what runs in it, and the window
shows **Disconnected by a newer window — Reconnect** instead of reconnecting on its own (two windows
would otherwise push each other out in turn). Click it, or the connection indicator, to reconnect.

## Herdr Backend

Native installs ([`termote start --mux herdr`](/installation/native/#herdr-backend)) and the container
([`termote container up --mux herdr`](/installation/docker/#terminal-backend)) can use Herdr instead of tmux.
It changes the session model in two ways:

- **Panes**: a Herdr tab can have more than one pane. When it does, a **pane strip** appears
  below the tab bar to switch between them. On a computer, a tab of 2 to 4 panes also shows its
  panes side by side, in the Herdr desktop's layout, all at one font size that fits the window:
  click a pane (or pick it in the pane strip) to type into it; Herdr's own focus does not move.
  A zoom, a split or a resize made on the desktop shows within a second. A pane closed by a
  newer window shows **Reconnect** in its own box. Termote shows one pane at a time instead on a
  phone, on a view-only device, with more than 4 panes, on Herdr older than 0.9.3 or on Windows,
  when the panes would be too small to read, or with **Show herdr panes side by side** off
  (Settings → Terminal). A tab past 4 panes says so in a notice: when it goes past, or when it opens past them, once per tab until the page reloads. Each pane shows the command it runs under its name. To close a pane, click the X next to its name (shown on the streamed pane,
  and on the others on hover or on touch screens), then confirm with "Close pane". The other panes
  of the tab stay open; a tab's last pane is closed by closing the tab.
- **Agent status badges**: each pane can show a small icon — idle, working, blocked, or done —
  reflecting the coding agent Herdr detected in that pane. Badges refresh at most once per the
  configured **Session poll interval** (Settings → Sessions), not instantly.

<Aside type="caution">
  Selecting a tab or pane in the PWA never changes what is shown on the Herdr desktop — it only
  changes which pane this client streams. There is no "show on desktop" action. In the container,
  Herdr runs inside it and sees only the container's terminals.
</Aside>

## Zellij Backend

Native installs on Linux and macOS ([`termote start --mux zellij`](/installation/native/#zellij-backend))
and the container ([`termote container up --mux zellij`](/installation/docker/#terminal-backend)) can use
Zellij 0.45.0 or later instead of tmux. A group is a Zellij session, a tab a Zellij tab and a pane a terminal
pane (plugin panes are not shown). Every running session of yours is listed, as with tmux; sessions kept only
for resurrection (EXITED) are not. When no session runs, Termote starts `main`.

- **Tabs**: each device selects its own tab, as with Herdr; your own Zellij client never moves. A tab with
  more than one pane shows the **pane strip**. Tabs can be renamed, closed and reordered; sessions cannot be
  reordered.
- **New tab**: Zellij lays a tab out only when a client is attached to the session, so adding a tab to a
  session nobody has open (no terminal and no Termote on it) says "open this Zellij session in a terminal
  (or in Termote) before adding a tab".
- **Terminal**: Termote's terminal is a real Zellij client, so Zellij's tab bar and status bar show, and a
  tab takes the size of the smallest client viewing it. It is in Zellij's locked mode, so the toolbar's Ctrl
  keys reach the pane; your own locked-mode bindings still act (the default config's Ctrl g unlocks). A click
  on another pane or tab inside the terminal closes the stream, and Termote reopens it on its pane.
- **Scrolling**: there is no server-side scrolling. The mouse wheel scrolls through Zellij itself, for every
  client viewing that pane; Select text still shows the pane's history.
- **View-only devices** see the pane's screen, without history scrolling or input.
- **Chat view** (Claude Code, Codex) and **Files/Changes** work on Linux and macOS. On macOS a session
  renamed after it started has no Chat view until it is restarted.

<Aside type="caution">
  After upgrading Zellij, Termote refuses to create sessions while sessions of the old version still run;
  restart those sessions (or Termote).
</Aside>

## Connection Indicator

The header displays a real-time connection status indicator showing your link to the server:

| Status        | Indicator | Meaning                                     |
| ------------- | --------- | ------------------------------------------- |
| Connected     | Green dot | Server online, terminal responsive           |
| Connecting    | Blue dot  | Establishing connection to server            |
| Disconnected  | Red dot   | No connection to server (clickable to retry) |
| Error         | Red X     | Connection error occurred                   |
| Disconnected by a newer window | Red dot | A newer window took this window's stream (clickable to reconnect) |

The indicator auto-detects disconnects on both the snapshot polling and the terminal
WebSocket. Click it when disconnected to manually retry.

<Aside type="tip">
  Sessions survive network disconnects. Reconnect to pick up where you left off.
</Aside>

## tmux Commands

```bash
# List windows (sessions)
tmux list-windows

# Create new window
tmux new-window -n myproject

# Switch to window
tmux select-window -t 0

# Kill window
tmux kill-window -t 0
```

### Worktrees (Herdr)

With Herdr 0.9.2 or later (not yet on Windows), a workspace in a git repository can open git
worktrees as workspaces of their own, from its **⋯** menu:

- **New worktree** asks for a branch, a base and an optional name. A new branch is made from the
  base (**Current HEAD** by default, or one of the repository's local branches); a branch that
  exists is checked out as it is, so the base is hidden. Herdr picks the folder
  (`~/.herdr/worktrees/<repo>/<slug>`, the branch in lowercase letters, digits and `-`, so
  `feat/x` and `feat-x` would share one and the second is refused), and the new workspace opens once it is made.
- **Open worktree** lists the repository's other worktrees: one already open is shown, a closed
  one is opened.
- **Remove worktree**, on a worktree's own workspace, names its branch and folder and asks first.
  It deletes the folder, files git ignores (`.env`, `node_modules`) included, and closes the
  workspace; the branch is kept. A worktree with uncommitted or untracked changes is asked about a
  second time: removing it then loses those changes and ends its terminals first.

A worktree's workspace shows its branch next to its name, indented under its repository's
workspace as in Herdr; collapsing the repository's workspace hides its worktrees too, and its
status badge then shows theirs as well. Creating and removing run git with your
own config, hooks included, as typing the command would. Branch names with spaces, control or
invisible characters are refused.

## API Endpoints

Sessions are managed via termote's `/api/mux/*` endpoints:

| Endpoint                       | Method      | Description       |
| ------------------------------- | ----------- | ------------------- |
| `/api/mux/snapshot`             | GET         | List all groups/tabs/panes |
| `/api/mux/tabs`                 | POST        | Create tab (body: `{groupId, name}`) |
| `/api/mux/tabs/{id}/select`     | POST        | Switch tab (tmux; Herdr and Zellij select client-side and answer 501) |
| `/api/mux/tabs/{id}`            | PATCH       | Rename tab (body: `{name, key}`; the tab's `key` refuses a stale id with 409) |
| `/api/mux/tabs/{id}?key=`       | DELETE      | Remove tab (same `key` check) |
| `/api/mux/tabs/{id}/move`       | POST        | Move a tab within its group (body: `{index}`; answers its new `id`) |
| `/api/mux/groups/{id}/move`     | POST        | Move a Herdr workspace (body: `{index}`) |
| `/api/mux/panes/{id}`           | DELETE      | Close a pane (psmux answers 501) |
| `/api/mux/panes/{id}/split`     | POST        | Split a pane (body: `{direction: right\|down, cwd?}`; answers the new pane's `id`) |
| `/api/mux/panes/{id}/zoom`      | POST        | Zoom a pane (body: `{mode: toggle\|on\|off}`) |
| `/api/mux/panes/{id}/swap`      | POST        | Swap with a neighbour (body: `{direction: prev\|next}`; 409 `no_neighbor` past an end) |
| `/api/mux/panes/{id}/resize`    | POST        | Resize (body: `{direction: left\|right\|up\|down, amount}`, 1–50 cells) |
| `/api/mux/groups`               | POST        | Create a group (body: `{name, cwd}`) |
| `/api/mux/groups/{id}`          | PATCH       | Rename a group (body: `{name}`) |
| `/api/mux/groups/{id}`          | DELETE      | Close a group and everything in it |
| `/api/mux/worktrees?groupId=`   | GET         | A workspace's worktrees and local branches (Herdr) |
| `/api/mux/worktrees`            | POST        | Create a worktree (body: `{groupId, branch, base, label}`) |
| `/api/mux/worktrees/open`       | POST        | Open a worktree (body: `{groupId, branch}`) |
| `/api/mux/worktrees/{id}`       | DELETE      | Remove a worktree workspace (body: `{force, path, branch}`) |

## Troubleshooting

### Session not persisting

1. Check tmux is running: `tmux list-windows`
2. Check termote logs: `termote container logs` (container) or `termote logs server` (native)

### WebSocket / terminal errors

1. Check termote logs: `termote container logs` or `termote logs server`
2. The terminal WebSocket is `/api/mux/stream`, served by termote itself
3. Check server health: `termote status` (container: `termote container status`)
