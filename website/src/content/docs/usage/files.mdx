To see what an agent changed, you would otherwise type `ls`, `cat` and `git diff` on a phone
keyboard and read the output in a terminal. Termote has two views for this:

- **Files**: the pane's directory as a tree, opened one folder at a time. A text file opens with
  line numbers and syntax highlighting, a CSV or TSV file as a table, an image as the picture,
  and a PDF, Excel or Word document as a read-only preview.
- **Changes**: when the directory is in a git repository, the files git reports as changed, and
  the diff of each one (for an image, the version before and after).

A file can be found by name in Files (see [Finding a File](#finding-a-file)). A text file can be
edited and saved from either view (see [Editing a File](/usage/file-editing/#editing-a-file)), a new one created in
Files (see [Creating a File](/usage/file-editing/#creating-a-file)), a file or an empty folder deleted there (see
[Deleting a File](/usage/file-editing/#deleting-a-file)), and a file renamed or moved there (see
[Renaming or Moving a File](/usage/file-editing/#renaming-or-moving-a-file)). Changes can also stage and discard
([Staging, Unstaging and Discarding](/usage/changes/#staging-unstaging-and-discarding)). Nothing
else changes from them: no folder is renamed, and nothing is committed.

## Where to Find Them

- **Desktop**: the **Files** and **Changes** buttons in the header open a panel to the right of
  the terminal. The terminal stays on screen and keeps working. One panel shows at a time; press
  its button again to close it.
  - Drag the panel's left edge to make it wider or narrower (it always leaves room for the
    terminal); double-click the edge to go back to the default width. With the keyboard, focus
    the edge and use the Left/Right arrows, Home and End. The width is remembered on this device.
    The terminal is resized once, when you let go.
  - The **Maximize panel** button at the top of the panel lets it cover the terminal or the Chat
    view for a while; press it again, or Escape, to put it back. The terminal keeps its size
    underneath, so other devices on the same window see no change.
- **Phone**: Files and Changes are views in the header's view menu, alongside Terminal
  (and Chat, when Claude Code runs in the pane). The button shows the current view's icon; tap
  it to pick another view. Each view takes the whole screen.

If the window grows or shrinks between the two layouts, an open view follows: from the
phone view to the desktop panel, and back.

## Which Directory Is Shown

The root is the **working directory of the pane on screen**. When that directory is inside a git
repository, the root is the top of the repository instead, so Files and Changes cover the whole
repository. The root is shown at the top of both views, with `~` for your home directory.

The directory is the one of the program running in the pane, so it follows a `cd` in the shell.
A command that only passes through another directory for a moment does not move the root. When
the root does move while a view is open, the view reloads from the new root and says
`The pane's directory changed`.

Supported backends:

- **tmux** on Linux and macOS, natively or in the container
- **Herdr** on any OS. Herdr must report the pane's directory (`cwd`); an older Herdr that does
  not shows `Not supported by this backend`.
- **psmux** on Windows is not supported: it does not report the pane's directory, and the two
  views are not offered.

### Places

Files can also show a folder outside the pane, such as a shell config folder or your notes, once
it is named on the host:

```bash
termote start --allow-path ~/.config/fish --allow-path ~/notes
termote start --remove-path ~/notes
termote container up --allow-path ~/notes   # the container keeps its own list
```

Pick it from **Places** (the folder icon at the top of Files); **Pane folder** goes back. A Place
works like the pane's folder: browse, search, edit, create, rename, delete with Undo, download and
paste images. Changes always stays on the pane's repository. Places are listed only to a device
with full access, never to a view-only one, and the app can never add or remove one.

Termote refuses your home folder itself and any folder above it, `~/.ssh`, `~/.gnupg`, its own
config, state, data and cache folders (and any folder holding them, such as `~/.config`, `~/.cache`
or `~/.local`; `~/.config/fish` is fine), `/proc`, `/sys`, `/dev`, the folders holding the host's
control sockets (`/tmp`, `/run`, `/var/run`), and a `.git` folder. A saved folder that is
gone or now points somewhere refused is skipped, and `start` prints the `--remove-path` that drops
it. On Windows, Places need the Herdr backend (`--mux herdr`).

## Files

- Folders come first, then files, ignoring case. Tap a folder to open or close it.
- A folder shows at most 5000 entries. A longer folder says that only the first 5000 are shown.
- Devices, sockets and links that point outside the root are greyed out and do not open. One
  exception: in a git worktree, a link to a file or folder in another worktree of the same
  repository (such as `docs/records` linked to the main checkout) opens like one of the root's,
  read-only. Find and Search look inside such a folder when git does not track the link (and the
  link is not inside a folder git does not track), and sort its files as that worktree's git
  does: a file it ignores is found only with ignored files on, and never searched. Windows
  junctions are not followed, only symbolic links.
- A file opens in place of the tree, in a tab (see [Open Files as Tabs](#open-files-as-tabs)),
  with its path, its size, a button to copy the path and one to wrap long lines (on by default on
  a phone). Long lines scroll inside the code area, never
  the whole page.
- Highlighting covers common languages and file names (TypeScript, Go, Python, shell,
  Dockerfile, Makefile, YAML, JSON, Markdown and others). It loads the first time a file needs
  it, so a device that never opens Files never downloads it.
- A file of more than 2000 lines keeps only the lines near the view in the page, so it opens and
  scrolls as quickly as a short one, whatever its length. The browser's find (Ctrl+F) and a
  selection then reach only those lines: use Search in Files, or download the file. A file of
  more than 400,000 lines shows its first 400,000 and says how many more there are.

| Shown                                                         | Why                                                                                              |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Text with colours                                             | A text file of up to 256 KiB, up to 5000 lines, no line over 2000 characters                     |
| Plain text, no colours                                        | A larger text file (up to 4 MiB), a language not covered, or highlighting that took over 3 seconds |
| `Not previewable (binary, special file or larger than 4 MiB)`  | A binary file that is not an image or a document, a file over 4 MiB, or something that is not a regular file |
| `This file can't be shown`                                     | A path termote never serves (see below)                                                          |

## Right-Click Menus

A right click on a file or folder of the tree opens its menu where the pointer is; the **…**
button on the row, a long press on a phone, Shift+F10 or the menu key open the same menu by the
row, its first item focused.

- **Copy relative path**, **Copy absolute path** and **Copy name**. The relative path is from the
  root the tree shows; the absolute one uses the host's separator (`\` on Windows), and a link's is
  the link's own path, not where it leads.
- **Insert @path in terminal** types the path after `@` into the pane, without Enter, and shows
  the terminal. A file under the pane's directory gets a path from there (`@src/app.ts`), any
  other (above it, beside it, or in a Place) its absolute path; one with a space is quoted
  (`@"my notes.md"`), as Claude Code writes it. The pane's directory is read at that moment, so a
  `cd` in the pane counts. A name with a line break or a `"` is never typed (it could run a
  command in a shell): a toast says so. When the terminal is not connected, a toast offers to
  copy the path instead.
- On a folder: **New file**, **New folder** and **Upload files here**, the box starting in that
  folder. A link to a folder, or a folder reached through one, offers none of them.
- **Download**, **Rename** and **Delete**, as described below.

A right click below the rows opens the tree's own menu: **New file**, **New folder**,
**Upload files** (into the root), **Refresh** and **Collapse all**. An empty directory shows a
message in place of the tree; a right click on it opens the same menu, without **Collapse all**,
so a first folder can be made there.

On a desktop, a right click on a file's tab opens the same menu with **Keep open** (for a preview
tab) and **Close** first. A tab kept from a directory the pane has left only copies, types its
absolute path and closes.

A view-only device sees the copies, **Refresh** and **Collapse all** only (and, on a tab,
**Keep open** and **Close**).

## Open Files as Tabs

Opening a file keeps the ones already open: each has a tab, and going back to a tab brings back
where you were in that file and its unsaved changes.

- **A single click opens a preview tab**, its name in italics: the next file opened the same way
  replaces it. A file gets a tab of its own once you double-click it (in the tree or on its tab),
  start editing it, create it, or tap **Keep open** (the pin in its bar).
- A file that is already open shows its tab; it never opens twice.
- The first tab, **Files**, shows the tree; the files stay open behind it. Back, when no link is
  left to retrace, shows the tree too.
- **Closing a tab**: its × button, a middle click, or Delete on the focused tab. A tab with
  unsaved changes (a dot after its name) asks `Discard changes?` first.
- **Reordering tabs** (desktop): drag a tab along the bar with the mouse; the others slide aside to
  make room, and Escape puts it back. Alt+Left or Alt+Right moves the focused tab one place. The
  **Files** tab always stays first. Diff tabs in Changes move the same way.
- **At most 10 tabs.** Opening one more closes the tab used longest ago, never the one shown and
  never one with unsaved changes. When every other tab has unsaved changes, more than 10 stay
  open.
- **On a phone** there is no tab bar. The button with the number of open files
  (`Open files (N)`), in the file's bar and above the tree, lists them in a sheet: tap one to show
  it, or keep it open, or close it.
- A file deleted in Termote closes its tab, and a file renamed in Termote keeps its tab under the
  new name. A file deleted or renamed by something else keeps its tab, which shows
  `File not found` with **Close tab**; once shown, the tab's name is struck through in the tab bar
  and the open files sheet until the file is found again.
- When the pane moves to another directory, the tabs opened in the old one close. Tabs with
  unsaved changes ask first: **Discard and close** drops the changes, **Keep** leaves them open
  so you can copy their text (they can no longer be saved).
- A file that may contain secrets asks again in every new tab. A tab where you chose to show it
  keeps it shown until the tab closes.
- Tabs live only in the page's memory: reloading the app starts with none.

## Finding a File

The **Find a file…** box at the top of Files (above the keyboard on a phone) searches the names
of the files under the root. Results replace the tree after a moment's pause in typing; each row
shows the path.

- Tap a result, or press Enter on it, to open the file; the tree opens down to it, and Back
  returns to the results. The arrow keys move between the box and the results, and Escape clears
  the box.
- A file that git ignores is not searched unless **Include ignored** (the switch next to the box,
  shown only in a git repository) is on. Those results are dimmed and tagged `ignored`. The
  choice is remembered on this device.
- A name that usually holds secrets shows a lock, as in the tree. Only names are searched here;
  the contents of files are searched in the **Search** tab (see
  [Searching File Contents](#searching-file-contents)).
- Only the first 200 matches are shown (`More than 200 matches — type more to narrow`). In a very
  large repository or folder the search can stop early, and the list says
  `Search stopped early in a large tree`.
- The list of files is kept for 30 seconds, and saving, creating or deleting a file drops it.
  **Refresh** reads it again.
- Outside a git repository, the folder is walked (at most 32 levels deep, for 5 seconds), and
  linked folders are not entered.

The folders never searched for ignored files are set in Settings → Files →
**Excluded folders** (see [Settings](/usage/settings/#excluded-folders)). A file git tracks is
always found, even under one of them.

Paths Termote never serves (see [Never Shown](/usage/security/#never-shown)) never appear in the results.

## Searching File Contents

The **Files | Search** switch at the top of Files shows the **Search** tab, which searches the
text of the files under the root. On a desktop, Ctrl+Shift+F (Cmd+Shift+F on a Mac) opens it and
puts the cursor in the box, from anywhere in Files or elsewhere in the app (the Files panel opens
first); from the terminal the keys stay the terminal's. The key can be changed in
[Settings > Shortcuts](/usage/keyboard-shortcuts/#changing-keys).

- The search runs as you type, after a short pause, once the box holds at least 2 characters.
  The text is searched as typed: spaces at either end count.
- **Match case**, **Whole word** and **Regular expression** (the buttons next to the box) change
  how the text matches; they are remembered on this device. Without Match case, case is ignored.
  A regular expression uses Go's syntax (RE2); whole words are made of the letters `A`–`Z`,
  `a`–`z`, digits and `_`. A regular expression that can match empty text, such as `a*`, is
  refused (`This pattern matches empty text`): write `a+` instead.
- The **…** button shows two more boxes: **Files to include** and **Files to exclude**, each a
  comma-separated list of patterns such as `*.ts, src/`. A pattern without `/` matches the file
  name in any folder; `**` stands for any number of folders; a pattern ending in `/` matches
  everything in that folder.
- Results are grouped by file, with the number of matching lines; each line shows its number and
  the matches highlighted. Groups past the first 50 files start closed. Tap a line, or press Enter
  on it, to open the file at that line, highlighted in the middle of the view. Markdown, CSV/TSV
  and SVG files open as their source in that tab, whatever the preview settings say. Back returns
  to the same results. The arrow keys move between the box and the results, and Escape goes back
  to the box.
- At most 2000 lines are shown (`Showing the first 2000 lines`), and 100 lines per file (the rest
  is counted under the file). A search stops after 5 seconds or 256 MiB read
  (`Stopped early: some files were not searched`); a line longer than 16 KiB is searched on its
  start only. Two searches can run at once on the server; a third says `Search busy, try again`.
- If the pane's directory changed since the search, the results are dimmed and cannot be opened
  until the next search.

The files searched are the ones **Find a file** lists without **Include ignored**. These are
never searched:

- files git ignores, in a git repository;
- files that may contain secrets (see
  [Files That May Contain Secrets](/usage/security/#files-that-may-contain-secrets)), counted under the results
  (`2 sensitive files not searched`);
- dot-files and dot-folders when the folder shown is your home folder or holds it (shell
  histories and tool settings hold secrets under ordinary names), also counted;
- binary files, files that are not UTF-8 text (a Shift-JIS, EUC-JP or UTF-16 file opens in Files,
  but is not searched), and files larger than 1 MiB;
- paths Termote never serves (see [Never Shown](/usage/security/#never-shown)).

A view-only device searches the same files it can open.

## Downloading a File

A copy of a file can be saved on the device you are using: **Download** in the **⋯** menu of its
row in the tree (on a phone, a finger resting on the row opens it), or the **Download** button in
the header of an open file (in the header's menu on a phone). The browser saves it as it saves any
download, under the file's name; nothing is opened or shown, whatever the file holds.

- Any regular file can be downloaded, also one Termote cannot preview (binary, larger than 4 MiB),
  up to **100 MiB**.
- A file whose name usually holds secrets is downloaded after a second ask; an open one you chose
  to show is downloaded at once.
- Only files are downloaded, not folders or links, and never through a folder that is a link.
- In the iOS app added to the Home Screen, the file opens in the share sheet: pick **Save to
  Files**. Closing the sheet saves nothing.
- Every download is written to the server log as an `audit: download` line (the path inside the
  pane's directory, the size and who asked).

| Shown                                                | Why                                                                  |
| ---------------------------------------------------- | -------------------------------------------------------------------- |
| `<name> is larger than 100 MiB, too large to download` | The file is over the limit                                           |
| `Too many files at once; try again`                  | Other downloads or images are being read; try again in a moment      |
| `<name> is gone`                                     | Something removed or moved the file after the tree was read          |
| `<name> is not a regular file; not downloaded`       | A FIFO, a socket or a device                                         |
| `A link on that path; not downloaded`                | The file or a folder on its path is a symbolic link                  |
| `<name> can't be downloaded from here`               | Termote's own folders, the install's data, `.git` and the upload store |
| `<name> changed; try again`                          | Something replaced the file while it was checked                     |

A view-only session has no Download.

## Uploading Files

A file on the device you are using, of any type (a PDF, a CSV, a zip, a screenshot, a log), can
be put in a folder of Files in three ways:

- **Upload files** (an arrow up, next to New file) opens the device's file picker; on a phone it
  offers the photo library, the camera and the Files app too. Several files can be picked at once.
  They go into the folder you last tapped in the tree, or the folder of the file you last tapped,
  or the top folder.
- **Dropping** files from the computer's file manager on Files: on a folder row they go into that
  folder, on a file row into its folder, below the rows into the top folder. A folder that is a
  symbolic link, or one inside such a link, passes them to the nearest real folder above it. While a file is open,
  a drop puts the files in that file's folder, and the result names the folder. A dropped file is
  never inserted into the text being edited.
- **Pasting** files copied in the file manager (Ctrl+V, ⌘V on a Mac) while the tree is shown puts
  them in the same folder as Upload files. A paste into the search box, or with a file open, does
  nothing. What a copy in the file manager puts on the clipboard differs between browsers and
  systems (on Linux often only the file's path), so when nothing happens, use the button or a drop.

The files go up one at a time. A row under the Files header shows the file being sent, how far it
is and how many are left, with **Cancel**; Cancel turns off once a file is fully sent, since the
server then saves it anyway. Uploads carry on when you switch to the terminal or
another view, each into the folder it was started for; the row shows again when you come back to
Files. When they are done one notice says how it went, such as `Uploaded 3 files.` or
`1 of 3 uploaded. big.zip: File is larger than 100 MB (1 more not uploaded)`.

- At most **100 MiB** a file, the most a download takes.
- An existing file is never replaced: a taken name gets a number, `report.pdf` becoming
  `report (2).pdf`, up to `(99)`. The notice says `Saved as report (2).pdf`.
- A folder that usually holds secrets (`.ssh`, `.aws`, …), or a name that does (`.env`), is asked
  about first, once for the files sent together, naming the file and where it goes. Enter keeps
  the files away; answering no sends none of those files, without a notice.
- Only files go up, never folders: a dropped folder is skipped and said so.
- When another upload is running (from another device, or another tab), the row says `Waiting for another upload…` and the file goes
  once that one ends, or after two and a half minutes says so.
- When the connection drops after the file was fully sent, Files reads the folder to see whether the file
  arrived; if it cannot tell, it says `Not sure the file was saved. Check the folder`.
- A file is written under a hidden temporary name (`.termote-upload-…`) and only gets its name
  once complete, so a half-sent file never shows under its name (while it is sent, the temporary
  file may show in the tree, marked as sensitive). One left by a server stopped mid-upload is
  removed by the next upload to that folder after an hour.
- Every upload is written to the server log as an `audit: upload` line (the path, the size and who
  sent it).

| Shown                                              | Why                                                                                       |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `File is larger than 100 MB`                       | The file is over the limit                                                                |
| `The folder is a link: not uploaded`               | A folder on the path is a symbolic link the tree had not shown as one: nothing is written through one |
| `Files can't be uploaded to this folder`           | A path Termote never serves (see [Never Shown](/usage/security/#never-shown)), `.git`, or its own folders  |
| `This file's name can't be used on the host`       | A name with `\`, a Windows device name (`NUL`, `CON.txt`, `COM1`), invisible or direction-changing characters, a control character, more than 255 bytes, one ending in a dot or a space, or on a Windows host one of `<>:"\|?*` |
| `Too many files with this name. Rename one first`  | `name (2)` up to `name (99)` are all taken                                                |
| `The folder is no longer on the host`              | Something removed or moved the folder after the tree was read                             |
| `The server can't write in this folder`            | The folder cannot be written                                                              |
| `The file system there is read-only`               | The folder is on a read-only disk or mount                                                |
| `The host's disk or quota is full`                 | The host's disk, or your disk quota, has no room left                                     |
| `The upload stalled. Try again on a better connection` | Nothing arrived for two minutes, or the file took more than 30 minutes                |
| `Another upload is running. Try again shortly`     | Another device's upload still held the server after the wait                              |

<Aside type="caution">
  An uploaded file is as trusted as one made with New file: a tool may read or run it by itself
  (on Windows a file runs by its extension, so an uploaded `.exe` or `.ps1` can be started like
  any other). Anyone who can sign in can already run commands in the terminal, so this allows
  nothing new, but check what you upload into such places.
</Aside>

A view-only session has no Upload files button and pastes nothing; a drop only says
`A view-only device cannot upload`, and the browser never opens the dropped file.
