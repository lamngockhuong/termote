---
title: Settings
description: Configure Termote preferences
---

Open settings from the **More** (⋯) menu in the header → **Settings**. Settings are grouped:
**Appearance**, **Keyboard**, **Terminal**, **Sessions**, **Files** and **Data & help**. On a phone the
dialog is a full-screen sheet; on desktop it is a two-column dialog with a group list on the left.
Help & gestures and About open in the same kind of sheet from the **More** menu.

## Interface Style

Settings → Appearance → **Interface style** changes how the whole app looks. The change applies
at once and is saved in this browser.

| Style    | Look                                                   | Default |
| -------- | ------------------------------------------------------ | ------- |
| Neutral  | Balanced defaults, indigo accent                       | ✓       |
| Terminal | Monospace labels, small corner radius, green accent    |         |
| Native   | Large corner radius, system-app feel, blue accent      |         |

The style is independent of the **theme** (Light, Dark, System), which you pick in the **More**
(⋯) menu. Any style works with any theme. If you have turned on reduced motion in your operating
system, Termote skips its animations.

## Text Input Send Behavior

Controls what happens when you tap **Send** in the text input mode (non-Latin input).

| Option         | Behavior                                      | Default |
| -------------- | --------------------------------------------- | ------- |
| Send text only | Sends text to terminal, no Enter key appended | ✓       |
| Send + Enter   | Sends text then automatically presses Enter   |         |

**Use case**: Set to "Send + Enter" if you want to type a command in Vietnamese/CJK and submit it in one tap.

## Paste Button Source

Controls where the **Paste** button in the toolbar gets content from.

| Option           | Behavior                                        | Default |
| ---------------- | ----------------------------------------------- | ------- |
| System clipboard | Paste from device clipboard (Ctrl+Shift+V)      | ✓       |
| tmux buffer      | Paste from tmux copy mode buffer (Ctrl+B, ])    |         |

**Tip**: Use "System clipboard" for pasting from other apps. Use "tmux buffer" for pasting text copied within tmux.

With the tmux backend the second option is labelled **tmux buffer**; with any other backend it is labelled **Session buffer**. With the Herdr backend there is no tmux buffer, so this setting is hidden and the Paste button always uses the system clipboard.

## Toolbar Default Expanded

Controls whether the keyboard toolbar starts in expanded or minimal mode when the page loads.

| Option | Behavior                                    | Default |
| ------ | ------------------------------------------- | ------- |
| Off    | Toolbar starts in minimal mode (fewer keys) | ✓       |
| On     | Toolbar starts expanded (all keys visible)  |         |

## Disable Right-Click Menu

Blocks the browser context menu (right-click / long-press) on the terminal area to prevent accidental interruptions.

| Option | Behavior                                | Default |
| ------ | --------------------------------------- | ------- |
| On     | Context menu is blocked on terminal     | ✓       |
| Off    | Browser default context menu is allowed |         |

## Copy on Select

Copies the text you select in the terminal with the mouse as soon as you release the button, and
shows a short "Copied" toast. Off, select the text and press Ctrl+Shift+C (Cmd+C on a Mac) instead;
see [Copy text](/usage/keyboard/#copy-text).

| Option | Behavior                                         | Default |
| ------ | ------------------------------------------------ | ------- |
| Off    | A selection is copied with Ctrl+Shift+C or Cmd+C | ✓       |
| On     | A selection is copied when the mouse is released |         |

## Fit Herdr Pane to This Device (Herdr Only)

A Herdr pane has one size, shared by the desktop and every device that shows it. By default the PWA shows the pane at the desktop's size: the font buttons then zoom in and out, and a pane larger than the screen can be dragged.

With this switch on, the PWA sets the pane's size to fit its own screen while the page shows the terminal, as it does with tmux: the font buttons change how many columns and rows the pane has. The pane on the desktop takes the same size until the page is hidden or closed, another view such as Chat opens, the connection is lost (after up to about 30 seconds), or another device with the switch on takes over. Under the Chat view the pane keeps the desktop's size, so a Claude Code dialog taller than a phone's screen is still shown whole and can be answered there. A device that lost the size shows a toast and keeps showing the pane at the desktop's size; it takes the size back the next time the page is shown.

| Option | Behavior                                  | Default |
| ------ | ----------------------------------------- | ------- |
| Off    | Pane keeps the desktop's size             | ✓       |
| On     | Pane fits this device while it is shown   |         |

This setting only appears with the Herdr backend. On macOS, if the server is killed (`kill -9`) while a device drives the size, the pane keeps that size until the service starts again.

## Show Session Tabs (Desktop Only)

Displays browser-like session tabs in the header row for quick session switching on desktop. The sidebar remains available for more detailed session management.

| Option | Behavior                              | Default |
| ------ | ------------------------------------- | ------- |
| On     | Show session tabs in header           | ✓       |
| Off    | Hide tabs, use sidebar only           |         |

This setting only appears on desktop devices.

## Blocked Sessions First

Lists sessions with an agent waiting on you at the top of each group in the sidebar. The other
sessions keep their order. It is off by default, because sessions then move whenever an agent
changes state.

| Option | Behavior                                    | Default |
| ------ | ------------------------------------------- | ------- |
| Off    | Sessions keep their order                   | ✓       |
| On     | Blocked sessions first in each group        |         |

## Notify When an Agent Needs Me

Settings → Sessions → **Notify when an agent needs me** shows a notification when an agent's
dialog waits for an answer, or when it finishes a turn. Tapping the notification opens that pane.
Without Web Push, the pane you are looking at never notifies. With it, every push shows a
notification, that pane included: browsers require it. The notification names the agent, the
group and the tab, and never holds screen or transcript text.

Turning it on asks the browser for permission to show notifications. If the browser blocks them,
the row reads **Blocked in browser settings**. Allow notifications for the site there, then turn it
on again. If the row reads **Reload to turn on**, the page is still running an older version of
the app: reload it first.

How the notification arrives depends on the device:

- **With the app closed** (Android Chrome, desktop Chrome, Edge and Firefox): the server sends a
  Web Push, so it arrives even when no Termote page is open.
- **iPhone and iPad**: it works only in the app added to the Home Screen, on iOS 16.4 or later.
  In Safari the row reads "iPhone/iPad: works only from the Home Screen app (iOS 16.4+)".
- **Without Web Push** (an older server, or a browser without it): only an open page notifies,
  which in practice means a desktop tab, since a phone suspends a page it does not show.

Limits:

- With tmux, only the active pane of each window is watched, so an agent in a split pane that is
  not active does not notify.
- The server checks every 5 seconds, so a turn shorter than that may not notify.
- `termote start --fresh`, or any change of the password, stops push to every device. A device
  gets it again once it opens Termote and signs in with the new password.
- Logging out also stops push to that device.

| Option | Behavior                                     | Default |
| ------ | -------------------------------------------- | ------- |
| Off    | No notifications                             | ✓       |
| On     | Notify when an agent is blocked or finished  |         |

## Terminal Font

The font the terminal uses, typed by name (e.g. `JetBrainsMono Nerd Font`). It must be installed on the device the browser runs on; if it is not, the terminal falls back to the system monospace font. Several names can be given, separated by commas. The value is saved when the field loses focus or you press Enter.

Nerd Font icons (prompt themes such as Starship or Powerlevel10k, file icons in `eza` or `lsd`) display without setting anything: Termote ships the Symbols Nerd Font and uses it for any icon the chosen font lacks, including on phones where no Nerd Font can be installed.

| Option      | Behavior                                                | Default |
| ----------- | ------------------------------------------------------- | ------- |
| Empty       | System monospace font, icons from the bundled font      | ✓       |
| A font name | That font first, then the system font and bundled icons |         |

## Session Poll Interval

Controls how often the app syncs the session list from the server. Lower values keep multi-device views in sync faster; higher values reduce server load when using a single device.

| Option                            | Default |
| --------------------------------- | ------- |
| 3s, 5s, 10s, 15s, 30s, 1m, 2m, 5m | 5s ✓    |

## Excluded Folders

Settings → Files → **Excluded folders** is the list of folder names that [Find a file](/usage/files-changes/#finding-a-file)
never enters. They apply only to files git ignores and to folders outside a repository; a file
git tracks is always searched, even under one of these names.

- Remove a name with the **x** on it. Add one by typing it in **Folder name** and pressing **Add**
  (or Enter). A name is a single folder name, such as `node_modules`: no `/`, no `*`, `?` or `[`,
  not `.` or `..`, and at most 255 bytes. The field says why a name is refused. At most 50 names.
- **Reset to defaults** restores the list below.

| Default folders                                                                                          |
| -------------------------------------------------------------------------------------------------------- |
| `node_modules`, `.venv`, `venv`, `__pycache__`, `dist`, `build`, `target`, `.next`, `.nuxt`, `.turbo`, `.cache`, `coverage`, `vendor` |

The **Include ignored** switch is not here: it sits next to the Find a file box in Files.

## Updates

Shows the version the server runs and the newest stable release on GitHub (the one
`termote update` installs), read when Settings opens and kept for an hour; **Check for updates**
asks GitHub again. When the server is older, it shows the command for this install with a
**Copy** button, and a link to the release notes:

| Install                    | Command                                                  |
| -------------------------- | -------------------------------------------------------- |
| `install.sh`/`install.ps1` | `termote update`                                         |
| Container                  | `termote update && termote container up` (on the host)   |

A git checkout gets a hint instead of a command (pull, rebuild and restart it; the commands differ
by OS). Termote does not check on its own when the app opens.

### Reloading after an update

The page comes from the server, so once the server runs a new version a banner reads
**Termote vX.Y.Z is ready** with a **Reload** button (also offered in **Updates**). Termote never
reloads on its own for a new release, since an unsaved edit in Files would be lost. It notices the new version when the app opens, when the terminal reconnects after the
server restarted, and when the app is shown again. There is no need for **Clear cache & reload**.
Only a server whose API changed in a way this page cannot use reloads it at once. With several
tabs open, **Reload** reloads only its own tab; the others show the banner.

:::note[Updating from 1.13 or older]
Pages of those versions do not know this banner yet. After the first update past them, close every
Termote tab (on a phone, quit the installed app) once; the new version loads when it opens again.
:::

## Clear Command History

Deletes all saved commands from the command history dropdown. Use when you want to free up stored history or start fresh.

## Show Gesture Hints (Mobile Only)

Re-opens the gesture tutorial overlay that appeared on your first visit. Useful if you want to review available touch gestures. It is in the **Data & help** group.

This button only appears on mobile devices.

## Persistence

All settings are saved to your browser's local storage (`termote-settings` key) and persist across sessions. Clearing browser data or using "Clear cache & reload" (in the **More** menu) will reset settings to defaults.
