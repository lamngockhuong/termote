Long replies are hard to read in a terminal on a phone, and so is typing a prompt into one. When
a pane runs **Claude Code** or **Codex**, the header shows a **Terminal / Chat** switcher (on a phone, one
view button that opens a menu of views). The Chat view is a second way to look at the same
session: what you send there is typed into the pane, and what the agent writes shows up in both
views. Nothing runs in the background on its own. Codex works the same way, with its own requirements
and one difference for dialogs (see [Codex](#codex)).

## Requirements

- Claude Code running in a pane, under one of these backends:
  - **tmux** on Linux or macOS
  - **psmux** on Windows
  - **Herdr** on any OS, after running `herdr integration install claude` once
- A native install (`termote start`). The container image does not include Claude Code.
- For Codex: see [Codex](#codex).

## What the Chat View Shows

- The whole conversation of the current session, read from the transcript Claude Code writes to
  disk: your messages, replies rendered as markdown, and tool calls. A command shows as `$ command`
  with its output folded behind `Output · N lines` (opened, the last 10 lines; a failed one is open
  already). Three steps or more in a row fold into one line such as `3 commands, 2 reads`; the steps
  the agent is running now stay open on the newest ones.
- New turns within about two seconds. After `/clear` or a resume, the view switches to the new
  session without mixing the two.
- While a turn runs, a row under the conversation shows what the terminal's working line says:
  the agent's word for it (`Incubating…`, `Working…`), whether it is thinking or running hooks,
  how long the turn has run and the tokens received. The agent writes a reply to its transcript
  only once the reply is complete, and never writes its thinking, so this row is what moves until
  then. When the line cannot be read, the row still says the agent is working and for how long.
- Code blocks framed with their language, highlighted, with a Copy button. A ` ```mermaid ` block
  is drawn as a diagram, with the same Show source, export and full-screen buttons as the
  [Markdown preview](/usage/files-changes/#markdown-preview); one that cannot be drawn stays code
  with the reason.
- File paths as links to the pane's [Files view](/usage/files-changes/): the path on a tool card,
  inline code that names a file (`src/app.ts`, `./run.sh`, `src/app.ts:42`, `src/app.ts#L42`) and a
  relative Markdown link. Tapping one opens that file in Files, at the line when one is given. A
  relative path is taken from the pane's directory, then from its root; a path outside the root is
  never requested and stays plain text, as every path does in a pane without a Files view. On desktop
  the file opens in the side panel and the Chat stays where it is. A single name under `/`, such as
  `/clear`, is a slash command, not a file.
- Images in a reply as text links. They are never loaded, so a reply cannot make your browser
  contact another site.

## Sending a Message

Type in the box at the bottom and tap the send button (Ctrl+Enter on desktop). Multi-line
messages arrive as one turn, exactly as written.

Termote only sends when the screen shows Claude Code's input box empty. While Claude Code works,
the message still goes: Claude Code puts it in its own queue and reads it when it is ready, and
the Chat view says `Queued: Claude Code reads it when it is ready.` In the terminal it shows as a
queued message, which you can edit there (Up). Otherwise the message is refused and the pane
gets no key at all:

| Message                                                    | Code                      | Meaning                                                                                      |
| ---------------------------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------- |
| Not sent: the agent is waiting for an answer               | `input_not_ready`         | A dialog is open                                                                             |
| Not sent: the input box already holds a draft              | `input_not_ready`         | Something is typed in the terminal's input box; send or clear it there                       |
| Not sent: the pane is in copy mode                         | `input_not_ready`         | The tmux pane is scrolled back in copy mode; leave it (`q`) in the terminal                  |
| Not sent: the text did not show in the input box           | `paste_not_confirmed`     | Enter was not sent; the text may be in the input box now                                     |
| The text was pasted but not submitted                      | `delivered_not_submitted` | The text is in the input box but Enter was not sent; check the terminal before sending again |
| The conversation changed; it has been reloaded             | `session_changed`         | The pane runs another session now (`/clear`, a resume); send again if you still want to      |
| Too long: the limit is 16 KB.                              | `text_too_long`           | The message is over 16 KB (UTF-8); split it                                                  |
| Not sent: the input box holds part of this message         | `partial_paste`           | The input box may hold some of the message's images or text; check and clear it there        |
| Not sent: an image is no longer on the host                | `invalid_request`         | The host deleted the upload (older than 7 days, or storage full); remove it and attach again |

Every refusal that leaves something to check offers **Open terminal**.

### Attaching Images

Tap the image button next to the box to pick a photo (or take one on a phone), or paste an image
into the box. Each image is uploaded to the host at once and shows as a thumbnail above the box;
the send button waits until every upload has finished. Up to 5 images go with one message, with or
without text. Each image also puts an `[Image #N]` token in the box where the caret is, as Claude
Code does, so you can write "this one [Image #1], that one [Image #2]". Remove an image with the
cross on its thumbnail or by deleting its token.

Termote pastes the message into Claude Code (or Codex) in order: the text up to an image, then that
image's path on its own, waiting each time for the agent to show it (an image as `[Image #N]`), and
finally presses Enter, so the images reach the agent as attachments where you put them. A message
that starts with `/` or `!` gets its images first, so it is never taken as a command. If a step fails halfway, the input box is cleared only when it holds nothing but what
this message pasted; otherwise you get `partial_paste` and the box is left for you to check.

The images are stored on the host as described in
[Attach an Image](/usage/keyboard/#attach-an-image), and are kept after the message is sent. The
image button is hidden when the server cannot store uploads, and in view-only mode. A copy that holds
both an image and text pastes the text.

## Slash Commands

Type `/` at the start of a message and a list of commands opens above the box. Keep typing to
narrow it: names that start with what you typed come first, then any whose name or description
contains it. Each row shows where the command comes from:

- `built-in`: Claude Code's own commands, with `/exit` first.
- `project`: `.claude/commands/` and `.claude/skills/` in the pane's project (the folder the
  Files view shows).
- `user`: `commands/` and `skills/` in your Claude config dir (`~/.claude`, or
  `CLAUDE_CONFIG_DIR`).
- `plugin`: commands and skills of the plugins you have installed and enabled, named
  `/<plugin>:<name>`. A plugin turned off in the project's `.claude/settings.json` or
  `.claude/settings.local.json` is left out.

Skills carry a `skill` tag as well.

Tap a row, or press Enter or Tab, and the box becomes `/name ` so you can type arguments; it is
not sent until you send it. The arrow keys move through the list and Escape closes it, as does a
space after the name.

A few commands open a screen the Chat view cannot drive, such as `/model`, `/config`,
`/permissions`, `/resume` and `/mcp`. They are marked `opens in Terminal`: picking one sends it
and switches to the terminal. `/exit` asks before it is sent, since it ends Claude Code; the app
then goes back to the terminal.

Only names and descriptions are read, never what a command contains. A skill installed as a
symlink is listed when it leads into the project, the config dir or `~/.agents/skills`; a link to
anywhere else is not, and neither are MCP prompts. Any command can still be typed in full.

### Prompt Templates

Prompts you type again and again can be saved as templates, with variables such as the file shown or
the text you selected, and inserted from the **Templates** button, the `/` list or the command
palette: see [Prompt Templates](/usage/prompt-templates/). An inserted template is never sent for you.

## Answering Dialogs

When Claude Code asks for permission or asks a single-choice question (up to nine options), a
card replaces the message box. Each button picks that option; **Cancel** sends Escape. If the
screen changed before your answer was sent, or another device answered first, nothing is sent
and the card shows the dialog that is open now.

The card shows the whole dialog, however long. A long command or question sits in a box you can
scroll, with **Show all** to open it; the rest of the card scrolls too, and **Cancel** stays at
its foot. On a permission card the buttons that approve stay off until you have read the whole
command (open it with **Show all**, or scroll to its end); the one that refuses works at once.

A single-choice question keeps its buttons, `Chat about this` included. Its `Type something`
option is an **Other…** button: it opens a field for an answer of your own (one line, up to
1 KB), sent with **Send**. Termote moves the pointer to `Type something` in the terminal, types
the text there, checks that it shows, then presses Enter. If anything on screen is not what it
expects, it stops and the card shows the dialog that is open now; if the text did not show, it
may be left in the terminal's field, so check it there. **Cancel** under the field only closes
it: the dialog stays open. A line break or a control character is refused, not removed.

A question in several parts (a row of tabs such as `Size · Drink · Submit`) is answered one tab
at a time. The card shows the tabs as steps, with the one open marked; each answer moves Claude
Code to the next tab, which gets a card of its own, up to the Submit tab with **Submit answers**
and **Cancel**. Tap another step to go to that tab, to skip a question or come back to one. If
you change tabs in the terminal before tapping, nothing is sent and the card shows the tab that
is open now.

When several choices can be ticked at once, each button ticks or unticks one option, and
**Next** moves on with the options you ticked. **Other…** there adds your text as one more
option, already ticked; its button unticks it like the others.

A question that shows a preview beside its options is answered the same way: one tap picks the
option. The preview itself is only shown in the terminal.

## Codex

A pane running Codex gets the Chat view with its conversation: your messages, replies rendered
as markdown, commands with their output, file changes as diffs. You send a message from the box
at the bottom, under the same rules as for Claude Code: Termote only sends when the screen shows
Codex's input box empty, and a refusal leaves the pane untouched. While Codex works, the message
is sent with Tab, which queues it for after the turn (Codex lists it under "Queued follow-up
inputs"), instead of Enter, which would steer the turn it is running. A `/` command is not
queued: send it once Codex is done.

Approval dialogs (run a command, make file edits) depend on the backend:

- **Herdr**: Herdr reports the agent as blocked, so the dialog is a card with a button per
  option. **Cancel** sends Escape.
- **tmux**: Codex's session file records no approval request, so Termote cannot tell that a
  dialog is waiting for you. The card shows the dialog read only and says "Answer this dialog in
  the terminal."

Other Codex dialogs (model picker, rate-limit prompt, and so on) are always shown read only, on
either backend.

### Codex Commands and Skills

Type `/` at the start of a message for Codex's own commands (checked against Codex 0.162.0), with
`/exit` first. They work as for Claude Code: a pick becomes `/name ` for its arguments, commands
that open a screen of their own (`/model`, `/new`, `/resume`, `/status`, `/diff` and others) are
marked `opens in Terminal`, and `/exit` and `/logout` ask before they are sent, since both end
Codex. Typed in full, the aliases `/quit`, `/cwd`, `/clean` and `/pet` behave as `/exit`, `/pwd`,
`/stop` and `/pets`. Codex has no custom `/` commands: its custom prompts are gone, replaced by
skills.

Skills come after `$`, where Codex itself looks for them, anywhere in a message: type `$` at the
start of a word and a list of skills opens above the box, narrowed by what you type after it. A
pick replaces that word with `$name ` and leaves the rest of the message as it was; the skill runs
when you send the message. A message that ends with `$name` is sent with a space after it: Codex's
own list would otherwise open on that word and take the Enter that submits it. Each row shows where the skill comes from:

- `project`: `.codex/skills/` and `.agents/skills/` at the top of the pane's project and, in a
  git repository, in each folder from there down to the pane's current folder, whether or not
  you have trusted the project in Codex (Codex reads them either way).
- `user`: `skills/` in Codex's home (`~/.codex`, or the `CODEX_HOME` of the Codex in the pane),
  then `~/.agents/skills`.
- `system`: the skills Codex ships with (`skills/.system/` in its home), then
  `/etc/codex/skills` on Linux and macOS. `[skills.bundled] enabled = false` in `config.toml`
  turns the first ones off.
- `plugin`: the skills of the Codex plugins turned on in `config.toml` in Codex's home and
  installed under its `plugins/cache/`, named `$<plugin>:<skill>` as Codex names them (for
  example `$atk:review`). An entry with `enabled = false`, `[plugins._default] enabled = false`
  for an entry that does not say, `[features] plugins = false`, or a `config.toml` Codex cannot
  read turns them off.

The list follows how Codex 0.164.0 loads skills:

- Skills are found in subfolders too, up to six folders down (for example
  `~/.agents/skills/group/deploy/SKILL.md`); folders whose name starts with `.` are skipped.
- A skill needs front matter between two `---` lines with a `description`; a `SKILL.md` without
  one is left out, as Codex leaves it out. The name is the front matter's `name`, else the
  folder's, and `user-invocable` (a Claude Code field) does not hide a skill.
- A skill in a folder that holds a plugin manifest (`.codex-plugin/`, `.claude-plugin/` or
  `.cursor-plugin/plugin.json`), or below one, is named `$<plugin>:<skill>`, as in a plugin.
- `[[skills.config]]` entries in `config.toml` turn a skill off by `name` or by the `path` of its
  `SKILL.md` (`~` and paths relative to Codex's home work); a later entry wins.

A name found twice keeps the first one, in the order above but with the folders below the top of
the project after the `system` ones, so a skill deep in the project (a vendored dependency, say)
cannot stand in for one of the project's or yours; a plugin's skill wins over any other of its
name. Only names and descriptions are read, and a skill installed as a symlink is listed only
when it leads into the folders of its own row (the project, your two skill folders,
`/etc/codex/skills`, or the plugin).

Codex may still run a different set than the list shows:

- Plugins from the `openai-*` marketplaces (curated, bundled, remote) are left out, since Codex
  loads them only for some sign-ins, and so are plugins or skill settings in a project's
  `.codex/config.toml`, a profile or `-c`.
- A plugin or skill whose name has a character other than letters, digits, `_`, `-` and `:` is
  left out, since it cannot follow `$`. This includes names with accented letters or a `.`.
- Codex lists every skill of a name; the list shows one.
- The pane's current folder is the folder of whatever runs in it at that moment, which can differ
  from the folder Codex started in. Without git, the pane's folder counts as the top of the
  project.
- Not looked at: a skill symlinked from outside those folders, the `policy.products` of a skill's
  `agents/openai.yaml`, front matter that ends past the first 8 KB, and front matter Codex cannot
  parse. A plugin manifest that is a symlink or larger than 1 MB does not name the skills below
  it.
- A very large skill folder is read in part (2,000 folders, two seconds).

Requirements:

- Codex run with `codex --no-daemon`. By default every Codex TUI hands its session to one shared background process, and Termote cannot
  tell which pane a session belongs to, so such panes have no Chat view.
- **tmux** on Linux or macOS, **psmux** on Windows, or **Herdr** on any of them after running
  `herdr integration install codex` once. On psmux the Chat view shows the conversation and its
  status, but sending from it does not work yet ([#408](https://github.com/lamngockhuong/termote/issues/408)).
- On Windows, Codex must run as you, not as administrator, and keep its sessions in
  `%USERPROFILE%\.codex` (a `CODEX_HOME` set only in the pane is not followed).
- Checked with Codex 0.159.3, and with 0.162.0 on Windows. A later version that writes its session elsewhere loses the Chat
  view; on tmux the server log notes once that it found Codex without a session file.

What to expect:

- A Codex that has received no message yet has no conversation to show: Codex writes its session
  file with the first message. On tmux the Chat button appears then; on Herdr it is there from
  the start and says no session was found until then.
- After `/new`, a tmux pane loses the Chat view until Codex is restarted, since it then holds two
  sessions and Termote does not guess which one is on screen. On Herdr the Chat view shows the
  session Herdr reports for the pane, which can still be the previous one until Herdr reports
  the new one.
- On Herdr, a pane that started the shared background process before you switched to
  `--no-daemon` can keep reporting a session that is not its own, even another pane's, until
  Codex restarts in it.
- Only the Codex process writing the session counts: another program reading the same session
  file (`tail -f`) gets no Chat view.

## Starting an Agent (Herdr)

On Herdr, a pane that shows only its shell (nothing running, not even a program started with
`exec`) also offers the Chat view. Instead of a conversation it shows **Claude Code** and
**Codex**: tap one and Termote asks Herdr to start it in that pane.

- Claude Code starts as `claude`, Codex as `codex --no-daemon`. No other arguments, model or name
  can be given.
- Before typing the command, Termote presses Ctrl+C in the pane, so a half-typed line, a
  continuation prompt or a heredoc does not take the command. A pane running anything else is
  refused with nothing typed.
- While the agent starts, the buttons wait and the view says "Starting Claude Code…". Once Claude
  Code is ready the conversation shows here; until Herdr reports its session (a few seconds) the
  view says it is starting.
- If the agent first asks something in the terminal (trusting a new folder, signing in), the PWA
  opens the Terminal view and tells you so. If it does not start (not installed, it exited), a
  warning offers **Open terminal** to see why. Herdr then holds that start for up to 30 seconds:
  starting again sooner says so, with nothing typed.
- Codex writes its session only with its first message, which the Chat view cannot send without
  one: type the first message in the terminal, and the Chat view follows from the next one.
- You can move to another pane meanwhile: a toast tells you how the start went.

Requirements: Herdr 0.8.2 or later on Linux, macOS or Windows. tmux and psmux do not offer it, and
view-only mode hides it.

On Windows a pane counts as
idle only when its shell has no child process, so a pane running `ping`, `nvim` or a nested
`cmd` is refused with nothing typed. A shell that keeps a long-lived child (`Start-Job`, a GUI
program started from it, something its profile launched) is refused the same way, and so is a
`wsl.exe` pane. Work that runs inside PowerShell itself has no child process, so the pane looks
idle: the start's Ctrl+C clears a wait (`Start-Sleep`, `Read-Host`), but it also stops a `.ps1`
script or a command such as `Copy-Item -Recurse` halfway, as pressing Ctrl+C there would. Start
an agent only in a pane you know is at its prompt.

## Limitations

- tmux: the chat follows the pane that has focus in the window. In a split window, it talks to
  the focused pane.
- psmux: only `%USERPROFILE%\.claude` is read. A `CLAUDE_CONFIG_DIR` set inside the pane is not
  followed.
- Herdr: the transcript is read from `~/.claude` of the user running Termote. A Claude Code
  started with another `CLAUDE_CONFIG_DIR` shows no history.
- Container mode is not supported.
- Only Claude Code and Codex for now.

<Aside>
  **Open terminal** is always one tap away. The terminal stream stays connected while you are in
  the Chat view, so switching back is instant.
</Aside>
