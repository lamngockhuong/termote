Long replies are hard to read in a terminal on a phone, and so is typing a prompt into one. When
a pane runs **Claude Code**, the header shows a **Terminal / Chat** switcher (on a phone, one
view button that opens a menu of views). The Chat view is a second way to look at the same
session: what you send there is typed into the pane, and what Claude Code writes shows up in both
views. Nothing runs in the background on its own.

## Requirements

- Claude Code running in a pane, under one of these backends:
  - **tmux** on Linux or macOS
  - **psmux** on Windows
  - **Herdr** on any OS, after running `herdr integration install claude` once
- A native install (`termote start`). The container image does not include Claude Code.

## What the Chat View Shows

- The whole conversation of the current session, read from the transcript Claude Code writes to
  disk: your messages, replies rendered as markdown, and tool calls collapsed with their result.
- New turns within about two seconds. After `/clear` or a resume, the view switches to the new
  session without mixing the two.
- Images in a reply as text links. They are never loaded, so a reply cannot make your browser
  contact another site.

## Sending a Message

Type in the box at the bottom and tap the send button (Ctrl+Enter on desktop). Multi-line
messages arrive as one turn, exactly as written.

Termote only sends when the screen shows Claude Code waiting at an empty input box. Otherwise
the message is refused and the pane gets no key at all:

| Message                                                    | Code                      | Meaning                                                                                      |
| ---------------------------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------- |
| Not sent: the agent is working / waiting for an answer     | `input_not_ready`         | Claude Code is busy or a dialog is open                                                      |
| Not sent: the input box already holds a draft              | `input_not_ready`         | Something is typed in the terminal's input box; send or clear it there                       |
| Not sent: the pane is in copy mode                         | `input_not_ready`         | The tmux pane is scrolled back in copy mode; leave it (`q`) in the terminal                  |
| Not sent: the text did not show in the input box           | `paste_not_confirmed`     | Enter was not sent; the text may be in the input box now                                     |
| The text was pasted but not submitted                      | `delivered_not_submitted` | The text is in the input box but Enter was not sent; check the terminal before sending again |
| The conversation changed; it has been reloaded             | `session_changed`         | The pane runs another session now (`/clear`, a resume); send again if you still want to      |
| Too long: the limit is 16 KB.                              | `text_too_long`           | The message is over 16 KB (UTF-8); split it                                                  |

Every refusal that leaves something to check offers **Open terminal**.

## Slash Commands

Type `/` at the start of a message and a list of commands opens above the box. Keep typing to
narrow it: names that start with what you typed come first, then any whose name or description
contains it. Each row shows where the command comes from:

- `built-in`: Claude Code's own commands, with `/exit` first.
- `project`: `.claude/commands/` and `.claude/skills/` in the pane's project (the folder the
  Files view shows).
- `user`: `commands/` and `skills/` in your Claude config dir (`~/.claude`, or
  `CLAUDE_CONFIG_DIR`).
- `plugin`: commands and skills of the plugins you have installed and enabled, named
  `/<plugin>:<name>`. A plugin turned off in the project's `.claude/settings.json` or
  `.claude/settings.local.json` is left out.

Skills carry a `skill` tag as well.

Tap a row, or press Enter or Tab, and the box becomes `/name ` so you can type arguments; it is
not sent until you send it. The arrow keys move through the list and Escape closes it, as does a
space after the name.

A few commands open a screen the Chat view cannot drive, such as `/model`, `/config`,
`/permissions`, `/resume` and `/mcp`. They are marked `opens in Terminal`: picking one sends it
and switches to the terminal. `/exit` asks before it is sent, since it ends Claude Code; the app
then goes back to the terminal.

Only names and descriptions are read, never what a command contains. A skill installed as a
symlink is listed when it leads into the project, the config dir or `~/.agents/skills`; a link to
anywhere else is not, and neither are MCP prompts. Any command can still be typed in full.

## Answering Dialogs

When Claude Code asks for permission or asks a single-choice question (up to nine options), a
card replaces the message box. Each button picks that option; **Cancel** sends Escape. If the
screen changed before your answer was sent, or another device answered first, nothing is sent
and the card shows the dialog that is open now.

A single-choice question keeps its buttons, `Chat about this` included. Its `Type something`
option is an **Other…** button: it opens a field for an answer of your own (one line, up to
1 KB), sent with **Send**. Termote moves the pointer to `Type something` in the terminal, types
the text there, checks that it shows, then presses Enter. If anything on screen is not what it
expects, it stops and the card shows the dialog that is open now; if the text did not show, it
may be left in the terminal's field, so check it there. **Cancel** under the field only closes
it: the dialog stays open. A line break or a control character is refused, not removed.

A question in several parts (a row of tabs such as `Size · Drink · Submit`) is answered one tab
at a time. The card shows the tabs as steps, with the one open marked; each answer moves Claude
Code to the next tab, which gets a card of its own, up to the Submit tab with **Submit answers**
and **Cancel**. Tap another step to go to that tab, to skip a question or come back to one. If
you change tabs in the terminal before tapping, nothing is sent and the card shows the tab that
is open now.

When several choices can be ticked at once, each button ticks or unticks one option, and
**Next** moves on with the options you ticked. **Other…** there adds your text as one more
option, already ticked; its button unticks it like the others.

A question that shows a preview beside its options is answered the same way: one tap picks the
option. The preview itself is only shown in the terminal.

## Limitations

- tmux: the chat follows the pane that has focus in the window. In a split window, it talks to
  the focused pane.
- psmux: only `%USERPROFILE%\.claude` is read. A `CLAUDE_CONFIG_DIR` set inside the pane is not
  followed.
- Herdr: the transcript is read from `~/.claude` of the user running Termote. A Claude Code
  started with another `CLAUDE_CONFIG_DIR` shows no history.
- Container mode is not supported.
- Only Claude Code for now.

<Aside>
  **Open terminal** is always one tap away. The terminal stream stays connected while you are in
  the Chat view, so switching back is instant.
</Aside>
