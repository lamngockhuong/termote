To see what an agent changed, you would otherwise type `ls`, `cat` and `git diff` on a phone
keyboard and read the output in a terminal. Termote has two views for this:

- **Files**: the pane's directory as a tree, opened one folder at a time. A text file opens with
  line numbers and syntax highlighting, a CSV or TSV file as a table, an image as the picture.
- **Changes**: when the directory is in a git repository, the files git reports as changed, and
  the diff of each one (for an image, the version before and after).

A file can be found by name in Files (see [Finding a File](#finding-a-file)). A text file can be
edited and saved from either view (see [Editing a File](#editing-a-file)), a new one created in
Files (see [Creating a File](#creating-a-file)), and a file or an empty folder deleted there (see
[Deleting a File](#deleting-a-file)). Nothing else changes from them: no file is renamed, and
nothing is staged, discarded or committed.

## Where to Find Them

- **Desktop**: the **Files** and **Changes** buttons in the header open a panel to the right of
  the terminal. The terminal stays on screen and keeps working. One panel shows at a time; press
  its button again to close it.
  - Drag the panel's left edge to make it wider or narrower (it always leaves room for the
    terminal); double-click the edge to go back to the default width. With the keyboard, focus
    the edge and use the Left/Right arrows, Home and End. The width is remembered on this device.
    The terminal is resized once, when you let go.
  - The **Maximize panel** button at the top of the panel lets it cover the terminal or the Chat
    view for a while; press it again, or Escape, to put it back. The terminal keeps its size
    underneath, so other devices on the same window see no change.
- **Phone**: Files and Changes are views in the header's view menu, alongside Terminal
  (and Chat, when Claude Code runs in the pane). The button shows the current view's icon; tap
  it to pick another view. Each view takes the whole screen.

If the window grows or shrinks between the two layouts, an open view follows: from the
phone view to the desktop panel, and back.

## Which Directory Is Shown

The root is the **working directory of the pane on screen**. When that directory is inside a git
repository, the root is the top of the repository instead, so Files and Changes cover the whole
repository. The root is shown at the top of both views, with `~` for your home directory.

The directory is the one of the program running in the pane, so it follows a `cd` in the shell.
A command that only passes through another directory for a moment does not move the root. When
the root does move while a view is open, the view reloads from the new root and says
`The pane's directory changed`.

Supported backends:

- **tmux** on Linux and macOS, natively or in the container
- **Herdr** on any OS. Herdr must report the pane's directory (`cwd`); an older Herdr that does
  not shows `Not supported by this backend`.
- **psmux** on Windows is not supported: it does not report the pane's directory, and the two
  views are not offered.

## Files

- Folders come first, then files, ignoring case. Tap a folder to open or close it.
- A folder shows at most 5000 entries. A longer folder says that only the first 5000 are shown.
- Devices, sockets and links that point outside the root are greyed out and do not open.
- A file opens in place of the tree, with its path, its size, a button to copy the path and one
  to wrap long lines (on by default on a phone). Long lines scroll inside the code area, never
  the whole page.
- Highlighting covers common languages and file names (TypeScript, Go, Python, shell,
  Dockerfile, Makefile, YAML, JSON, Markdown and others). It loads the first time a file needs
  it, so a device that never opens Files never downloads it.

| Shown                                                         | Why                                                                                              |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Text with colours                                             | A text file of up to 256 KiB, up to 5000 lines, no line over 2000 characters                     |
| Plain text, no colours                                        | A larger text file (up to 1 MiB), a language not covered, or highlighting that took over 3 seconds |
| `Not previewable (binary, special file or larger than 1 MiB)`  | A binary file that is not an image, a file over 1 MiB, or something that is not a regular file   |
| `This file can't be shown`                                     | A path termote never serves (see below)                                                          |

## Finding a File

The **Find a file…** box at the top of Files (above the keyboard on a phone) searches the names
of the files under the root. Results replace the tree after a moment's pause in typing; each row
shows the path.

- Tap a result, or press Enter on it, to open the file; the tree opens down to it, and Back
  returns to the results. The arrow keys move between the box and the results, and Escape clears
  the box.
- A file that git ignores is not searched unless **Include ignored** (the switch next to the box,
  shown only in a git repository) is on. Those results are dimmed and tagged `ignored`. The
  choice is remembered on this device.
- A name that usually holds secrets shows a lock, as in the tree. Only names are searched, never
  contents.
- Only the first 200 matches are shown (`More than 200 matches — type more to narrow`). In a very
  large repository or folder the search can stop early, and the list says
  `Search stopped early in a large tree`.
- The list of files is kept for 30 seconds, and saving, creating or deleting a file drops it.
  **Refresh** reads it again.
- Outside a git repository, the folder is walked (at most 32 levels deep, for 5 seconds), and
  linked folders are not entered.

The folders never searched for ignored files are set in Settings → Files →
**Excluded folders** (see [Settings](/usage/settings/#excluded-folders)). A file git tracks is
always found, even under one of them.

Paths Termote never serves (see [Never Shown](#never-shown)) never appear in the results.

## Editing a File

The pencil button (**Edit**) in a text file's bar turns its text into a plain text box, with
**Cancel** and **Save** in place of the other buttons. It is meant for small changes, such as
turning `status: review` into `status: approved` in a record's front matter, without asking the
agent or typing `sed`.

- A Markdown file is edited as its source, even when the preview is on. A CSV or TSV file shown
  as a table is edited in the table (see [Editing a Table](#editing-a-table)); shown as its
  source, or opened from Changes, it is edited as its source.
- Ctrl+S (Cmd+S on a Mac) saves. Cancel, or Back, with unsaved changes asks
  `Discard changes?` first.
- Line breaks stay as the file had them: a file with Windows line breaks (`\r\n`) keeps them.
- The text being edited stays while you switch views or the panel closes and opens again. It is
  kept only in the page's memory, never in the browser's storage, so closing or reloading the
  app loses it (a phone may close an app left in the background).
- In **Changes**, the diff of a file the working tree still has as text has the same Edit button
  (**Edit working copy** on the staged side: the working tree's file is what is saved). After
  saving, the diff of what is not staged shows, read again; when the file then matches the
  index, the list shows with `No changes left in <file>`.

When saving does not go through, your text stays in the box:

| Shown                                                 | What to do                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `The file changed on the host since you opened it`    | Something (often the agent) wrote the file meanwhile. **Reload** reads it again and drops your text; **Copy my text** copies it first. A save never overwrites the other change. |
| `This pane's folder changed`                           | The pane moved to another directory. Copy your text, then Cancel to see the file there.             |
| `Not sure the file was saved. Saving again is safe.`   | The connection dropped or the server did not answer within 30 seconds. Save again: the same text is not a conflict. |
| `The server can't write this file`                     | The file is read-only, belongs to another user, or its folder cannot be written                    |
| `The file system there is read-only`                   | The file is on a read-only disk or mount, such as a container volume mounted read-only             |
| `The host's disk or quota is full`                     | The host's disk, or your disk quota, has no room left                                              |

Some files have no Edit button, because the server would refuse the save: a symbolic link (or a
file reached through a linked folder), a file with several hard links, a file that mixes line
break styles or holds a NUL character, a file over 1 MiB, an image, and a file in Termote's own
data or upload folders. A file that may contain secrets can be edited once it has been shown.

<Aside type="caution">
  A save replaces the file with a new one in the same folder. If the agent writes the same file
  in the instant between the last check and the replacement, its change is lost. The new file
  keeps the old one's permissions, but not extended attributes or ACLs.
</Aside>

A view-only session (once that role exists) has no Edit button. Until the server enforces roles,
this is only hidden in the app.

## Creating a File

The **New file** button (a page with a plus) at the top of Files asks for a path from the pane's
directory, such as `docs/notes/today.md`. It starts with the folder you last tapped in the tree.
**Create** makes an empty file, and every folder on the path that is missing, then opens it in
the text box to type its contents and **Save**. The button shows over the tree only, not while a
file is open.

- An existing file or folder is never replaced: the box says
  `A file or directory of that name already exists`, with **Open it** to open that one instead.
- A name that usually holds secrets (`.env.local`, for example) asks
  `This name usually holds secrets. Create it anyway?` once; the new file then opens without
  asking to show it.
- When another file has unsaved changes, `Discard other changes?` asks first.
- When the connection drops before the server answers, the box says
  `The file may have been created. Refresh to check.`, and **Refresh** reads the tree again.
- Closing the box while **Create** runs does not stop it: the file is still made and shows in the
  tree, but it does not open.
- The folders made for the path stay when a later step fails, as with `mkdir -p`. A new file left
  empty stays too.

| Shown                                          | Why                                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `Part of this path is a file, not a directory` | A folder on the path is a file                                                                      |
| `Part of this path is a symbolic link`         | A folder on the path is a symbolic link: nothing is ever created through one                        |
| `Files can't be created there`                 | A path Termote never serves (see [Never Shown](#never-shown)), or its own data or upload folders    |
| `The server can't create a file there`         | The folder cannot be written                                                                        |
| `The file system there is read-only`           | The folder is on a read-only disk or mount, such as a container volume mounted read-only            |
| `The host's disk or quota is full`             | The host's disk, or your disk quota, has no room left                                               |
| `This name can't be used`                      | An empty part (`a//b`, a trailing `/`), a part that ends in a dot or a space, a control character such as a line break, more than 32 levels or 1024 bytes, or on Windows one of `<>:"\|?*` |

<Aside type="caution">
  A new file can be one that another tool reads or runs by itself, such as
  `.claude/settings.local.json`, `.vscode/tasks.json` or a file under `.github/workflows`.
  Anyone who can sign in to Termote can already run commands in the terminal, so this allows
  nothing new, but check what you create in such places.
</Aside>

A view-only session (once that role exists) has no New file button either; until the server
enforces roles, it is only hidden in the app.

## Deleting a File

A file or an **empty** folder can be deleted from Files, three ways: **Delete** in the **⋯** menu
of a row in the tree (with a mouse the button shows on hover or focus; on a touch screen it is
always there), the Delete key on a focused row, or the **Delete** button in the header of an open
file (not while it is being edited). A dialog shows the full path and asks first; **Cancel** has
the focus, so pressing Enter does not delete.

- A deleted file is not erased: it moves to Termote's trash on the host. A toast says
  `Deleted <name>` with **Undo** for 10 seconds, which puts it back where it was (it never
  replaces anything now there). A deleted empty folder is made again by Undo.
- The trash keeps a file for 7 days, at most 1 GiB in all (the oldest go first), and never
  removes one younger than an hour. The app has no trash browser: after the toast is gone, take
  the file from the trash folder on the host (`~/.cache/termote/trash` on Linux).
- A folder that is not empty is not deleted, and neither is the root itself.
- Deleting asks the server to check that the file is still the one you saw. If something (often
  the agent) changed it meanwhile, nothing is deleted.
- On another file system than the trash's (WSL's `/mnt/c`, a mounted volume, the container's
  `/workspace`), the file cannot be moved to the trash. The dialog then asks a second time,
  `Delete permanently? This cannot be undone.`, and only after that deletes it, with no Undo. In
  the container, every delete under `/workspace` is permanent in this way.
- A file whose name usually holds secrets is marked `This is a sensitive file` in the dialog.

| Shown                                                              | Why                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `The folder is not empty`                                           | Only an empty folder is deleted                                    |
| `The file changed since it was read`                                | Something changed the file after the dialog read it                |
| `Part of this path is a symbolic link`                              | Nothing is deleted through a link, and a link itself is not deleted |
| `This file has several hard links; delete it from a terminal`       | Another name would keep the file                                   |
| `The server can't delete this`                                      | The file belongs to another user                                   |
| `The file system there is read-only`                                | The file is on a read-only disk or mount                           |
| `Too large to delete here; use the terminal`                        | The file is over 512 MiB                                           |
| `Deleting is not available on this server`                          | The server has no usable trash                                     |

A view-only session (once that role exists) has no Delete button; until the server enforces
roles, it is only hidden in the app.

<Aside type="note">
  `termote uninstall` keeps the trash and prints its path; `termote uninstall --purge` removes it
  too. See [Uninstall](/installation/native/#uninstall).
</Aside>

## Markdown Preview

A Markdown file (`.md`, `.markdown`, `.mdx`) opens rendered: headings, lists, tables (they
scroll sideways on a phone), task lists, footnotes and code. The eye button in its bar switches
between the preview and the source; the choice is remembered on this device. A Markdown file
over 256 KiB opens as its source, with a note that it is too large to preview.

- **Code blocks** are highlighted in the language named after the opening fence (` ```ts `,
  ` ```bash `, ` ```go `...), with a button to copy the block. A block in a language not covered
  (`mermaid`, for example) is shown as plain text. The wrap button wraps code blocks too.
- **Front matter** (the `---` block at the top of docs and MDX pages) is shown as a code block.
- **Raw HTML and MDX components** are shown as the text they are, never run.
- **Images are never loaded.** An image inside the root shows as a link that opens the file in
  Files; an image on the web shows as a link to its site.

Links:

- A link to another file under the root (`docs/guide.md`, `../README.md`, `/src/main.go`) opens
  it in place; `guide.md#install` opens it at that heading. A leading `/` means the root.
- A link to a folder shows the tree with that folder open.
- `#heading` scrolls to the heading in the same file.
- The back button returns to the file the link was followed from, where you left it, before
  going back to the tree.
- A link to a missing file says `Not found`. A link that leaves the root, or that uses another
  scheme than `http`/`https` (`javascript:`, `file:`, `data:`), is shown as plain text.
- `http`/`https` links open in a new tab; hovering shows the site they go to.

In **Changes**, a changed Markdown file has the same eye button over its diff: it shows the
current version of the file, rendered with the same rules. A deleted file has no preview. Its
links open in Files.

## CSV and TSV as a Table

A `.csv`, `.tsv` or `.tab` file opens as a table: the header row stays at the top and the row
numbers at the left while the rest scrolls, and a 1 MiB file scrolls as smoothly as a short one.
The eye button in its bar switches between the table and the source; the choice is remembered on
this device, apart from the one for Markdown. Changes keeps showing the diff of a CSV file as
text.

- **Delimiter**: a `.tsv` or `.tab` file is read with tabs. For a `.csv` file the delimiter is
  guessed from its first lines (comma, semicolon, tab or pipe); the **Delimiter** menu reads it
  again with another one.
- **Quotes** follow RFC 4180: a value in double quotes can hold the delimiter, a line break and
  `""` for one quote. A value that holds a line break shows `↵` in its cell.
- **Header row** (on at first) takes the first row as the column names. Turned off, the
  columns are `Column 1`, `Column 2`… and the first row is a row like the others.
- **Sorting**: press a column name to sort by it, again to reverse, a third time to go back to
  the file's order. Text sorts without regard to case and runs of digits by their value
  (`item 2` before `item 10`; decimals are compared digit run by digit run, so `1.5` comes after
  `1.25`). Empty cells go last, and the header row is never sorted.
- **Filter rows** keeps the rows where any cell contains what you typed, ignoring case, and
  shows how many are left (`12 / 340 rows`).
- **Records** shows one row at a time as `column: value`, with **Previous** and **Next**, for a
  phone where a row is wider than the screen.
- Tap a cell (or press Enter on it) to see its whole value, with a button to copy it. A cell
  shows at most 1024 characters; the full value is only in that sheet.
- A row with another number of cells than the header has its number in orange; hovering or a
  screen reader says how many cells it has.

Sorting, filtering, the delimiter and the header row only change what is shown. Nothing is
written to the file, and they are forgotten when the file is closed.

| Shown                                                   | Why                                                                     |
| ------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Unclosed quote on line N: shown as source`             | A quote opened on that line never closes; the file shows as its source |
| `Showing 200 of N columns. See all in Source`           | Only the first 200 columns are shown; the source has them all           |
| `No rows`                                               | The file is empty                                                       |

<Aside type="caution">
  A value is shown as text, never run: a formula such as `=HYPERLINK(...)` shows as typed.
  Characters that could make a value read as something else, such as the right-to-left override
  that makes `0001` read `1000`, control characters and zero-width spaces, show as marks like
  `⟨U+202E⟩`. **Copy** in a cell's sheet copies the value itself, those characters included,
  without the quotes that wrap it in the file.
</Aside>

### Editing a Table

**Edit** on a file shown as a table keeps the table and makes each cell editable, with **Cancel**
and **Save** in the bar as for any file. Opened from Changes, or shown as its source, the file is
edited as text instead.

- Tap a cell to change its value in a sheet: the value can hold several lines, and characters
  that hide or reorder text show below it as `⟨U+XXXX⟩`. **Apply** puts it in the table; a cell
  a short row does not have can be set too.
- **Add row below** (in that sheet) and the **Add a row at the end** button add an empty row and
  open its first cell. **Delete row** asks first, and says when the row is the file's first one,
  which is the header when **Header row** is on. To rename a column or delete the header, turn
  **Header row** off first: the header row is then a row you can open.
- **Undo** and **Redo**, or Ctrl+Z and Ctrl+Shift+Z (Cmd on a Mac) on the table, walk through
  your changes; Ctrl+S saves. Typed in the sheet or the filter, these keys belong to that box.
- Saving changes only the characters of the cells you set: a value that needs quotes (it holds
  the delimiter, a quote, a line break, or a space at either end) gets them, a cell that had
  quotes keeps them, and a new row uses the file's delimiter and line breaks. Every other byte
  stays as it was.
- The delimiter cannot change while editing. When the one you are viewing with is not the one
  found in the file, Edit asks first: edits written with another delimiter can shift the columns.
- Sorting and filtering still work while editing; they never change the file.

If the file changed on the host since you opened it, Save says so and writes nothing. **Reload
and reapply** reads the file again and applies each of your changes to the row it was made on,
found by that row's values rather than its number, so a row an agent added or removed above it
does not matter. A change whose row is gone, or matches more than one row, is listed with why, and
a cell's value can be copied to set it again by hand; changes after an added or deleted row that
could not be applied are listed too, since they may concern that row. When the file read again is
no longer a table that can be edited, nothing is applied and Save stays off. Nothing is saved
until you press Save.

## Images

A PNG, JPEG, GIF or WebP file (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) opens as the picture,
fit to the width of the view, over a checkerboard so transparent parts show. Under it are its
size in pixels and its file size. The server checks the file's contents, not only its name: a
file named `.png` that holds something else is not shown.

An SVG file opens as its source first, like any text file. The **Image** button in its bar
switches between the source and the picture; the choice is remembered on this device. In
Changes, the same button switches between the diff and the pictures.

In **Changes**, a changed image shows the version before and after, side by side on a desktop
and one above the other on a phone:

| Side                 | Before    | After          |
| -------------------- | --------- | -------------- |
| Not staged (Changes) | the index | the working tree |
| Staged               | `HEAD`    | the index      |

A new image shows only the after side (`Added`), a deleted one only the before side
(`Deleted`). A renamed image reads the before side from its old path, shown next to the label.
For a conflict, only the file as it is now in the working tree is shown. The pictures are read
again when you press Refresh or when the file's status changes, not every 5 seconds.

| Shown                                                          | Why                                                                     |
| -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Larger than 10 MiB`                                            | Images over 10 MiB are not shown                                         |
| `Too many pixels to show (over 40 megapixels)`                  | An image (or a GIF frame) over 40 million pixels, which a phone may not hold |
| `Not previewable (not a PNG, JPEG, GIF, WebP or SVG image)`     | The contents are not one of these types (or an SVG without an `<svg>`)  |
| `Stored in Git LFS: only the pointer is in git`                 | git holds a Git LFS pointer, not the image; termote does not fetch it   |
| `The image could not be decoded`                                | The browser could not read the file (damaged, or a format it lacks)     |
| `Busy, try again`                                               | Several images are being read at once; the **Retry** button reads it again |

A name that usually holds secrets asks first, as for text. An SVG opened by its address never
runs a script: the server sends it with a policy that forbids scripts, and as a download.

## Changes

The list follows `git status` and is read again every 5 seconds while the view is open and the
browser tab is visible. It is grouped:

- **Conflicts**: files with an unresolved merge conflict
- **Staged**: changes added to the index
- **Changes**: changes in the working tree that are not staged
- **Untracked**: new files git does not track yet

Each file shows a letter: `M` modified, `A` added, `D` deleted, `R` renamed (with the old path),
`C` copied, `T` type changed, `U` conflict, `?` untracked. A file with both staged and unstaged
changes is listed in both groups, and each opens the diff of its own side. An untracked file
opens as all added lines.

The diff shows each hunk with the old and new line numbers (one column on a narrow phone
screen), added lines on green and removed lines on red, with `+` and `-` kept so the colour is
never the only sign.

| Shown                            | Why                                                                         |
| -------------------------------- | --------------------------------------------------------------------------- |
| `Not a git repository`            | The pane's directory is not inside a git repository                         |
| `Binary file changed`             | git reports a binary change; there are no lines to show                     |
| `Diff truncated at 1 MiB`         | The diff of this file is longer than 1 MiB; only its start is shown         |
| `Unresolved conflict`             | A conflicted file is shown whole, as it is now in the working tree          |
| `No longer changed`               | The file was committed, reverted or removed after you opened it            |
| `git took too long; trying again` | `git status` took over 10 seconds (a very large repository); it backs off   |

Submodules are not listed, and their contents are not compared.

When the list has more than 15 entries, a **Filter changes…** box appears above it. It keeps the
files whose path contains what you typed, ignoring case (for a rename, the old path counts too).
Groups with nothing left are hidden, the counts show the filtered numbers, and
`No changes match` shows when nothing is left. Escape clears the box. The filter lives in the
page only: it is cleared when you leave the view or when the root moves.

## Files That May Contain Secrets

Files whose names usually mean secrets are listed with a lock and the word `Sensitive`: for
example `.env`, `.env.*`, `*.env` and `.envrc`, private keys (`*.pem`, `*.key`, `*.jks`,
`id_rsa*`, `id_ed25519*`), `.netrc`, `.npmrc`, `.pgpass`, `.my.cnf`, `.vault-token`,
`.git-credentials`, `credentials*`, `auth.json`, `secrets.*`, `.dev.vars`, Terraform state and
variables (`*.tfstate`, `*.tfvars`) and anything under `.ssh`, `.gnupg`, `.aws`, `.kube`, `.docker`, `.config/gh`
or `.config/gcloud`. A link to such a file counts too, as does a rename from or to one.

Opening one asks `This file may contain secrets. Show its contents?` first, for the file and for
its diff. The answer is not remembered: the next time, it asks again. The server checks this
itself: without the confirmation it sends no contents at all.

<Aside type="caution">
  The lock is a warning based on names, not a guarantee. A secret in a file with an ordinary
  name (`prod-creds.yaml`) is shown without asking. Anyone who can sign in to Termote can read
  every file under the pane's directory.
</Aside>

## Never Shown

Some paths are never served (or saved, created in, deleted, or found by name), even after confirming:

- Termote's own config and state directories (the saved password, logs) and its trash
- `/proc`, `/sys` and `/dev` (process environments and devices)
- the repository's `.git` directory, which is not listed in Files either

Paths are checked on the server against the root: `..`, absolute paths and links that lead
outside the root are refused.

## How git Is Run

Termote runs `git status` and `git diff` itself to fill Changes, and `git cat-file` to read the
before and after versions of an image. A repository's own settings
cannot make it run a program: file system monitors, filter drivers, external diff tools and text
conversion are turned off for these commands, and submodules are skipped. At most two git
commands run at a time, each limited to 10 seconds.
