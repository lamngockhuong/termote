To see what an agent changed, you would otherwise type `ls`, `cat` and `git diff` on a phone
keyboard and read the output in a terminal. Termote has two views for this:

- **Files**: the pane's directory as a tree, opened one folder at a time. A text file opens with
  line numbers and syntax highlighting, a CSV or TSV file as a table, an image as the picture.
- **Changes**: when the directory is in a git repository, the files git reports as changed, and
  the diff of each one (for an image, the version before and after).

A file can be found by name in Files (see [Finding a File](#finding-a-file)). A text file can be
edited and saved from either view (see [Editing a File](#editing-a-file)), a new one created in
Files (see [Creating a File](#creating-a-file)), a file or an empty folder deleted there (see
[Deleting a File](#deleting-a-file)), and a file renamed or moved there (see
[Renaming or Moving a File](#renaming-or-moving-a-file)). Nothing else changes from them: no
folder is renamed, and nothing is staged, discarded or committed.

## Where to Find Them

- **Desktop**: the **Files** and **Changes** buttons in the header open a panel to the right of
  the terminal. The terminal stays on screen and keeps working. One panel shows at a time; press
  its button again to close it.
  - Drag the panel's left edge to make it wider or narrower (it always leaves room for the
    terminal); double-click the edge to go back to the default width. With the keyboard, focus
    the edge and use the Left/Right arrows, Home and End. The width is remembered on this device.
    The terminal is resized once, when you let go.
  - The **Maximize panel** button at the top of the panel lets it cover the terminal or the Chat
    view for a while; press it again, or Escape, to put it back. The terminal keeps its size
    underneath, so other devices on the same window see no change.
- **Phone**: Files and Changes are views in the header's view menu, alongside Terminal
  (and Chat, when Claude Code runs in the pane). The button shows the current view's icon; tap
  it to pick another view. Each view takes the whole screen.

If the window grows or shrinks between the two layouts, an open view follows: from the
phone view to the desktop panel, and back.

## Which Directory Is Shown

The root is the **working directory of the pane on screen**. When that directory is inside a git
repository, the root is the top of the repository instead, so Files and Changes cover the whole
repository. The root is shown at the top of both views, with `~` for your home directory.

The directory is the one of the program running in the pane, so it follows a `cd` in the shell.
A command that only passes through another directory for a moment does not move the root. When
the root does move while a view is open, the view reloads from the new root and says
`The pane's directory changed`.

Supported backends:

- **tmux** on Linux and macOS, natively or in the container
- **Herdr** on any OS. Herdr must report the pane's directory (`cwd`); an older Herdr that does
  not shows `Not supported by this backend`.
- **psmux** on Windows is not supported: it does not report the pane's directory, and the two
  views are not offered.

## Files

- Folders come first, then files, ignoring case. Tap a folder to open or close it.
- A folder shows at most 5000 entries. A longer folder says that only the first 5000 are shown.
- Devices, sockets and links that point outside the root are greyed out and do not open.
- A file opens in place of the tree, in a tab (see [Open Files as Tabs](#open-files-as-tabs)),
  with its path, its size, a button to copy the path and one to wrap long lines (on by default on
  a phone). Long lines scroll inside the code area, never
  the whole page.
- Highlighting covers common languages and file names (TypeScript, Go, Python, shell,
  Dockerfile, Makefile, YAML, JSON, Markdown and others). It loads the first time a file needs
  it, so a device that never opens Files never downloads it.

| Shown                                                         | Why                                                                                              |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Text with colours                                             | A text file of up to 256 KiB, up to 5000 lines, no line over 2000 characters                     |
| Plain text, no colours                                        | A larger text file (up to 1 MiB), a language not covered, or highlighting that took over 3 seconds |
| `Not previewable (binary, special file or larger than 1 MiB)`  | A binary file that is not an image, a file over 1 MiB, or something that is not a regular file   |
| `This file can't be shown`                                     | A path termote never serves (see below)                                                          |

## Open Files as Tabs

Opening a file keeps the ones already open: each has a tab, and going back to a tab brings back
where you were in that file and its unsaved changes.

- **A single click opens a preview tab**, its name in italics: the next file opened the same way
  replaces it. A file gets a tab of its own once you double-click it (in the tree or on its tab),
  start editing it, create it, or tap **Keep open** (the pin in its bar).
- A file that is already open shows its tab; it never opens twice.
- The first tab, **Files**, shows the tree; the files stay open behind it. Back, when no link is
  left to retrace, shows the tree too.
- **Closing a tab**: its × button, a middle click, or Delete on the focused tab. A tab with
  unsaved changes (a dot after its name) asks `Discard changes?` first.
- **At most 10 tabs.** Opening one more closes the tab used longest ago, never the one shown and
  never one with unsaved changes. When every other tab has unsaved changes, more than 10 stay
  open.
- **On a phone** there is no tab bar. The button with the number of open files
  (`Open files (N)`), in the file's bar and above the tree, lists them in a sheet: tap one to show
  it, or keep it open, or close it.
- A file deleted in Termote closes its tab, and a file renamed in Termote keeps its tab under the
  new name. A file deleted or renamed by something else keeps its tab, which shows
  `File not found` with **Close tab**.
- When the pane moves to another directory, the tabs opened in the old one close. Tabs with
  unsaved changes ask first: **Discard and close** drops the changes, **Keep** leaves them open
  so you can copy their text (they can no longer be saved).
- A file that may contain secrets asks again in every new tab. A tab where you chose to show it
  keeps it shown until the tab closes.
- Tabs live only in the page's memory: reloading the app starts with none.

## Finding a File

The **Find a file…** box at the top of Files (above the keyboard on a phone) searches the names
of the files under the root. Results replace the tree after a moment's pause in typing; each row
shows the path.

- Tap a result, or press Enter on it, to open the file; the tree opens down to it, and Back
  returns to the results. The arrow keys move between the box and the results, and Escape clears
  the box.
- A file that git ignores is not searched unless **Include ignored** (the switch next to the box,
  shown only in a git repository) is on. Those results are dimmed and tagged `ignored`. The
  choice is remembered on this device.
- A name that usually holds secrets shows a lock, as in the tree. Only names are searched here;
  the contents of files are searched in the **Search** tab (see
  [Searching File Contents](#searching-file-contents)).
- Only the first 200 matches are shown (`More than 200 matches — type more to narrow`). In a very
  large repository or folder the search can stop early, and the list says
  `Search stopped early in a large tree`.
- The list of files is kept for 30 seconds, and saving, creating or deleting a file drops it.
  **Refresh** reads it again.
- Outside a git repository, the folder is walked (at most 32 levels deep, for 5 seconds), and
  linked folders are not entered.

The folders never searched for ignored files are set in Settings → Files →
**Excluded folders** (see [Settings](/usage/settings/#excluded-folders)). A file git tracks is
always found, even under one of them.

Paths Termote never serves (see [Never Shown](#never-shown)) never appear in the results.

## Searching File Contents

The **Files | Search** switch at the top of Files shows the **Search** tab, which searches the
text of the files under the root. On a desktop, Ctrl+Shift+F (Cmd+Shift+F on a Mac) opens it and
puts the cursor in the box, from anywhere in Files; from the terminal the keys stay the
terminal's.

- The search runs as you type, after a short pause, once the box holds at least 2 characters.
  The text is searched as typed: spaces at either end count.
- **Match case**, **Whole word** and **Regular expression** (the buttons next to the box) change
  how the text matches; they are remembered on this device. Without Match case, case is ignored.
  A regular expression uses Go's syntax (RE2); whole words are made of the letters `A`–`Z`,
  `a`–`z`, digits and `_`. A regular expression that can match empty text, such as `a*`, is
  refused (`This pattern matches empty text`): write `a+` instead.
- The **…** button shows two more boxes: **Files to include** and **Files to exclude**, each a
  comma-separated list of patterns such as `*.ts, src/`. A pattern without `/` matches the file
  name in any folder; `**` stands for any number of folders; a pattern ending in `/` matches
  everything in that folder.
- Results are grouped by file, with the number of matching lines; each line shows its number and
  the matches highlighted. Groups past the first 50 files start closed. Tap a line, or press Enter
  on it, to open the file at that line, highlighted in the middle of the view. Markdown, CSV/TSV
  and SVG files open as their source in that tab, whatever the preview settings say. Back returns
  to the same results. The arrow keys move between the box and the results, and Escape goes back
  to the box.
- At most 2000 lines are shown (`Showing the first 2000 lines`), and 100 lines per file (the rest
  is counted under the file). A search stops after 5 seconds or 256 MiB read
  (`Stopped early: some files were not searched`); a line longer than 16 KiB is searched on its
  start only. Two searches can run at once on the server; a third says `Search busy, try again`.
- If the pane's directory changed since the search, the results are dimmed and cannot be opened
  until the next search.

The files searched are the ones **Find a file** lists without **Include ignored**. These are
never searched:

- files git ignores, in a git repository;
- files that may contain secrets (see
  [Files That May Contain Secrets](#files-that-may-contain-secrets)), counted under the results
  (`2 sensitive files not searched`);
- dot-files and dot-folders when the folder shown is your home folder or holds it (shell
  histories and tool settings hold secrets under ordinary names), also counted;
- binary files, files that are not UTF-8 text, and files larger than 1 MiB;
- paths Termote never serves (see [Never Shown](#never-shown)).

A view-only device searches the same files it can open.

## Editing a File

The pencil button (**Edit**) in a text file's bar turns its text into an editor, with
**Cancel** and **Save** in place of the other buttons. It is meant for small changes, such as
turning `status: review` into `status: approved` in a record's front matter, without asking the
agent or typing `sed`.

On a computer with a mouse the editor shows line numbers and colors the code, and has the keys
below. On a phone or a touch tablet the text is in a plain text box, as it always was. If the
editor cannot load (the connection dropped), the plain text box takes its place with
`Could not load the editor` and **Retry**: what you typed is kept either way.

| Keys                                   | What they do                                                  |
| -------------------------------------- | ------------------------------------------------------------- |
| Ctrl+S (Cmd+S on a Mac)                | Save                                                          |
| Ctrl+F (Cmd+F on a Mac)                | Find in the file; Enter or F3 goes to the next match, Escape closes |
| Ctrl+H                                 | Find and replace (Cmd+Alt+F too on a Mac)                     |
| Ctrl+G                                 | Go to a line                                                  |
| Ctrl+D (Cmd+D on a Mac)                | Select the next occurrence of the selection                   |
| Alt+drag, Ctrl+Alt+↑/↓ (Cmd+Alt+↑/↓ on a Mac)                 | Several cursors                                               |
| Ctrl+Z, Ctrl+Shift+Z (Cmd+Z, Cmd+Shift+Z on a Mac)                   | Undo, redo                                                    |
| Tab, Shift+Tab                         | Indent, unindent                                              |

Ctrl+H and Ctrl+G are the Ctrl key on a Mac too: Cmd+H hides the browser there, and Cmd+G finds
the next match. Tab indents inside the editor; to move the focus out with the keyboard, press
Ctrl+M (Shift+Alt+M on a Mac), then Tab. Font size, tab size, line wrapping and Vim keys are in
Settings → Files (see [Settings](/usage/settings/#editor)). With Vim keys on, the keys are Vim's
(`/` finds, `:w` saves), except Ctrl+S, which still saves.

A search result opens the editor at the match when the file is being edited, and Edit in
Changes opens it at the first change of the diff.

- A Markdown file is edited as its source, even when the preview is on. A CSV or TSV file shown
  as a table is edited in the table (see [Editing a Table](#editing-a-table)); shown as its
  source, or opened from Changes, it is edited as its source.
- Ctrl+S (Cmd+S on a Mac) saves. Cancel, or Back, with unsaved changes asks
  `Discard changes?` first.
- Line breaks stay as the file had them: a file with Windows line breaks (`\r\n`) keeps them.
- The text being edited stays while you switch views or tabs, or the panel closes and opens
  again. Each file keeps its own unsaved changes, so several files can be edited at once; a file
  edited from Changes shares its text with the same file in Files. It is kept only in the page's
  memory, never in the browser's storage, so closing or reloading the
  app loses it (a phone may close an app left in the background).
- In **Changes**, the diff of a file the working tree still has as text has the same Edit button
  (**Edit working copy** on the staged side: the working tree's file is what is saved). After
  saving, the diff of what is not staged shows, read again; when the file then matches the
  index, the list shows with `No changes left in <file>`.

When saving does not go through, your text stays in the box:

| Shown                                                 | What to do                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `The file changed on the host since you opened it`    | Something (often the agent) wrote the file meanwhile. **Reload** reads it again and drops your text; **Copy my text** copies it first. A save never overwrites the other change. |
| `This pane's folder changed`                           | The pane moved to another directory. Copy your text, then Cancel to see the file there.             |
| `Not sure the file was saved. Saving again is safe.`   | The connection dropped or the server did not answer within 30 seconds. Save again: the same text is not a conflict. |
| `The server can't write this file`                     | The file is read-only, belongs to another user, or its folder cannot be written                    |
| `The file system there is read-only`                   | The file is on a read-only disk or mount, such as a container volume mounted read-only             |
| `The host's disk or quota is full`                     | The host's disk, or your disk quota, has no room left                                              |

Some files have no Edit button, because the server would refuse the save: a symbolic link (or a
file reached through a linked folder), a file with several hard links, a file that mixes line
break styles or holds a NUL character, a file over 1 MiB, an image, and a file in Termote's own
data or upload folders. A file that may contain secrets can be edited once it has been shown.

<Aside type="caution">
  A save replaces the file with a new one in the same folder. If the agent writes the same file
  in the instant between the last check and the replacement, its change is lost. The new file
  keeps the old one's permissions, but not extended attributes or ACLs.
</Aside>

A view-only session (once that role exists) has no Edit button. Until the server enforces roles,
this is only hidden in the app.

## Creating a File

The **New file** button (a page with a plus) at the top of Files asks for a path from the pane's
directory, such as `docs/notes/today.md`. It starts with the folder you last tapped in the tree.
**Create** makes an empty file, and every folder on the path that is missing, then opens it in
the text box to type its contents and **Save**, in a tab of its own. The button shows over the
tree only, not while a file is shown.

- An existing file or folder is never replaced: the box says
  `A file or directory of that name already exists`, with **Open it** to open that one instead.
- A name that usually holds secrets (`.env.local`, for example) asks
  `This name usually holds secrets. Create it anyway?` once; the new file then opens without
  asking to show it.
- When the connection drops before the server answers, the box says
  `The file may have been created. Refresh to check.`, and **Refresh** reads the tree again.
- Closing the box while **Create** runs does not stop it: the file is still made and shows in the
  tree, but it does not open.
- The folders made for the path stay when a later step fails, as with `mkdir -p`. A new file left
  empty stays too.

| Shown                                          | Why                                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `Part of this path is a file, not a directory` | A folder on the path is a file                                                                      |
| `Part of this path is a symbolic link`         | A folder on the path is a symbolic link: nothing is ever created through one                        |
| `Files can't be created there`                 | A path Termote never serves (see [Never Shown](#never-shown)), or its own data or upload folders    |
| `The server can't create a file there`         | The folder cannot be written                                                                        |
| `The file system there is read-only`           | The folder is on a read-only disk or mount, such as a container volume mounted read-only            |
| `The host's disk or quota is full`             | The host's disk, or your disk quota, has no room left                                               |
| `This name can't be used`                      | An empty part (`a//b`, a trailing `/`), a part that ends in a dot or a space, a control character such as a line break, more than 32 levels or 1024 bytes, or on Windows one of `<>:"\|?*` |

<Aside type="caution">
  A new file can be one that another tool reads or runs by itself, such as
  `.claude/settings.local.json`, `.vscode/tasks.json` or a file under `.github/workflows`.
  Anyone who can sign in to Termote can already run commands in the terminal, so this allows
  nothing new, but check what you create in such places.
</Aside>

A view-only session (once that role exists) has no New file button either; until the server
enforces roles, it is only hidden in the app.

## Deleting a File

A file or an **empty** folder can be deleted from Files, three ways: **Delete** in the **⋯** menu
of a row in the tree (with a mouse the button shows on hover or focus; on a touch screen it is
always there), the Delete key on a focused row, or the **Delete** button in the header of an open
file (not while it is being edited). A dialog shows the full path and asks first; **Cancel** has
the focus, so pressing Enter does not delete.

- A deleted file is not erased: it moves to Termote's trash on the host. A toast says
  `Deleted <name>` with **Undo** for 10 seconds, which puts it back where it was (it never
  replaces anything now there). A deleted empty folder is made again by Undo.
- The trash keeps a file for 7 days, at most 1 GiB in all (the oldest go first), and never
  removes one younger than an hour. The app has no trash browser: after the toast is gone, take
  the file from the trash folder on the host (`~/.cache/termote/trash` on Linux).
- A folder that is not empty is not deleted, and neither is the root itself.
- Deleting asks the server to check that the file is still the one you saw. If something (often
  the agent) changed it meanwhile, nothing is deleted.
- On another file system than the trash's (WSL's `/mnt/c`, a mounted volume, the container's
  `/workspace`), the file cannot be moved to the trash. The dialog then asks a second time,
  `Delete permanently? This cannot be undone.`, and only after that deletes it, with no Undo. In
  the container, every delete under `/workspace` is permanent in this way.
- A file whose name usually holds secrets is marked `This is a sensitive file` in the dialog.

| Shown                                                              | Why                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `The folder is not empty`                                           | Only an empty folder is deleted                                    |
| `The file changed since it was read`                                | Something changed the file after the dialog read it                |
| `Part of this path is a symbolic link`                              | Nothing is deleted through a link, and a link itself is not deleted |
| `This file has several hard links; delete it from a terminal`       | Another name would keep the file                                   |
| `The server can't delete this`                                      | The file belongs to another user                                   |
| `The file system there is read-only`                                | The file is on a read-only disk or mount                           |
| `Too large to delete here; use the terminal`                        | The file is over 512 MiB                                           |
| `Deleting is not available on this server`                          | The server has no usable trash                                     |

A view-only session (once that role exists) has no Delete button; until the server enforces
roles, it is only hidden in the app.

<Aside type="note">
  `termote uninstall` keeps the trash and prints its path; `termote uninstall --purge` removes it
  too. See [Uninstall](/installation/native/#uninstall).
</Aside>

## Renaming or Moving a File

A file can be renamed from Files: **Rename** in the **⋯** menu of its row in the tree, or the
**Rename** button in the header of an open file (not while it is being edited; a file with unsaved
changes is renamed from its row). On a phone, a finger resting on a row opens the same menu. The
dialog shows the path from the pane's directory with the name, without its extension, selected.

- Change the folders in the path to move the file. A folder that does not exist yet is created.
- Nothing is ever replaced: if a file or folder of the new name exists, the dialog says so and
  offers **Open it**.
- The file's open tab, its unsaved changes and its editor in Changes follow it to the new path,
  in every pane showing the same directory. Saving afterwards writes the new path.
- A toast says `Renamed <old> to <new>` (or `Moved <name> to <folder>`) with **Undo**, which
  renames it back. Folders made for the move stay. A file whose old name the server would not
  accept as a new one (one ending in a dot or a space) has no Undo.
- Changes then shows a deleted file and an untracked one, as after `mv`, until you stage them;
  Termote does not run `git mv`.
- Only files are renamed, not folders or links.
- A file whose name usually holds secrets, before or after, is renamed after a second ask.

| Shown                                                   | Why                                                                        |
| ------------------------------------------------------- | -------------------------------------------------------------------------- |
| `A file or directory of that name already exists`       | The new path is taken; nothing was replaced                                |
| `This file no longer exists`                            | Something removed or moved the file after the tree was read                |
| `<path> has unsaved changes. Save or discard them first` | The file at the new path is being edited                                   |
| `The file changed while it was being renamed`           | Something replaced the file during the rename; nothing was moved           |
| `Can't move a file to another file system`              | The new folder is on another disk or mount; a file is never copied         |
| `The file is open in another program on the host`       | Windows: another program holds the file open                               |
| `Part of this path is a symbolic link`                  | Nothing is renamed through a link                                          |
| `The server can't rename this file`                     | The file or its folder belongs to another user, or the folder is protected |
| `The file system there is read-only`                    | The file is on a read-only disk or mount                                   |

A view-only session has no Rename.

## Downloading a File

A copy of a file can be saved on the device you are using: **Download** in the **⋯** menu of its
row in the tree (on a phone, a finger resting on the row opens it), or the **Download** button in
the header of an open file (in the header's menu on a phone). The browser saves it as it saves any
download, under the file's name; nothing is opened or shown, whatever the file holds.

- Any regular file can be downloaded, also one Termote cannot preview (binary, larger than 1 MiB),
  up to **100 MiB**.
- A file whose name usually holds secrets is downloaded after a second ask; an open one you chose
  to show is downloaded at once.
- Only files are downloaded, not folders or links, and never through a folder that is a link.
- In the iOS app added to the Home Screen, the file opens in the share sheet: pick **Save to
  Files**. Closing the sheet saves nothing.
- Every download is written to the server log as an `audit: download` line (the path inside the
  pane's directory, the size and who asked).

| Shown                                                | Why                                                                  |
| ---------------------------------------------------- | -------------------------------------------------------------------- |
| `<name> is larger than 100 MiB, too large to download` | The file is over the limit                                           |
| `Too many files at once; try again`                  | Other downloads or images are being read; try again in a moment      |
| `<name> is gone`                                     | Something removed or moved the file after the tree was read          |
| `<name> is not a regular file; not downloaded`       | A FIFO, a socket or a device                                         |
| `A link on that path; not downloaded`                | The file or a folder on its path is a symbolic link                  |
| `<name> can't be downloaded from here`               | Termote's own folders, the install's data, `.git` and the upload store |
| `<name> changed; try again`                          | Something replaced the file while it was checked                     |

A view-only session has no Download.

## Markdown Preview

A Markdown file (`.md`, `.markdown`, `.mdx`) opens rendered: headings, lists, tables (they
scroll sideways on a phone), task lists, footnotes and code. The eye button in its bar switches
between the preview and the source; the choice is remembered on this device. A Markdown file
over 256 KiB opens as its source, with a note that it is too large to preview.

- **Code blocks** are highlighted in the language named after the opening fence (` ```ts `,
  ` ```bash `, ` ```go `...), with a button to copy the block. A block in a language not covered
  is shown as plain text. The wrap button wraps code blocks too.
- **Mermaid diagrams** (` ```mermaid `) are drawn as images once you scroll to them: flowcharts,
  sequence, class, state, Gantt and the other kinds. The code button in the block's bar switches
  between the diagram and its source; Copy always copies the source. A wide diagram scrolls
  sideways. The diagram is a picture: nodes and links in it cannot be clicked, and the diagram
  follows the light or dark theme of Termote, whatever its `%%{init}%%` line or front matter
  asks for. A shape with an image or an icon (`@{ img: ... }`) is drawn without it, so nothing
  is loaded. The source is shown instead, with the reason, when the diagram is too large (over
  50 KB, or over 500 links), is not valid Mermaid, is of a kind the renderer does not know, takes
  longer than 10 seconds, or the renderer cannot be loaded. The renderer is downloaded the first
  time a diagram is shown, not when the app is installed: offline, until then, diagrams show as
  their source with "Could not load the diagram renderer". Diagrams are drawn in the background,
  so even a large one never makes the page stop responding.
- **Saving a diagram.** Once drawn, a diagram's bar has three more buttons, also in its full
  screen view: **Share** opens the share sheet with the diagram as a PNG (on an iPad or iPhone:
  Save Image, Notes, Files or any note app), **Copy image** puts the PNG on the clipboard to
  paste into a note, and **Download SVG** saves the diagram as an SVG file. The PNG is twice the
  diagram's size (less for a very large one), in the theme it is shown in, with that theme's
  background; the SVG file keeps that background too. Named after the file and the diagram's
  number, as `README-mermaid-1.png`. Share and Copy image show only where the browser offers
  them (Firefox on a desktop and Chrome on Linux have no Share), and only on a secure page:
  over HTTPS (such as `termote start --tailscale`) or on `localhost`. Opened over plain HTTP
  on the LAN, only Download SVG shows. In the app added to the Home Screen on iOS, Download
  SVG goes through the share sheet (Save to Files). An SVG pasted into a note app usually shows as text: use the PNG
  there.
- **Front matter** (the `---` block at the top of docs and MDX pages) is shown as a code block.
- **Raw HTML and MDX components** are shown as the text they are, never run. The one exception
  is a `<details>` block with its `<summary>`: it shows as a section you tap to expand, and the
  Markdown inside it renders as usual. Only its `open` attribute is kept, and a `<details>`
  without its `</details>` stays text.
- **Images are never loaded.** An image inside the root shows as a link that opens the file in
  Files; an image on the web shows as a link to its site.

Links:

- A link to another file under the root (`docs/guide.md`, `../README.md`, `/src/main.go`) opens
  it in the same tab; `guide.md#install` opens it at that heading. A leading `/` means the root.
  A file already open in another tab shows that tab.
- Ctrl+click (Cmd+click on a Mac), a middle click, or a long press on a phone opens the link in
  a new tab.
- A link to a folder shows the tree with that folder open.
- `#heading` scrolls to the heading in the same file.
- The back button returns to the file the link was followed from in that tab, where you left
  it, before going back to the tree.
- A link to a missing file says `Not found`. A link that leaves the root, or that uses another
  scheme than `http`/`https` (`javascript:`, `file:`, `data:`), is shown as plain text.
- `http`/`https` links open in a new tab; hovering shows the site they go to.

In **Changes**, a changed Markdown file has the same eye button over its diff: it shows the
current version of the file, rendered with the same rules. A deleted file has no preview. Its
links open in Files.

## CSV and TSV as a Table

A `.csv`, `.tsv` or `.tab` file opens as a table: the header row stays at the top and the row
numbers at the left while the rest scrolls, and a 1 MiB file scrolls as smoothly as a short one.
The eye button in its bar switches between the table and the source; the choice is remembered on
this device, apart from the one for Markdown. Changes shows the diff of a CSV file as text
first; its eye button shows the current version of the file as a table, to read only (Edit opens
it for changes). A deleted file has no table.

- **Delimiter**: a `.tsv` or `.tab` file is read with tabs. For a `.csv` file the delimiter is
  guessed from its first lines (comma, semicolon, tab or pipe); the **Delimiter** menu reads it
  again with another one.
- **Quotes** follow RFC 4180: a value in double quotes can hold the delimiter, a line break and
  `""` for one quote. A value that holds a line break shows `↵` in its cell.
- **Header row** (on at first) takes the first row as the column names. Turned off, the
  columns are `Column 1`, `Column 2`… and the first row is a row like the others.
- **Sorting**: press a column name to sort by it, again to reverse, a third time to go back to
  the file's order. Text sorts without regard to case and runs of digits by their value
  (`item 2` before `item 10`; decimals are compared digit run by digit run, so `1.5` comes after
  `1.25`). Empty cells go last, and the header row is never sorted.
- **Filter rows** keeps the rows where any cell contains what you typed, ignoring case, and
  shows how many are left (`12 / 340 rows`). It searches hidden columns too: while any column is
  hidden, the count says so (`12 / 340 rows · 2 columns hidden`).
- **Column widths**: drag the line at the right edge of a column name, with a mouse or a finger,
  to make that column wider or narrower; a drag never sorts. Double-click or double-tap the line
  to fit the column to its values. From the keyboard, Tab to the line, then Left and Right change
  the width 2 characters at a time, Home and End go to the narrowest and widest, and Enter fits.
  A column is 4 to 120 characters wide.
- The **Columns** button in the bar has **Fit columns**, which fits every column to the rows on
  screen (up to 1000, from the first one in view), **Reset widths**, back to the widths the table
  opened with, **Wrap**, a list of the columns, and **Lines**: 3, 6 or 10 (3 at first). A wrapped
  column shows up to that many lines of each value (a line break still ends with `↵`) and its name
  has a wrap icon; while any column wraps, every row is that many lines tall, and a longer value
  is cut. The whole value is in its cell's sheet, or its field while editing.
- Each column name has a ⋯ button (shown on hover, or always on a touch screen); right-clicking a
  name opens the same menu. **Pin column** keeps that column at the left, next to the row numbers,
  its name too: it stays in its place until the table scrolls sideways to it, then the columns
  before it pass under it. One column is pinned at a time; **Unpin column** in the same menu unpins
  it, and so does **Unpin name** in the **Columns** menu, there while a column is pinned. While the
  row numbers and the pinned column take more than half the table's width (a phone, a very wide
  column), it scrolls with the others, so the table can still be read. **Hide column** in the ⋯ menu
  hides that column, as **Show** below does; a pinned column hidden is unpinned.
- **Show** in the **Columns** menu lists the columns, each ticked while it is shown: untick one to
  hide it from the table and from Records, which also says how many are hidden. **Show all**
  brings them back. The last column shown cannot be hidden, and hiding the column the table is
  sorted by goes back to the file's order. Hidden columns are skipped by the
  arrow keys, Home and End, and Tab in a cell, and **Fit columns** fits only the ones shown.
- **Records** shows one row at a time as `column: value`, with **Previous** and **Next**, for a
  phone where a row is wider than the screen. Press or tap a row number to open that row in
  Records; turned off, Records goes back to the table where you left it.
- Tap a cell (or press Enter on it) to see its whole value, with a button to copy it. A cell
  shows at most 1024 characters; the full value is only in that sheet. With a mouse, a click only
  selects the cell, as in a spreadsheet, and a double-click opens it: in the sheet, or on a file you
  can edit in the cell itself (see below); a value opened from Records still shows in its sheet.
- A row with another number of cells than the header has its number in orange; hovering or a
  screen reader says how many cells it has.
- From the keyboard, the arrow keys, Page Up and Page Down move between cells; Home and End go to
  the first and last column of the row, and Ctrl+Home and Ctrl+End (Cmd on a Mac) to the first
  and last cell of the table, in the order shown.

Sorting, filtering, the delimiter, the header row, column widths, wrapped columns, the pinned
column and hidden columns only change what is shown. Nothing is written to the file, and they are
forgotten when the file is closed. Widths, wrapped columns and their lines, the pinned column and
hidden columns also stay while you show another tab and come back, and go back to the defaults when
the delimiter or the header row changes.

| Shown                                                   | Why                                                                     |
| ------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Unclosed quote on line N: shown as source`             | A quote opened on that line never closes; the file shows as its source |
| `Showing 200 of N columns. See all in Source`           | Only the first 200 columns are shown; the source has them all           |
| `No rows`                                               | The file is empty                                                       |

<Aside type="caution">
  A value is shown as text, never run: a formula such as `=HYPERLINK(...)` shows as typed.
  Characters that could make a value read as something else, such as the right-to-left override
  that makes `0001` read `1000`, control characters and zero-width spaces, show as marks like
  `⟨U+202E⟩`. **Copy** in a cell's sheet copies the value itself, those characters included,
  without the quotes that wrap it in the file.
</Aside>

### Finding in a Table

Ctrl+F (Cmd+F on a Mac) on a table, whether you are only viewing it or editing it, opens a find
box under its bar; what you typed last is selected, ready to type over. Unlike **Filter rows**, it
hides no row: every cell that matches is tinted, the current one outlined, and the box counts them
(`3 of 17`). Typed in the filter, a cell's field or a sheet, Ctrl+F is still the browser's own.

- Enter and Shift+Enter in the box, or F3 and Shift+F3 anywhere in the table, go to the next or
  previous match, round from the last to the first, scrolling it into view. From the box the
  focus stays in it; from a cell the focus goes to the match. F3 with the box closed opens it
  again on the next match. In a cell's field, F3 sets the value first, as leaving the cell does.
- Matches go row by row in the order shown (after sorting and filtering), then along the columns
  shown. The header row and hidden columns are not searched; while any column is hidden, the box
  says so.
- The search ignores case and matches part of a value. **Aa** matches case, the boxed **ab**
  matches only a whole value, and **.\*** reads what you type as a regular expression (JavaScript,
  Unicode); one that does not compile shows `Invalid pattern`. Values are searched whole, past the
  1024 characters a cell shows. Characters that hide or reorder text, typed in the box, show below
  it as `⟨U+XXXX⟩`.
- An edit, a sort, a filter or a hidden column finds again: the current match stays on its cell
  while that still matches, else it moves to the next one.
- Escape or the close button closes the box and puts the focus back on the current match.

A regular expression, and any search of a file over 256 KiB, runs apart from the page, so the
table never freezes; one still running after 10 seconds (30 for the first search, while that
part loads) is stopped and the box says `Search took too long`; one too deep for the browser
says `Search failed`. At most 100,000 matches are counted (`100000+`).

### Selecting, Copying and Pasting

With a mouse and a keyboard, Shift with the arrow keys, Home, End, Page Up or Page Down (and
Ctrl+Home or Ctrl+End) grows a range of cells from the cell in focus; Shift+click or a drag from
one cell to another selects the cells between, and a drag near the top or bottom of the table
scrolls it. An arrow key alone, a click or Escape drops the range. On a phone nothing is
selected.

- Ctrl+C (Cmd+C on a Mac), while only viewing too, copies the range, or the cell in focus, or
  from a row number its row, as a spreadsheet does: tab separated, one line a row, in the order
  shown, hidden columns left out. Values are copied whole, past the 1024 characters a cell
  shows; one that holds a tab, a line break or a quote is put in quotes, so it pastes into a
  single cell. At most 100,000 cells are copied at once.
- Ctrl+V while editing pastes a block copied from a spreadsheet or another table, from the cell in
  focus (or the range's top-left cell) along the rows and columns shown, as one change that one
  Ctrl+Z takes back; a cell given its own value is left as it is. A block wider than the columns
  left is refused. A longer one, while the table is neither sorted nor filtered, asks to add the
  rows it needs at the end; sorted or filtered, it is refused, saying why. Saving changes only the
  cells pasted.
- A range the block fits into a whole number of times, both down and across, gets the block over
  and over, as in a spreadsheet: one copied cell fills every cell of the range, a copied row fills
  every row of a range as wide, and a short line's missing cells are emptied. Any other range, or
  a row number with no range selected, takes the block once, from its top-left cell. The 100,000
  cell limit counts the cells of the range filled.
- Delete or Backspace while editing clears every cell of the range, along the rows and columns
  shown, as one change that one Ctrl+Z takes back. At most 100,000 cells are cleared at once.
- No clipboard permission is asked, so this works over plain HTTP on the LAN too, and on a Mac
  with no text selected. Pasted in a cell's field, the filter or the find box, the text goes into
  that box.

### Editing a Table

**Edit** on a file shown as a table keeps the table and makes each cell editable, with **Cancel**
and **Save** in the bar as for any file. Opened from Changes, or shown as its source, the file is
edited as text instead.

- Tap a cell to change its value in a sheet: the value can hold several lines, and characters
  that hide or reorder text show below it as `⟨U+XXXX⟩`. **Apply** puts it in the table; a cell
  a short row does not have can be set too.
- With a mouse, a double-click on a cell, or F2 or Enter on the cell in focus, edits the value in
  the cell itself, the field growing over the rows below to show up to 20 lines (past them it
  scrolls), at least 12rem wide; a single click only selects the cell, so Ctrl+V on it pastes a
  block (see above), and a tap on a touch screen, a laptop's too, still opens it. A double-click
  while only viewing a file you can edit starts editing first. Enter sets it, Shift+Enter or
  Alt+Enter breaks the line, and Escape drops what you typed: the table stays in editing, **Cancel**
  leaves it. Tab and Shift+Tab set it and go to the next or previous cell, from the end of a row
  onto the next one. Clicking elsewhere, or scrolling the cell out of view, sets it too. The ⤢
  button in the cell takes what you typed to the cell's sheet, for more room and for **Add row
  below** and **Delete row**. A value longer than 1024 characters, or one that holds characters
  which hide or reorder text, opens in the sheet.
- With a keyboard, typing on the cell in focus starts editing it with what you type, which
  replaces its value (Escape keeps the old one); on a file you are only viewing, it starts
  editing first. A value the field cannot take opens in the sheet with what you typed. Delete or
  Backspace clears the cell, and one Ctrl+Z brings the value back. With an input method (IME),
  the first key opens the field: if the first character you composed does not show in it, type
  it again there. On a phone, typing on a cell does nothing.
- **Insert row above** and **Add row below** (in that sheet) and the **Add a row at the end**
  button add an empty row and open its first cell. **Delete row** asks first, and says when the
  row is the file's first one, which is the header when **Header row** is on. To delete the
  header, turn **Header row** off first: the header row is then a row you can open.
- While editing, the ⋯ menu of a column name also has the edits below, and right-clicking a cell,
  or pressing Shift+F10 or the context menu key on a name or a cell, opens the same menu.
  **Insert column left** and **Insert column right** add an empty column: a delimiter
  in each row long enough to reach it, nothing else; a shorter row and a blank line stay as they
  are. With **Header row** on, the new column's name is asked for at once (Escape leaves it
  empty). **Delete column** asks first, saying how many cells with a value go with it; the last
  column cannot go. A row left with one empty cell keeps it as `""`, so it does not become a
  blank line. Opened from a cell, the menu also has **Insert row above** and **Insert row below**.
- **Rename column** in that menu, F2 on a column name, or a double-click on it (the first click
  still sorts) edits the name in place, with **Header row** on; on a touch screen, or for a name
  the field cannot take, it opens in the sheet, which adds or deletes no row around the header.
  Widths, wrapped and hidden columns and the sort follow their columns when one is added or
  deleted, undone, or dropped with **Cancel**; a deleted column brought back by Undo has its
  values, not its width or wrap.
- **Undo** and **Redo**, or Ctrl+Z and Ctrl+Shift+Z (Cmd on a Mac) on the table, walk through
  your changes; Ctrl+S saves. Typed in the sheet, a cell or the filter, Ctrl+Z and Ctrl+Shift+Z
  belong to that box; Ctrl+S in a cell sets it, then saves.
- Saving changes only the characters of the cells you set: a value that needs quotes (it holds
  the delimiter, a quote, a line break, or a space at either end) gets them, a cell that had
  quotes keeps them, and a new row or column uses the file's delimiter and line breaks. Every
  other byte stays as it was.
- The delimiter cannot change while editing. When the one you are viewing with is not the one
  found in the file, Edit asks first: edits written with another delimiter can shift the columns.
- Sorting and filtering still work while editing; they never change the file.

If the file changed on the host since you opened it, Save says so and writes nothing. **Reload
and reapply** reads the file again and applies each of your changes to the row it was made on,
found by that row's values rather than its number, so a row an agent added or removed above it
does not matter. A change whose row is gone, or matches more than one row, is listed with why, and
a cell's value can be copied to set it again by hand; changes after an added or deleted row that
could not be applied are listed too, since they may concern that row. A column added or deleted
is found again by its name in the header row, wherever that column moved, and with **Header row**
off at its place while the file has as many columns as before; when its column is gone, or two
columns have that name, it is listed, and so is every change after it. A pasted block finds each
of its rows the same way and is applied whole or not at all, so one that set a row matching
another (two empty rows, say) is listed; rows it added go at the new end of the file. When the file read again is
no longer a table that can be edited, nothing is applied and Save stays off. Nothing is saved
until you press Save.

## Images

A PNG, JPEG, GIF or WebP file (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) opens as the picture,
fit to the width of the view, over a checkerboard so transparent parts show. Under it are its
size in pixels and its file size. The server checks the file's contents, not only its name: a
file named `.png` that holds something else is not shown.

An SVG file opens as its source first, like any text file. The **Image** button in its bar
switches between the source and the picture; the choice is remembered on this device. In
Changes, the same button switches between the diff and the pictures.

**Full screen.** Tap or click an image (in Files, either side in Changes) or a Mermaid diagram
of a Markdown preview to open it full screen:

- On a phone: pinch to zoom, drag with one finger, double tap to zoom in (and again to fit).
  The page behind does not move.
- On a desktop: the mouse wheel (or a trackpad pinch) zooms around the pointer, dragging moves
  the picture, and the buttons or the keys `+`, `-` and `0` zoom in, zoom out and fit.
- Zoom goes from half the fitted size to 8 times it. A diagram or an SVG is drawn again at the
  new size once you stop, so it stays sharp.
- The back gesture or button, the close button and Escape close it, leaving the file where it
  was.
- A diagram has its Share, Copy image and Download SVG buttons in a bar at the bottom; what
  they did shows there for a few seconds.

In **Changes**, a changed image shows the version before and after, side by side on a desktop
and one above the other on a phone:

| Side                 | Before    | After          |
| -------------------- | --------- | -------------- |
| Not staged (Changes) | the index | the working tree |
| Staged               | `HEAD`    | the index      |

A new image shows only the after side (`Added`), a deleted one only the before side
(`Deleted`). A renamed image reads the before side from its old path, shown next to the label.
For a conflict, only the file as it is now in the working tree is shown. The pictures are read
again when you press Refresh or when the file's status changes, not every 5 seconds.

| Shown                                                          | Why                                                                     |
| -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Larger than 10 MiB`                                            | Images over 10 MiB are not shown                                         |
| `Too many pixels to show (over 40 megapixels)`                  | An image (or a GIF frame) over 40 million pixels, which a phone may not hold |
| `Not previewable (not a PNG, JPEG, GIF, WebP or SVG image)`     | The contents are not one of these types (or an SVG without an `<svg>`)  |
| `Stored in Git LFS: only the pointer is in git`                 | git holds a Git LFS pointer, not the image; termote does not fetch it   |
| `The image could not be decoded`                                | The browser could not read the file (damaged, or a format it lacks)     |
| `Busy, try again`                                               | Several images are being read at once; the **Retry** button reads it again |

A name that usually holds secrets asks first, as for text. An SVG opened by its address never
runs a script: the server sends it with a policy that forbids scripts, and as a download.

## Changes

The list follows `git status` and is read again every 5 seconds while the view is open and the
browser tab is visible. It is grouped:

- **Conflicts**: files with an unresolved merge conflict
- **Staged**: changes added to the index
- **Changes**: changes in the working tree that are not staged
- **Untracked**: new files git does not track yet

Each file shows a letter: `M` modified, `A` added, `D` deleted, `R` renamed (with the old path),
`C` copied, `T` type changed, `U` conflict, `?` untracked. A file with both staged and unstaged
changes is listed in both groups, and each opens the diff of its own side. An untracked file
opens as all added lines.

The diff shows each hunk with the old and new line numbers (one column on a narrow phone
screen), added lines on green and removed lines on red, with `+` and `-` kept so the colour is
never the only sign.

| Shown                            | Why                                                                         |
| -------------------------------- | --------------------------------------------------------------------------- |
| `Not a git repository`            | The pane's directory is not inside a git repository                         |
| `Binary file changed`             | git reports a binary change; there are no lines to show                     |
| `Diff truncated at 1 MiB`         | The diff of this file is longer than 1 MiB; only its start is shown         |
| `Unresolved conflict`             | A conflicted file is shown whole, as it is now in the working tree          |
| `No longer changed`               | git stopped listing this side of the file while it was being read           |
| `git took too long; trying again` | `git status` took over 10 seconds (a very large repository); it backs off   |

Submodules are not listed, and their contents are not compared.

Diffs open as tabs, the same way files do in Files (see
[Open Files as Tabs](#open-files-as-tabs)), with tabs of their own:

- Each side of a file is a tab: the staged and the unstaged diff of one file are two tabs, the
  staged one named `(staged)`. The first tab, **Changes**, shows the list.
- A single click opens the preview tab; a double click (on the list or on the tab) or **Edit**
  keeps it. **Edit** opens the editor in that tab, and switching tabs keeps it with its unsaved
  changes. Back from the diff shows the list; the tab stays open.
- When git no longer lists a side (committed, staged, reverted), its tab closes with
  `No changes left in <file>`. A tab being edited stays open.
- Closing, the limit of 10, the sheet on a phone, a move of the root and a file that may contain
  secrets work as in Files.

When the list has more than 15 entries, a **Filter changes…** box appears above it. It keeps the
files whose path contains what you typed, ignoring case (for a rename, the old path counts too).
Groups with nothing left are hidden, the counts show the filtered numbers, and
`No changes match` shows when nothing is left. Escape clears the box. The filter lives in the
page only: it is cleared when you leave the view or when the root moves.

## Files That May Contain Secrets

Files whose names usually mean secrets are listed with a lock and the word `Sensitive`: for
example `.env`, `.env.*`, `*.env` and `.envrc`, private keys (`*.pem`, `*.key`, `*.jks`,
`id_rsa*`, `id_ed25519*`), `.netrc`, `.npmrc`, `.pgpass`, `.my.cnf`, `.vault-token`,
`.git-credentials`, `credentials*`, `auth.json`, `secrets.*`, `.dev.vars`, Terraform state and
variables (`*.tfstate`, `*.tfvars`) and anything under `.ssh`, `.gnupg`, `.aws`, `.kube`, `.docker`, `.config/gh`
or `.config/gcloud`. A link to such a file counts too, as does a rename from or to one.

Opening one asks `This file may contain secrets. Show its contents?` first, for the file and for
its diff. The answer is not remembered: the next time, it asks again. The server checks this
itself: without the confirmation it sends no contents at all.

<Aside type="caution">
  The lock is a warning based on names, not a guarantee. A secret in a file with an ordinary
  name (`prod-creds.yaml`) is shown without asking. Anyone who can sign in to Termote can read
  every file under the pane's directory.
</Aside>

## Never Shown

Some paths are never served (or saved, created in, deleted, or found by name), even after confirming:

- Termote's own config and state directories (the saved password, logs) and its trash
- `/proc`, `/sys` and `/dev` (process environments and devices)
- the repository's `.git` directory, which is not listed in Files either

Paths are checked on the server against the root: `..`, absolute paths and links that lead
outside the root are refused.

## How git Is Run

Termote runs `git status` and `git diff` itself to fill Changes, and `git cat-file` to read the
before and after versions of an image. A repository's own settings
cannot make it run a program: file system monitors, filter drivers, external diff tools and text
conversion are turned off for these commands, and submodules are skipped. At most two git
commands run at a time, each limited to 10 seconds.
