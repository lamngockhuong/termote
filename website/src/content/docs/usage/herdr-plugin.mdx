When Termote runs the [Herdr backend](/usage/sessions/#herdr-backend), the Termote plugin for
Herdr gives you its link from inside Herdr: it opens Termote on the workspace, tab and pane you
are on (a [deep link](/usage/sessions/#deep-links)), shows that link as a QR code to scan with a
phone, copies it, and starts, stops or restarts the server.

## Requirements

- Herdr 0.7.4 or later.
- Termote 1.5.0 or later (it has `termote url` and `termote panel`; update with
  `termote update`). The plugin runs the `termote` command for
  everything it does, so it needs no other runtime.
- Linux and macOS: Herdr starts plugin commands with its server's `PATH`, which often lacks
  `~/.local/bin`. The plugin's launcher also looks there and in the install
  (`~/.local/share/termote/current/bin`, or under `$XDG_DATA_HOME`), so `termote link` is not
  required, and skips a copy too old for the plugin. When it finds none that works, the panel
  says why and stays open until you press Enter.
- Windows: the installer puts `termote` on the user `PATH`; restart Herdr after installing so it
  sees it.
- The server runs the Herdr backend (`termote start --mux herdr`). With tmux, the IDs in a
  Herdr link mean nothing to Termote, so the link opens the home screen and the plugin says so.

## Install

```bash
herdr plugin install lamngockhuong/termote/herdr-plugin
```

Herdr shows the manifest and the commands it will run before installing. To remove it:
`herdr plugin uninstall lamngockhuong.termote`.

## The Panel

The panel is a popup with the server's status, every address it answers on (Tailscale, LAN,
this machine), and a QR code of the link to the pane that was focused when you opened it:

```bash
herdr plugin action invoke lamngockhuong.termote.panel
```

| Key          | Does                                                                  |
| ------------ | --------------------------------------------------------------------- |
| `o`          | Open the link in this machine's browser                               |
| `c`          | Copy the link                                                         |
| `s`          | Start the server (shown when it is not running)                       |
| `x`          | Stop the server                                                       |
| `r`          | Restart the server                                                    |
| `q`, `Esc`   | Close the panel                                                       |

The link uses the first address another device is likely to reach: the Tailscale name, else the
first LAN address, else `localhost`. The password is never part of it; the device that opens it
still signs in.

## Actions

The same tasks are plugin actions, for a key binding or `herdr plugin action invoke`. Herdr
allows each id once, so on Windows the ids end in `-windows` (`lamngockhuong.termote.panel-windows`,
`lamngockhuong.termote.open-windows`, ...):

| Action                          | Runs                             |
| ------------------------------- | -------------------------------- |
| `lamngockhuong.termote.panel`   | Opens the panel                  |
| `lamngockhuong.termote.open`    | `termote url --herdr --open`     |
| `lamngockhuong.termote.copy`    | `termote url --herdr --copy`     |
| `lamngockhuong.termote.start`   | `termote start`                  |
| `lamngockhuong.termote.stop`    | `termote stop`                   |
| `lamngockhuong.termote.restart` | `termote restart`                |

Herdr only writes an action's output to the plugin log (`herdr plugin log list --plugin
lamngockhuong.termote`), so use the panel when you want to read the result. To open the panel with
a key, add this to Herdr's `config.toml`:

```toml
[[keys.command]]
key = "prefix+o"
type = "plugin_action"
command = "lamngockhuong.termote.panel"
description = "Termote link and QR code"
```

On Windows, bind `lamngockhuong.termote.panel-windows` instead.

<Aside type="note">
  `copy` uses the system's clipboard command (`wl-copy`, `xclip`, `xsel`, `pbcopy`, `clip`). An
  action has no terminal, so when none of them works there (for example `xclip` without a
  display), use `c` in the panel: it falls back to the terminal's clipboard (OSC 52), which also
  works over SSH.
</Aside>

## From a Script

The plugin is a thin layer over two commands you can use yourself:

- `termote status --json` prints the server's state as one JSON object: `running`, `status`,
  `version`, `backend`, `pid`, `port`, `lan`, `auth`, `tailscale`, `urls` (`local`, `lan`, `tailscale`) and
  `supervisor`. It exits with 1 when the server is not running.
- `termote url` prints the link: `--group`, `--tab` and `--pane` select a session (the IDs of
  `/api/mux/snapshot`), `--view` a view, and `--herdr` takes the session from the Herdr plugin
  context. `--open`, `--copy` and `--qr` open it, copy it, or print it as a QR code. Only the
  link goes to stdout.

```bash
termote url --group main --tab 1          # tmux: session "main", window 1
termote url --group w1 --tab w1:t2 --qr   # Herdr: workspace w1, tab w1:t2, with a QR code
```
