The agent overview shows every pane running a coding agent (Claude Code, Codex, any agent your
backend reports), in every session, on one screen. It is for checking on several agents at once:
which one waits on you, which is still working, which has finished.

## Open it

- **Desktop**: the grid button at the top of the sidebar.
- **Phone**: the view menu in the header, then **Agent overview**.
- **Address**: `#/overview` after your Termote address. A reload keeps it, and **Copy link** copies it.

It covers the panes without closing them: leave with its close button, `Esc`, the browser's Back
button, or by picking a session. Back and Forward move between the overview and the pane you came from.

## The cards

One card per agent, sorted by what needs you first: blocked, then working, done and idle. Within one
state, the agent that has been in it longest comes first. Each card shows:

- the agent's state and how long it has been in it. "≥ 5 min ago" means the server found the agent
  already in that state when it started watching (after a restart, for example);
- the session and tab it runs in, and **worktree** for a Herdr worktree;
- its last message;
- the branch and the number of changed files of its directory (not on Windows with psmux);
- how full its context is: a bar, the share of the context window and the tokens, for example
  `72% 144k/200k`, and the model for Claude Code. Bars turn yellow from 70% and red from 90%.

Tap a card to open the agent: its Chat view for Claude Code and Codex, else its terminal. A Chat card
also has a terminal button. The filter above the cards counts agents and is the overview's own: it
does not change the sidebar's.

<Aside>
With tmux and psmux, only the active pane of each window is watched: an agent in another split of the
same window has no card. Herdr and Zellij watch every pane.
</Aside>

## Context and limits

For Claude Code the window is 1M when it was started with `--model <model>[1m]`, 200k for any other
`--model`. Started without `--model` (the model comes from its settings or `/model`), or under Herdr,
the window is assumed to be 200k and the share is marked `~`, until the context grows past 200k. For
Codex the share is the one Codex reports itself ("% context left", turned into the share used).

With a Codex pane signed in to a ChatGPT plan, an **Accounts** strip above the cards shows that
account's limits: a bar for the 5-hour and the weekly window, when each resets, and when Codex last
recorded them. Numbers older than 30 minutes are dimmed, since the account may have been used
elsewhere since. There is no such line for Claude Code: its limits are not written anywhere Termote
reads.

The header also shows a small chip for the pane you have open, such as `ctx 72% · 7d 95%` (the limit
only for Codex). On a phone it shows only the higher of the two. Tap it to open the overview. Turn it
off in **Settings > Sessions > Agent usage in the header**.

## Needs you

When an agent waits on a dialog (a permission, a question), the overview shows it at the top, one at
a time, with the same buttons as the Chat view. The dialog on top stays until you answer it or press
**Skip**: an agent that starts waiting later joins the end, never in front of it. After an answer the
card says **Answered**, and only **Next** shows the next dialog, so a second tap never answers another
agent. **Show again** brings back the dialogs you skipped.

A view-only device sees the dialogs without buttons. An agent whose dialogs Termote cannot read or
answer gets an **Open terminal** button instead. With Zellij, if the answer cannot reach the pane at
that moment, the card says so and you can try again.

## History and activity

**History** at the bottom of a card opens its last hour as a strip, one colour and mark per state
(blocked is striped, idle hollow), with the minutes of each underneath. The part before the first
change the server recorded stays blank: it is unknown, not idle. For Claude Code it also lists the
session's subagents: each one's type, description, state, the last tool it called and how long it ran
or has been running. One started by another is indented under it. "(guessed)" marks a subagent taken as
done because its file has not changed for 10 minutes, when the transcript cannot tell. Closed, the
button still says "2 subagents, 1 running".

**Activity** in the overview's header lists every change of state of every agent since the server
started (the last 500), newest first. Filter it by the state changed to. A row opens that agent's pane,
even after its tmux window moved; a row of a pane that has closed cannot be opened.

## Stuck agents

An agent that says it is working but has written nothing for a while gets an hourglass line: "May be
stuck: no new activity for 14 min". Set how long in **Settings > Sessions > Stuck agent** (3 to 60
minutes, 10 by default). Writes of its running subagents count as activity. It is only a hint on the
card: no notification is sent.

<Aside type="caution">
The times come from the server. They start when the server first sees an agent, and they are recorded
only while a page is open or a device has notifications on.
</Aside>
