## Docker Run

```bash
# Basic (auto-generates credentials, check logs: docker logs termote)
docker run -d --name termote -p 7680:7680 ghcr.io/lamngockhuong/termote:0.1

# With custom credentials
docker run -d --name termote -p 7680:7680 \
  -e TERMOTE_USER=admin -e TERMOTE_PASS=secret \
  ghcr.io/lamngockhuong/termote:0.1

# Without auth (local dev only)
docker run -d --name termote -p 7680:7680 \
  -e NO_AUTH=true \
  ghcr.io/lamngockhuong/termote:0.1

# With persistence
docker run -d --name termote -p 7680:7680 \
  -v termote-data:/home/termote \
  ghcr.io/lamngockhuong/termote:0.1
```

## Options

<Tabs>
  <TabItem label="Unix (macOS/Linux)">
    | Flag              | Description                              |
    | ----------------- | ---------------------------------------- |
    | `--lan`           | Expose to LAN (default: localhost)       |
    | `--no-auth`       | Disable basic auth                       |
    | `--port <port>`   | Custom port (default: 7680)              |
    | `--fresh`         | Force new password prompt (ignore saved) |
    | `--update`        | Auto-update with saved config            |
    | `--version <ver>` | Install specific version                 |
  </TabItem>

  <TabItem label="Windows (PowerShell)">
    | Flag              | Description                              |
    | ----------------- | ---------------------------------------- |
    | `-Lan`            | Expose to LAN (default: localhost)       |
    | `-NoAuth`         | Disable basic auth                       |
    | `-Port <port>`    | Custom port (default: 7680)              |
    | `-Fresh`          | Force new password prompt (ignore saved) |

    Online installer flags: `$env:TERMOTE_UPDATE="true"` for auto-update.
  </TabItem>
</Tabs>

<Aside type="tip">
  Scripts auto-detect `podman` or `docker` - both work identically.
</Aside>

<Aside type="note">
  Use Container mode when you don't need access to host binaries (like `claude`
  or `git`).
</Aside>

## Prevent macOS Sleep

macOS automatically sleeps after inactivity, disconnecting remote terminal sessions — even with containers running. Use `caffeinate` to keep the machine awake:

```bash
# Prevent system sleep (runs until you press Ctrl+C)
caffeinate -s

# Or run in background
caffeinate -s &

# Stop background caffeinate
pkill caffeinate
```

<Aside type="tip">
  Use `caffeinate -s` (system sleep only) instead of `-d` (display sleep) — you
  don't need the display on for remote access.
</Aside>

```bash
podman logs termote
```

### Container won't start

<Tabs>
  <TabItem label="Unix (macOS/Linux)">
    ```bash
    # Check startup errors
    docker logs termote

    # Port already in use?
    lsof -i :7680

    # Use different port
    ./scripts/termote.sh install container --port 7690
    ```
  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    # Check startup errors
    docker logs termote

    # Port already in use?
    netstat -ano | Select-String 7680

    # Use different port
    .\scripts\termote.ps1 install container -Port 7690
    ```
  </TabItem>
</Tabs>

### Debug inside container

```bash
docker exec -it termote /bin/sh
# Inside container:
ps aux                        # Check processes
curl localhost:7681           # Test ttyd
curl localhost:7680/api/tmux/health
```

### Common Issues

| Issue            | Solution                                     |
| ---------------- | -------------------------------------------- |
| Port in use      | `lsof -i :7680` then kill or use `--port`    |
| Container crash  | `docker logs termote` to see error           |
| Auth not working | Restart container, check logs for password   |
| WebSocket error  | Check ttyd running inside container          |
| Stale PWA cache  | Settings → "Clear Cache & Reload" to refresh |

## Updating

### Via CLI (Recommended)

If Termote is already installed, use the built-in update command:

```bash
termote update                    # Update to the latest release (1.x)
termote update --version 0.1.0   # Stay on 0.x (pin a version)
termote update --force            # Force reinstall current version
```

This automatically preserves your config, stops services, downloads the new version, verifies checksums, and re-installs with your saved settings.

### Via One-liner

Re-run the installer - it compares versions and prompts before updating:

<Tabs>
  <TabItem label="Unix (macOS/Linux)">
    ```bash
    # Auto-update with saved config
    curl -fsSL https://raw.githubusercontent.com/lamngockhuong/termote/release/0.x/scripts/get.sh | bash -s -- --update

    # Or without saved config
    curl -fsSL https://raw.githubusercontent.com/lamngockhuong/termote/release/0.x/scripts/get.sh | bash -s -- --container
    ```

    Options: `--update`, `--yes`, `--download-only`, `--fresh`, `--strict`
  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    # Auto-update with saved config
    $env:TERMOTE_UPDATE="true"; irm https://raw.githubusercontent.com/lamngockhuong/termote/release/0.x/scripts/get.ps1 | iex

    # Or without saved config
    $env:TERMOTE_MODE="container"; irm https://raw.githubusercontent.com/lamngockhuong/termote/release/0.x/scripts/get.ps1 | iex
    ```

    Options: `$env:TERMOTE_UPDATE="true"`, `$env:TERMOTE_AUTO_YES="true"`, `$env:TERMOTE_VERSION="0.1.0"`, `$env:TERMOTE_MODE="container"`
  </TabItem>
</Tabs>

## Uninstall

`uninstall` only stops Termote: it leaves the install directory (`~/.termote` by default, or
`TERMOTE_INSTALL_DIR`), its config and logs, and the `termote` command in place. To remove 0.x
completely, for example before installing 1.0:

<Tabs>
  <TabItem label="Unix (macOS/Linux)">
    ```bash
    ~/.termote/scripts/termote.sh uninstall all   # stop native + container, reset Tailscale serve, delete the config
    ~/.termote/scripts/termote.sh unlink          # remove the 'termote' symlink (/usr/local/bin or ~/.local/bin)
    rm -rf ~/.termote                             # scripts, binaries, PWA, logs
    hash -r                                       # zsh: rehash
    ```
  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    & "$HOME\.termote\scripts\termote.ps1" uninstall all   # stop native + container, reset Tailscale serve
    & "$HOME\.termote\scripts\termote.ps1" unlink          # remove termote.cmd/termote.ps1 from ~\.local\bin
    Remove-Item -Recurse -Force "$HOME\.termote"           # scripts, binaries, PWA, logs, config.json
    ```
  </TabItem>
</Tabs>

<Aside type="caution">
  `uninstall all` runs `tailscale serve reset`, which removes **every** `tailscale serve` mapping on the
  machine, not only Termote's (on Unix only when the saved config used Tailscale, through `sudo`). Check
  `tailscale serve status` first if you serve anything else.
</Aside>

If you used container mode, also remove the image built for it: find it with `docker images | grep termote`
(or `podman images`), then `docker rmi <image>`. 1.0 does not read anything 0.x left behind, so nothing else
needs to stay.
