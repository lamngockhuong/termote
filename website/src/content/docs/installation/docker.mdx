`termote container up` runs the server in a container instead of on the host: termote (PWA + terminal stream +
API) and a terminal backend (tmux, or Herdr) in one image, with a workspace directory mounted from the host. Use
it when the terminals do not need your host tools (like `claude` or `git` as installed on the host).

## Prerequisites

- Podman (preferred when both are installed) or Docker, including Docker Desktop or Podman Desktop on macOS and
  Windows.
- The `termote` command, installed as in [Getting Started](/getting-started/). You do not need to run
  `termote start`.

## Quick Start

<Steps>
1. Start the container

   ```bash
   termote container up
   ```

2. Open http://localhost:7680 and log in as `admin` with the password it prints.

3. (Optional) Expose it to the LAN; the option is saved like any other

   ```bash
   termote container up --lan
   ```

</Steps>

## How It Runs

- The image is `ghcr.io/lamngockhuong/termote:<version>`, where `<version>` is the version of your `termote`
  binary, so the container always matches the command that started it. `container up` pulls it, replaces any
  existing `termote` container and waits until the server answers.
- It runs as your user and group, with `--restart unless-stopped`, and mounts the workspace directory
  (default `~/termote-workspace`, created if missing) at `/workspace`. It warns when the workspace contains
  sensitive directories such as `.ssh` or `.aws`.
- The password and settings reach the container through the environment of the `docker`/`podman` process
  (`-e NAME`, no value), so they never appear on a command line or in a file on disk (`docker inspect` still shows
  them, as with any environment variable).
- The container settings are saved apart from the native `termote start` options, but the admin password is
  shared: a new one (`--fresh`) applies to both, and the native server takes it at its next `termote restart`.
- The container's default port is 7680. If the native server already uses that port, `container up` refuses and
  suggests `--port`.
- From a git checkout, or with `--build`, it builds `termote:local` from the Dockerfile instead of pulling.

## Terminal Backend

The image carries both tmux and [Herdr](https://herdr.dev), so there is nothing to install or detect. The first
`container up` without `--mux` asks which one to use; without a terminal to ask in, it uses tmux and prints how
to switch. The choice is saved with the container settings, apart from the native `--mux`:

```bash
termote container up --mux herdr   # Herdr workspaces and agent status badges
termote container up               # keeps the saved backend
termote container up --mux tmux    # back to tmux
```

<Aside type="caution" title="Herdr in the container">
  - Herdr runs inside the container, so it sees only the container's terminals, never the Herdr server or the
  agents running on your host.
  - No Herdr client is attached in the container, so panes keep Herdr's own size; the PWA fits the terminal to
  it instead of resizing the pane.
  - `--mux herdr --no-auth` is refused unless `--allow-herdr-no-auth` is also given, as with `termote start`.
</Aside>

<Aside type="note" title="After a reboot">
  Docker's daemon restarts the container after a reboot. Rootless Podman has no daemon, so the container stays
  stopped; to keep it running across reboots, run it as a
  [Quadlet](https://docs.podman.io/en/latest/markdown/podman-systemd.unit.5.html) systemd unit.
</Aside>

## Options

Like `termote start`, every option is saved, a flag you leave out keeps its saved value, and a boolean is turned
off with `=false`.

| Option                      | Description                                                            |
| --------------------------- | ---------------------------------------------------------------------- |
| `--port <port>`             | Port on the host (default 7680)                                        |
| `--lan[=false]`             | Expose to the LAN (default: this machine only)                         |
| `--tailscale <host[:port]>` | Publish over [Tailscale HTTPS](/installation/tailscale/) (default 443) |
| `--no-tailscale`            | Stop publishing over Tailscale                                         |
| `--no-auth[=false]`         | Disable the login                                                      |
| `--mux <tmux\|herdr>`       | Terminal backend (asked the first time, tmux without a terminal)       |
| `--allow-herdr-no-auth`     | Required together with `--mux herdr --no-auth`                         |
| `--allow-host <name>`       | Allow another `Host` header name (repeatable, no wildcard)             |
| `--remove-host <name>`      | Remove an allowed name (repeatable)                                    |
| `--workspace <dir>`         | Directory mounted at `/workspace` (default `~/termote-workspace`)      |
| `--fresh`                   | Set a new password (shared with the native server)                     |
| `--build`                   | Build the image from a checkout instead of pulling it                  |

<Aside type="note" title="Windows and --lan">
  On Windows the container port is published on localhost only, and `--lan` adds a `netsh` port forwarding rule
  and a firewall rule, which asks for administrator rights. `container down` removes them again.
</Aside>

## Managing the Container

```bash
termote container status    # is it running, and what the server reports
termote container logs      # recent log lines
termote container logs -f   # follow the logs (Ctrl+C to stop)
termote container down      # remove the container (and its Tailscale mapping)
```

`termote stop`, `restart` and `uninstall` only act on the native server; the container has its own commands.

## Updating

`termote update` updates the command, and the image tag follows it. Run `container up` again to move the
container to the image of the new version, with the saved settings:

```bash
termote update
termote container up
```

## Prevent macOS Sleep

macOS automatically sleeps after inactivity, disconnecting remote terminal sessions — even with containers running. Use `caffeinate` to keep the machine awake:

```bash
# Prevent system sleep (runs until you press Ctrl+C)
caffeinate -s

# Or run in background
caffeinate -s &

# Stop background caffeinate
pkill caffeinate
```

<Aside type="tip">
  Use `caffeinate -s` (system sleep only) instead of `-d` (display sleep) — you
  don't need the display on for remote access.
</Aside>

## Troubleshooting

### Debug inside container

```bash
docker exec -it termote /bin/sh
# Inside container:
ps aux                        # Check processes (termote, tmux)
```

Replace `docker` with `podman` if that is your runtime.

### Common Issues

| Issue                        | Solution                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| Neither podman nor docker    | Install one of them, then `termote container up` again                                   |
| Port in use                  | Often the native server: `termote container up --port <port>`, or `termote stop` first   |
| Image cannot be pulled       | A pre-release has no image until it is published; install a stable release              |
| Server does not answer       | `termote container logs` shows why                                                        |
| Gone after a reboot (Podman) | Rootless Podman does not restart it: `termote container up` again, or use a Quadlet unit |
| Host rejected (403)          | Add the name the error suggests: `termote container up --allow-host <name>`              |
| Stale PWA cache              | Settings → "Clear Cache & Reload" to refresh                                             |

### API Test

```bash
curl -u admin:<password> http://localhost:7680/api/mux/health
```

## Uninstall

```bash
termote container down
```

This removes the container; the workspace directory and the saved settings stay. To remove the command too, run
`termote uninstall` (see [Native](/installation/native/#uninstall)).

## Development

`docker-compose.yml` in the repository is for development from a checkout only. Everyone else uses
`termote container up`.
