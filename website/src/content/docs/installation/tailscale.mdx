Automatic HTTPS using `tailscale serve`. No manual certificate management, and Termote never runs `sudo` for it.

## Prerequisites

- [Tailscale](https://tailscale.com) installed and authenticated
- MagicDNS and HTTPS certificates enabled for your tailnet
- **Linux only, once:** let your user change `tailscale serve` without sudo

  ```bash
  sudo tailscale set --operator=$USER
  ```

  If you skip this, `termote start --tailscale` stops before touching the running server and prints this line.

## Setup

<Steps>
1. Start with the Tailscale name of this machine

   <Tabs>
     <TabItem label="Native">

       ```bash
       termote start --tailscale myhost.tailnet-name.ts.net
       ```
     </TabItem>
     <TabItem label="Container">

       ```bash
       termote container up --tailscale myhost.tailnet-name.ts.net
       ```
     </TabItem>
   </Tabs>

2. Open https://myhost.tailnet-name.ts.net from any device on your tailnet

</Steps>

The option is saved, so a later `termote start` (or `termote container up`) keeps publishing it.

## Options

```bash
# Another HTTPS port (default 443)
termote start --tailscale myhost.tailnet-name.ts.net:8443

# Tailscale + LAN
termote start --tailscale myhost.tailnet-name.ts.net --lan

# Stop publishing over Tailscale
termote start --no-tailscale
```

The same `--tailscale` and `--no-tailscale` options work with `termote container up`.

<Aside type="tip">
  Tailscale is the recommended way to expose Termote securely over the internet.
</Aside>

## How It Works

```
Tailnet device → Tailscale (HTTPS) → 127.0.0.1:7680 → termote (terminal stream + API)
```

- **Native:** the service's `termote serve` applies
  `tailscale serve --bg --https=<port> http://127.0.0.1:<port>` every time it starts, at boot, on restart and
  after an update, so the mapping always follows the saved config.
- If that HTTPS port on Tailscale already serves something else, `start` refuses and suggests another port
  (`--tailscale myhost.tailnet-name.ts.net:8443`); the server never replaces a mapping that is not its own.
- **Container:** `container up` applies the same mapping on the host; `tailscaled` keeps it across reboots.
- The Tailscale name is added to the Host allowlist automatically, so requests through `tailscale serve` are not
  rejected by the DNS-rebinding guard.
- `termote stop`, `termote start --no-tailscale`, `termote uninstall` and `termote container down` remove only
  Termote's own mapping (`tailscale serve --https=<port> off`), never your other `tailscale serve` entries.

Tailscale handles:

- TLS certificates (auto-renewed)
- Authentication (Tailscale ACLs)
- NAT traversal

## Stalls on mobile data

Termote works on Wi-Fi, but on mobile data the header stays at **Loading...** with 0 sessions, or the terminal
stays blank, while the Chat view may still load. The PWA shows a toast saying the network seems to drop large
replies.

Some carriers' IPv6 paths carry packets of at most 1280 bytes. Tailscale's tunnel is 1280 bytes inside, and
WireGuard adds 80 bytes on IPv6, so a full-size packet is 1360 bytes on the carrier's network and is dropped
without an error coming back. Small replies (health, a short chat poll) get through; a session list, a terminal
redraw or an image upload never does.

Check it from the server while the phone is on mobile data (`100.x.y.z` is the phone's Tailscale address,
`tailscale status` lists it):

```bash
ping -c 3 -M do -s 1172 100.x.y.z   # 1200-byte packets: replies
ping -c 3 -M do -s 1252 100.x.y.z   # 1280-byte packets: 100% loss on an affected network
```

Fix it by lowering Tailscale's MTU on the server to 1200 (Linux, `tailscaled` as a systemd service):

```bash
echo 'TS_DEBUG_MTU=1200' | sudo tee -a /etc/default/tailscaled
sudo systemctl restart tailscaled
ip link show tailscale0   # mtu 1200
```

`tailscale serve` handles the phone's TCP connection inside `tailscaled`, so a smaller MTU there makes both
directions fit, uploads included; Termote needs no change.

<Aside type="caution">
  With an MTU below 1280, Linux removes the IPv6 address from `tailscale0`: this machine is then reachable over
  its Tailscale IPv4 address and MagicDNS name only, and HTTP/3 (QUIC) does not run over Tailscale. Traffic
  outside Tailscale is not affected. The setting lives in the system config, not in Termote, so set it again
  after moving to another machine or reinstalling Tailscale.
</Aside>
