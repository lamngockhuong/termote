The native server runs on the host, so its terminals see your tools: `claude`, `git`, `gh` and the rest. termote
streams the terminal itself (PTY on Unix, ConPTY on Windows) into xterm.js in the PWA; there is no separate
terminal process to install.

## Prerequisites

termote needs one terminal backend: **tmux** (on Windows, **psmux**) or a running
**[Herdr](https://herdr.dev/#install)** server (see [Herdr Backend](#herdr-backend)); you do not need both.

<Tabs>
  <TabItem label="Linux">

    ```bash
    # tmux
    sudo apt install tmux
    # or Herdr instead: see https://herdr.dev/#install
    ```
  </TabItem>
  <TabItem label="macOS">

    ```bash
    # tmux
    brew install tmux
    # or Herdr instead: see https://herdr.dev/#install
    ```
  </TabItem>
  <TabItem label="Windows">

    ```powershell
    # psmux: tmux-compatible multiplexer for Windows
    winget install psmux
    ```
  </TabItem>
</Tabs>

### tmux Configuration (Recommended)

With the tmux backend, for copy/paste to work with the keyboard toolbar buttons, add this to your `~/.tmux.conf`:

```bash
# Vi mode for copy: Space=start selection, Enter=copy
set-option -g mode-keys vi
# Mouse support (scroll, select) - toggle with Ctrl+b m
set-option -g mouse on
bind m set -g mouse \; display "Mouse #{?mouse,on,off}"
```

Apply the config:

```bash
tmux source-file ~/.tmux.conf
```

This enables: **Copy icon** → navigate → **Space** → select → **Enter** → **Paste icon**

<Aside type="tip" title="Copy to System Clipboard">
  With mouse ON, tmux captures mouse events. To copy to system clipboard:
  - **Hold Shift** while selecting text (bypasses tmux, uses terminal selection)
  - Or press **Ctrl+b m** to toggle mouse off temporarily
</Aside>

## What `termote start` Does

<Steps>
1. **Picks the backend** the first time: Herdr when its server answers on its socket (`$HERDR_SOCKET_PATH`, else
   `herdr.sock` in Herdr's config directory: `$XDG_CONFIG_HOME/herdr`, or `~/.config/herdr`; on Windows
   `%APPDATA%\herdr`, reached as a named pipe), tmux (psmux on Windows) when it is installed. When both are there it asks, or, without a
   terminal to ask in, picks tmux and prints how to switch. When neither is there it stops with install hints.
   The choice is saved and not detected again unless you pass `--mux`.

2. **Creates the admin password** the first time (or with `--fresh`): type one, or press Enter to generate
   one. It is printed once; `termote show-password` shows it again later.

3. **Checks the port and Tailscale first.** If anything fails, a server that is already running is left
   running, so a mistake does not cut the connection you may be using.

4. **Registers `termote serve` with your service manager** and starts it (see the table below), waits until
   the server reports this version, then prints the URLs, the allowed host names and the credentials. It
   always warns when auth is off or LAN access is on.

</Steps>

| OS                                   | Service manager                                                          | Behaviour                                                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Linux                                | systemd user unit `~/.config/systemd/user/termote.service`               | Restarted after a crash; tmux and its shells survive stop, restart and crash. Runs while you are logged in: `loginctl enable-linger $USER` keeps it running after logout and starts it at boot (`start` prints this hint) |
| Linux without user systemd (WSL2)    | Detached process with a PID file                                         | Not restarted after a crash or reboot; `start` says so. Run `termote start` again, or enable systemd in WSL (`[boot]` `systemd=true` in `/etc/wsl.conf`)                  |
| macOS                                | launchd agent `~/Library/LaunchAgents/app.ohnice.termote.plist`          | Restarted after a crash, started at login; tmux survives                                                                                                               |
| Windows                              | Scheduled Task `Termote` at logon, run hidden                            | No administrator rights needed. If policy refuses the task, a hidden launcher in the Startup folder is used instead (no restart after a crash then)                    |

The unit, plist or task never contains the password or any `TERMOTE_*` variable.

<Aside type="note" title="Windows">
  The Windows service setup is new in 1.0. Please report anything that does not work on
  [GitHub](https://github.com/lamngockhuong/termote/issues).
</Aside>

## Start Options

Every option is saved. A flag you leave out keeps its saved value, so `termote start` with no flags starts the
server exactly as last time. A boolean option is turned off with `=false`.

| Option                      | Description                                                            |
| --------------------------- | ---------------------------------------------------------------------- |
| `--port <port>`             | Port (default 7680; Windows 7690)                                      |
| `--lan[=false]`             | Listen on every interface instead of `127.0.0.1` only                  |
| `--tailscale <host[:port]>` | Publish over [Tailscale HTTPS](/installation/tailscale/) (default 443) |
| `--no-tailscale`            | Stop publishing over Tailscale                                         |
| `--no-auth[=false]`         | Disable the login                                                      |
| `--mux <tmux\|herdr>`       | Terminal backend (default: detected the first time)                    |
| `--allow-host <name>`       | Allow another `Host` header name (repeatable, no wildcard)             |
| `--remove-host <name>`      | Remove an allowed name (repeatable)                                    |
| `--allow-herdr-no-auth`     | Required together with `--mux herdr --no-auth`                         |
| `--user <name>`             | Login username (default `admin`; shared with the container)            |
| `--fresh`                   | Set a new password                                                     |

```bash
termote start --lan                  # also reachable from the LAN (saved)
termote start                        # same options as last time
termote start --lan=false            # back to this machine only
termote start --allow-host box.local # accept another host name
termote start --remove-host box.local
termote start --fresh                # new password
termote start --user alice           # log in as alice instead of admin
```

The allowed host names are always loopback, the Tailscale name, the `--allow-host` names, and with `--lan` the
address a request arrived on (so it keeps working when the LAN IP changes). A request for any other name gets a
403 that names the `termote start --allow-host <name>` to run.

<Aside type="caution" title="Give Termote a host name of its own">
  Browsers send a site's cookies to every port of its host name, so another web service on the same name (another
  port on the same server, another app on the same domain) receives Termote's session cookie whenever you open
  it, and with it a signed-in terminal. On a server that runs anything else, reach Termote under a name only it
  answers on: a Tailscale name, or a name of its own such as `termote.example.com`. Log out from the **More** menu
  on a device you no longer use.
</Aside>

## Herdr Backend

Linux, macOS and Windows can drive Herdr workspaces instead of tmux (psmux on Windows). Herdr must already be running on this host
([install Herdr](https://herdr.dev/#install)); Termote only talks to its socket. When Herdr is running at the first `start` it is picked for you; otherwise:

```bash
termote start --mux herdr
```

<Aside type="caution" title="Herdr behavior differs from tmux">
  - Selecting a tab or pane on the PWA does **not** change what is shown on the Herdr desktop
  — it only changes which pane the client streams. There is no "show on desktop" button.
  - Each pane gets an agent-status badge (idle/working/blocked/done) refreshed at most once
  per the configured poll interval; it is not pushed instantly.
  - This is the Herdr on your host. The container runs its own Herdr instead, see
  [Container Installation](/installation/docker/#terminal-backend).
  - `--mux herdr --no-auth` is refused unless `--allow-herdr-no-auth` is also given: Herdr
  exposes every workspace on the host, not just the pane the PWA is showing, so running it
  without a password needs an explicit opt-in.
</Aside>

## Managing the Server

```bash
termote status          # what the running server reports (version, backend, pid)
termote stop            # stop it; it starts again at the next login
termote restart         # stop and start with the saved options
termote logs            # recent lines of every log
termote logs server     # server log only
termote logs follow     # tail live (Ctrl+C to stop)
termote logs clean      # delete the log files
termote show-password   # print the saved username and password
```

The service runs `termote serve`, which reads the saved config. Once a config file exists, `TERMOTE_*`
environment variables are ignored, and `serve` removes them from its environment so no terminal inherits one.

## Updating

```bash
termote update                   # newest stable 1.x release
termote update --version 1.0.1   # a specific version
termote update --version 1.13.0-rc.1  # a pre-release, only when named
termote update --force           # reinstall the current version
```

`update` downloads the release and checks its `.sha256` and, from 1.10.0 on, the release signature: an archive
the Termote release key did not sign is refused even when its checksum matches. It installs it beside the current version, switches to it,
restarts the service and waits until the server reports the new version and keeps answering. If it does not, it
switches back to the previous version and restarts that one. The current and the previous version are kept; your
config and the service registration do not change. It works when typed inside a Termote pane.

`update` refuses to run from a git checkout (use `git pull && make build` there) and for a binary that the
installer did not put in place.

## Uninstall

```bash
termote uninstall
```

This removes the service registration, Termote's Tailscale mapping, the `termote` command and the install root.
Your config (`~/.config/termote`) and logs (`~/.local/state/termote`) stay, and `uninstall` prints both paths so
you can delete them by hand. On Windows, `%APPDATA%\termote` and `%LOCALAPPDATA%\termote\state` stay.

## Prevent macOS Sleep

macOS automatically sleeps after inactivity, disconnecting remote terminal sessions. Use `caffeinate` to keep the machine awake while Termote is running:

```bash
# Prevent system sleep (runs until you press Ctrl+C)
caffeinate -s

# Or run in background
caffeinate -s &

# Stop background caffeinate
pkill caffeinate
```

<Aside type="tip">
  Use `caffeinate -s` (system sleep only) instead of `-d` (display sleep) — you
  don't need the display on for remote access.
</Aside>

## Troubleshooting

### Quick Diagnostics

```bash
termote status          # is it running, which version and backend
termote logs server     # last server log lines
```

### Common Issues

| Issue                                    | Solution                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| `termote: command not found`             | Open a new terminal, or add `~/.local/bin` to your PATH as the installer printed             |
| No terminal backend found                | Install tmux (Windows: `winget install psmux`) or start Herdr, then `termote start`          |
| Port in use                              | `start` names the port; stop the other program or choose `termote start --port <port>`      |
| Host rejected (403)                      | Run the `termote start --allow-host <name>` the error names                                  |
| Saved password cannot be decrypted       | The `secret` file was removed or replaced: `termote start --fresh`                           |
| Stops when you log out (Linux)           | `loginctl enable-linger $USER`                                                               |
| Not running after a reboot (WSL2)        | No user systemd there: `termote start` again, or enable systemd in WSL                       |
| Stale PWA cache                          | More (⋯) menu → "Clear cache & reload" to refresh                                                |
