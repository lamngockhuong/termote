Orchestrator là một phiên Claude Code hoặc Codex mà bạn trò chuyện để điều phối các agent lập trình
đang chạy trong những pane Termote khác. Bạn hỏi nó từng agent đang làm gì, nhờ nó giao việc cho
một agent, báo khi agent xong, agent đã trả lời gì và đã sửa những gì, cho xem hộp thoại mà một agent
đang chờ, dừng một agent, hay mở agent mới, mỗi agent trong một git worktree của riêng nó. Nó làm mọi việc bằng các lệnh `termote agents`, nên dùng lại đúng
những gì Termote vẫn làm cho bạn trong [Chat view](/vi/usage/agent-chat/) và
[Tổng quan](/vi/usage/overview/), với cả bốn backend tmux, Herdr, Zellij và herdr-core.

Tính năng này không bắt buộc: chưa cài skill thì không có gì thay đổi, và Termote không bao giờ tự
ghi vào thư mục của Claude Code hay Codex.

## Yêu cầu

- Termote chạy native (`termote start`). Chế độ container không có local socket, nên
  `termote agents` báo là không hỗ trợ.
- Claude Code hoặc Codex cho chính phiên orchestrator. Các agent được điều phối có thể là Claude
  Code, Codex hoặc OpenCode, như trong Chat view.

## Cài skill

Chọn một trong hai cách, đừng dùng cả hai: dùng cả hai thì agent thấy skill hai lần.

**Từ chính Termote.** Skill được nhúng sẵn trong `termote`, nên luôn khớp phiên bản với nó:

```bash
termote skills install                 # cho Claude Code và Codex, agent nào có trên máy
termote skills install --agent claude  # hoặc chỉ một trong hai
termote skills status                  # đã cài chưa, có khớp termote này không?
termote skills uninstall
```

Lệnh này ghi vào `~/.claude/skills/termote-orchestrator/` (hoặc dưới `CLAUDE_CONFIG_DIR`) và
`~/.codex/skills/termote-orchestrator/` (hoặc dưới `CODEX_HOME`), và chỉ cho agent đã có thư mục
trên máy. Thư mục cùng tên do bạn tự tạo thì được giữ nguyên. Sau `termote update`, Termote báo khi
skill đã cài thuộc phiên bản khác; chạy lại `termote skills install` để cập nhật. `termote skills
status` còn so file đã cài với bản đi kèm chương trình `termote`, nên skill còn sót lại từ một bản build cũ hơn
của cùng phiên bản cũng được báo là cần cập nhật; `--json` có thêm mã SHA-256 của skill đi kèm
termote này (`sha256`) và của từng bản đã cài.

**Dưới dạng plugin**, từ marketplace nhỏ `termote-plugins` (không tải repo Termote về):

```text
/plugin marketplace add lamngockhuong/termote-plugins
/plugin install termote@termote
```

```bash
codex plugin marketplace add lamngockhuong/termote-plugins
codex plugin add termote@termote
```

Khối đầu dành cho Claude Code, khối sau dành cho Codex.

## Dựng orchestrator

Mở một workspace riêng cho nó, chẳng hạn tên `orchestrator` (một session tmux, một workspace
Herdr), chạy Claude Code hoặc Codex trong đó, rồi hỏi, ví dụ:

- "Các agent của tôi đang làm gì?"
- "Nhờ agent ở pane api chạy test, rồi cho tôi biết cái gì lỗi."
- "Mở một agent Claude Code trong workspace web để viết các test còn thiếu."
- "Mở ba agent trong ba worktree, mỗi agent lo một file test đang lỗi. Báo tôi khi từng agent xong và nó đã sửa gì."

Thư mục của nó là thư mục nào cũng được: skill đến từ Termote hoặc từ plugin, không từ một repo.

## Các lệnh nó chạy

Skill chỉ chạy các lệnh dưới đây. Bạn cũng có thể tự chạy chúng:

```bash
termote agents list [--json]                 # mọi agent: pane id, workspace, tên, trạng thái, thư mục
termote agents read <pane> [--all] [--json]  # lượt cuối: yêu cầu của bạn và mọi thứ sau đó
termote agents send <pane> 'Run the tests'   # một tin; agent đang bận thì tin được xếp hàng
termote agents wait <pane>@<seq>...          # tới khi một pane kết thúc lượt hoặc cần câu trả lời
termote agents answer <pane>                 # xem hộp thoại agent đang chờ
termote agents answer <pane> 1               # hoặc: cancel | next | --text 'câu trả lời'
termote agents diff <pane> [--stat]          # commit của branch kể từ base, rồi phần chưa commit
termote agents stop <pane> --cursor <cursor> # dừng lượt đang chạy, như Esc (cursor lấy từ read --json)
termote agents start --workspace <id> --kind claude --name tests 'Write the tests'
termote agents start --workspace <id> --kind claude --worktree fix-login 'Fix the login test'
termote agents jobs [--mine] [--all] [--json] # sổ việc: pane, trạng thái, lượt chưa đọc, branch của từng việc
termote agents job show <id>                 # prompt, ghi chú, ủy quyền và lịch sử của việc
termote agents job set <id> --state review --note 'What was done'
termote agents wait --job <id>...            # tới khi agent của một việc cần orchestrator
termote agents answer <pane> --delegated     # chọn Yes một lần, theo ủy quyền bạn đã cho trên PWA
```

`<pane>` là pane id mà `list` hiện (`%3`, `w1:p2`), hoặc một tên chỉ một pane có: tên riêng của
pane, nếu không có thì tên tab (`api`), hoặc `workspace/tên` (`web/api`). Tên mà hai pane cùng có
thì bị từ chối, kèm id của cả hai.

`wait` nhận một hoặc nhiều pane và trả về ngay khi một pane kết thúc lượt (mã 0), hiện hộp thoại (3)
hoặc không còn agent (5); mọi pane đã kết thúc đều được in, và mã nặng nhất thắng. Mã 4 nghĩa là hết
`--timeout` (mặc định 30 phút), 6 là không pane nào đang làm và cũng không pane nào vừa xong (không
còn gì để chờ), 7 là lịch sử trên server đã bị xóa (hãy `read` từng pane).

Agent có thể kết thúc lượt bằng một câu hỏi viết ngay trong câu trả lời thay vì trong hộp thoại
("Có cần thêm test không?"). Lượt đó vẫn tính là đã kết thúc (mã 0), nhưng `wait` ghi rằng pane
`ends with a question`, và `read` cũng đánh dấu như vậy (trường `endsWithQuestion` trong
`read --json`), để orchestrator hỏi lại bạn rồi gửi câu trả lời của bạn, thay vì báo việc đã xong.
Termote chỉ xét dòng cuối của câu trả lời có kết thúc bằng dấu hỏi hay không.

Agent Claude Code đã viết xong câu trả lời và chỉ còn chờ việc chạy nền do nó mở (một subagent chạy
nền) cũng được báo một lần, và vẫn nằm trong dòng `next:` để lần `wait` sau báo khi phần chạy nền đó
xong; `list` ghi trạng thái của nó là `background`. Agent đã kết thúc lượt nhưng một shell nó chạy
vẫn còn chạy nền (`done` kèm `background: "1 shell"`) vẫn được chờ tiếp: shell chạy xong thì agent
bắt đầu lượt mới, và `wait` báo khi lượt đó kết thúc thay vì báo không còn gì để chờ.

Mỗi pane được chờ từ mốc riêng của nó, lấy từ nhật ký hoạt động của server: `send` và `start` in ra
pane kèm mốc (`termote agents wait %3@41`), còn `wait` in một dòng `next:` gồm từng pane chưa được
báo cùng mốc của pane đó (`next: termote agents wait %3@41 %5@48`), hoặc báo rằng không còn pane nào. Pane đang chờ hộp thoại vẫn nằm trong dòng đó, nên lần chờ sau khi
trả lời vẫn theo dõi nó.
Muốn chờ nhiều agent, hãy gom `<pane>@<seq>` mới nhất của từng agent. Nhờ vậy, lượt nào kết thúc
trong lúc orchestrator đang đọc pane khác vẫn được báo, kể cả khi lượt đó kết thúc trước mốc in ra
cho một pane khác, còn lượt đã báo rồi thì không báo lại. `--after <seq>` là mốc cho mọi pane được
nêu mà không kèm mốc riêng; `list --json` có mốc mới nhất (`latest`) cho lần chờ đầu tiên, và nêu
pane mà chính lệnh đang chạy trong đó (`self`) khi biến môi trường của tmux, Herdr hoặc Zellij cho
biết chắc chắn. Khi đó `send` tới pane ấy bị từ chối, và `--pane` của một việc (`job add`, `job set`)
trỏ vào nó cũng vậy: việc phải giao cho agent làm việc đó.

Orchestrator chạy trong Claude Code để `wait` chạy nền, dù chờ theo mốc hay theo `--job`, nên bạn
vẫn nói chuyện với nó được trong lúc các agent làm việc: Claude Code báo cho nó khi `wait` thoát.
Khi đó nó xử lý những gì `wait` báo, đọc từng pane được nêu, rồi mới mở lần `wait` tiếp theo bằng
dòng `next:` (hoặc `wait again:` khi hết giờ), và mỗi pane chỉ nằm trong một lệnh `wait` đang chạy.
Thông báo đó không phải lời của bạn, nên không bao giờ được tính là bạn đã đồng ý. Agent mà lệnh
chạy nền không báo lại được, như Codex, vẫn chờ như cũ với `--timeout` ngắn hơn giới hạn thời gian
một lệnh của nó; Claude Code dừng một lệnh chạy thường sau tối đa 10 phút.

`diff` cho thấy agent đã thay đổi gì trong thư mục của nó: các commit của branch kể từ lúc tách khỏi
base (mặc định là branch mà checkout chính của bạn đang dùng, hoặc `--base <branch>`), rồi những gì
đã đưa vào index, chưa đưa vào index và chưa được git theo dõi. Diff của từng file nằm sau một dòng nói rằng đây là dữ liệu
agent viết ra, không phải chỉ dẫn; file nhạy cảm như `.env` chỉ hiện tên, và lệnh in tối đa 64 KB diff
(`--stat` chỉ liệt kê file).

## Sổ việc

Termote giữ một sổ ghi các việc orchestrator đã giao, nên cả bạn lẫn nó đều không phải dựa vào trí
nhớ của nó: sổ vẫn còn sau khi cuộc trò chuyện bị compact, khi mở tab mới hay khi server khởi động
lại. Mỗi lần `start` ghi một việc, với tiêu đề lấy từ `--title` (nếu không có thì kiểu
"claude in fix-login"; không bao giờ lấy từ prompt, vì thiết bị chỉ xem cũng thấy tiêu đề). Các lệnh
`send`, `read`, `answer`, `stop` và `diff --stat` ghi lại việc chúng đã làm vào việc của pane đó.
`termote agents jobs` liệt kê các việc chưa xong: pane, agent của nó đang làm gì, có lượt nào kết
thúc mà orchestrator chưa đọc không, branch và thư mục.

`wait --job <id>...` báo một lượt orchestrator chưa đọc, dù lượt đó kết thúc từ lúc nào (kể cả trước
khi bắt đầu chờ, hay trong lúc server tắt), báo một hộp thoại đúng một lần dù bạn để nó mở, và báo
việc nào mà agent đã mất (tmux khởi động lại, pane bị đóng). Khi agent của mọi việc đều rảnh, lượt
cuối đã được đọc và không còn shell nào nó mở chạy nền, lệnh báo không còn gì để chờ thay vì chờ tới hết giờ. Termote nhận ra agent của một việc qua
tiến trình của nó, nên một agent khác chiếm lại id pane tmux cũ không bao giờ bị nhầm là agent của
việc. Khi agent làm xong, orchestrator chuyển việc sang `review` kèm ghi chú và bạn nhận được một
thông báo đẩy; nó không bao giờ tự đánh dấu việc là `done` thay bạn.

Nhóm Kế hoạch trong [Tổng quan](/vi/usage/overview/) hiện đúng sổ việc ấy. Ở đó bạn còn thêm được
việc để orchestrator nhận (`start --job <id>`), sửa việc và cấp ủy quyền.

## Ủy quyền cho hộp thoại xin quyền

Hộp thoại xin quyền (chạy lệnh, sửa file) là việc của bạn. Để một việc dài vẫn chạy tiếp khi bạn
vắng mặt, bạn có thể cấp cho agent của một việc một ủy quyền trên PWA, khi đăng nhập bằng mật khẩu
hoặc bằng thiết bị đã ghép: chạy các lệnh bắt đầu bằng một tiền tố do bạn gõ (`pnpm test`), hoặc
sửa file trong worktree của việc khi agent đang làm trong đó, tối đa một ngày. Chỉ bạn mới cấp được ủy quyền: orchestrator,
dòng lệnh, một Termote khác và server không bật đăng nhập đều không cấp được.

Khi đó orchestrator thử `answer <pane> --delegated` trước. Chính Termote kiểm tra hộp thoại và chỉ
chọn "Yes" cho đúng lần này khi mọi điều sau đều đúng: hộp thoại trên màn hình và lời gọi công cụ
duy nhất đang chờ trong transcript của agent cùng nêu một lệnh hoặc một file; không subagent nào
đang chạy; lệnh không chứa thứ gì để shell nối lệnh, mở rộng hay chuyển hướng, và không bắt đầu
bằng một shell hay trình thông dịch; file nằm trong worktree, không đi qua liên kết nào, và không
phải file cấu hình agent, file chạy như hook hay file chứa bí mật (`.claude/`, `.git`, `CLAUDE.md`,
`package.json`, các file khóa phụ thuộc, `.env`...). Mọi trường hợp khác đều bị từ chối và quay về
bạn như trước. Mỗi câu trả lời hiện trên thẻ của việc và trong nhật ký kiểm toán của server.

<Aside type="caution">
  Ủy quyền chạy `pnpm test` sẽ chạy mọi lệnh `package.json` khai báo cho `test`, và agent được
  sửa file trong worktree có thể đổi phần khai báo đó. Chỉ cấp ủy quyền cho lệnh ngắn, quen thuộc,
  trên những việc bạn đang theo dõi.
</Aside>

Từ dòng lệnh, lựa chọn khiến hộp thoại không hỏi lại nữa (`don't ask again`, `always allow`,
chuyển sang `auto mode`) luôn bị từ chối: chỉ bạn mới chọn được, trên PWA hoặc trong terminal. Mọi câu trả lời
cho hộp thoại xin quyền đến từ dòng lệnh đều được ghi vào nhật ký kiểm toán.

## Dừng

`stop` dừng lượt mà agent đang làm, như khi bấm Esc trong terminal của nó. Lệnh cần `cursor` lấy từ
`read --json`, nên không bao giờ dừng nhầm một cuộc trò chuyện khác mà pane đã chuyển sang; agent không
làm gì, hoặc đang chờ hộp thoại, sẽ không bị dừng. Agent Claude Code mà màn hình không cho thấy lượt
nào đang chạy cũng không bị dừng, chẳng hạn khi nó đã viết xong câu trả lời và chỉ còn chờ một
subagent chạy nền: Esc không dừng được phần chạy nền ấy, nên `stop` báo lại điều này
(`agent_no_turn`), và nút Dừng cũng không hiện cho agent đó. Sau khi gửi Esc, `stop` theo dõi agent
vài giây và thoát với mã 8 nếu nó vẫn đang làm. Bạn cũng dừng được agent từ
[Chat view](/vi/usage/agent-chat/) hoặc từ thẻ của nó trong [Tổng quan](/vi/usage/overview/).

## Mở agent

Khi không có `--worktree`, `start` mở một tab mới trong workspace (`--name` đặt tên tab) rồi chạy
agent ở đó, prompt là tin nhắn đầu tiên của nó.
`list` hiện thư mục của từng workspace, hoặc `-` khi các pane của nó nằm ở những thư mục khác nhau. Khi tab mới sẽ
mở ở một thư mục khác thư mục đó (tab tmux mở ở thư mục lúc tạo session), `start` đóng tab và không
chạy gì; lệnh in ra thư mục mà agent được mở.

Với `--worktree <branch mới>`, `start` tạo một git worktree của repo trong workspace trên một branch
mới (từ `--base`, nếu không có thì từ commit hiện tại), rồi chạy agent trong pane đầu tiên của một
workspace mới dành riêng cho nó, nên các agent làm song song không bao giờ dùng chung một checkout.
Workspace bạn nêu chỉ cho biết repo nào: agent không chạy ở đó, và `--name` đặt tên cho workspace
mới. Với Herdr, worktree nằm dưới `~/.herdr/worktrees/<repo>/`, không nằm cạnh repo. Worktree mới
chưa có `node_modules`, nên git hook (`lefthook`, `husky`) bị bỏ qua cho tới khi cài phụ thuộc trong
đó; khi repo có file khóa phụ thuộc như `pnpm-lock.yaml`, `start` nhắc bạn kèm lệnh cần chạy. Chạy lại đúng lệnh đó sau một lần thất
bại thì lệnh làm tiếp trong worktree đã tạo, cùng với việc của worktree đó: nếu agent của worktree
vẫn còn chạy ở đó và đang rảnh, nó nhận prompt; nếu agent đang làm hoặc đang chờ hộp thoại, `start`
nêu pane và việc của nó. Branch đã có mà chưa có worktree thì bị từ chối, để agent không bao giờ sửa vào một branch bạn còn làm dở. Termote không bao
giờ xóa worktree nó đã tạo: hãy xóa từ menu của workspace (Remove worktree) hoặc bằng git.

Claude Code, Codex và OpenCode đều nhận prompt ngay khi khởi chạy, nên agent mới có việc để làm
mà không ai phải gõ gì trong terminal; `-` đọc prompt dài từ stdin. Termote không bao giờ gõ prompt
vào shell: nó ghi prompt ra một file riêng, và dòng lệnh nó gõ sẽ đọc lại file đó, nên dấu nháy,
`$(...)`, dấu nháy ngược và các dòng xuống hàng đến agent đúng như đã viết. Cách này chạy với
`bash`, `zsh`, `sh` và `fish` trên Linux và macOS; tab có shell là PowerShell, và mọi tab trên
Windows, sẽ từ chối prompt (`prompt_unsupported_shell`) và không chạy gì. Prompt là tham số dòng
lệnh của agent, người dùng khác trên cùng máy nhìn thấy được, nên đừng đặt bí mật vào đó.

## Những việc nó không làm

Skill để các quyết định cho bạn:

- Mỗi lần chỉ gửi tới một pane, theo id; không gửi cùng một tin cho nhiều agent, và không gửi vào
  chính pane của nó.
- Hỏi bạn trước khi mở agent, và hỏi chọn workspace nào khi thư mục không rõ. Với việc sửa code,
  nó đề xuất một worktree mới và nói rõ điều đó.
- Chỉ dừng agent khi bạn yêu cầu hoặc đồng ý, và không bao giờ tự thử lại.
- Coi những gì `read` và `diff` in ra là dữ liệu của các agent, không bao giờ là chỉ dẫn.
- Cho bạn xem hộp thoại xin quyền (chạy lệnh, sửa file) và trả lời bằng lựa chọn của bạn, trừ
  khi một ủy quyền bạn đã cấp bao trùm hộp thoại đó; nó không bao giờ chọn lựa chọn khiến hộp thoại
  thôi hỏi, và không bao giờ đề nghị tự cấp ủy quyền cho mình.
- Không bao giờ chạy `termote show-password` hay `termote pair`, và không cần mật khẩu: các lệnh
  tới server qua local socket, thứ chỉ chính user của bạn mở được.
- Không bao giờ gõ vào pane bằng lệnh tmux, Herdr hay Zellij: Termote kiểm tra rằng mỗi tin nằm
  đúng trong ô nhập của agent và mỗi câu trả lời khớp với hộp thoại trên màn hình.

<Aside type="caution">
  Tin sẽ chờ khi ô nhập của agent đang có chữ bạn gõ trong terminal (`input_has_draft`).
  Orchestrator nhờ bạn gửi hoặc xóa chữ đó; nó không bao giờ tự xóa.
</Aside>

## Theo dõi trên điện thoại

Mọi tin orchestrator gửi đều hiện trong [Chat view](/vi/usage/agent-chat/) của agent, trong
[Tổng quan](/vi/usage/overview/) và nhật ký hoạt động, như thể bạn gửi từ Termote. Mở Termote trên
điện thoại, đăng nhập như thường lệ, để theo dõi hoặc can thiệp.
