Muốn biết agent đã sửa gì, thường bạn phải gõ `ls`, `cat`, `git diff` trên bàn phím điện thoại rồi
đọc kết quả trong terminal. Termote có hai view để xem nhanh:

- **Files**: thư mục của pane dạng cây, mở từng thư mục một. File văn bản mở ra có số dòng và tô
  màu cú pháp, file CSV hoặc TSV mở ra thành bảng, file ảnh mở ra thành hình.
- **Changes**: khi thư mục nằm trong một repo git, danh sách file git báo đã đổi, kèm diff của
  từng file (với ảnh thì là bản trước và bản sau khi đổi).

Trong Files, bạn tìm được file theo tên (xem [Tìm file](#tìm-file)). Ở cả hai view đều sửa và lưu
được file văn bản (xem [Sửa file](#sửa-file)); riêng trong Files thì tạo được file mới (xem
[Tạo file mới](#tạo-file-mới)), xoá được file hoặc thư mục rỗng (xem [Xoá file](#xoá-file)), và
đổi tên hay chuyển được file (xem [Đổi tên hoặc chuyển file](#đổi-tên-hoặc-chuyển-file)). Ngoài
ra không đổi được gì khác: không đổi tên thư mục, không đưa thay đổi vào index, không bỏ thay đổi
và không commit.

## Mở ở đâu

- **Desktop**: nút **Files** và **Changes** trên header mở một panel bên phải terminal. Terminal
  vẫn ở trên màn hình và vẫn dùng được. Mỗi lúc chỉ có một panel; bấm lại nút của nó để đóng.
  - Kéo mép trái của panel để nới rộng hay thu hẹp nó (luôn chừa chỗ cho terminal); nhấp đúp vào
    mép để về độ rộng mặc định. Dùng bàn phím thì đặt focus vào mép rồi bấm mũi tên trái/phải,
    Home và End. Thiết bị này nhớ độ rộng đã chọn. Terminal chỉ đổi kích thước một lần, lúc thả
    chuột.
  - Nút **Maximize panel** ở đầu panel cho panel tạm che terminal hoặc view Chat; bấm lại nút đó
    hoặc Escape để trả về như cũ. Terminal bên dưới giữ nguyên kích thước, nên các thiết bị khác
    đang xem cùng cửa sổ tmux không thấy gì thay đổi.
- **Điện thoại**: Files và Changes là các view trong nút view trên header, cùng với Terminal (và
  Chat, khi pane chạy Claude Code). Nút này hiện icon của view đang mở; chạm vào để chọn view
  khác. Mỗi view chiếm cả màn hình.

Khi cửa sổ to lên hoặc nhỏ đi qua ranh giới giữa hai bố cục, view đang mở đi theo: từ view trên
điện thoại sang panel trên desktop, và ngược lại.

## Thư mục nào được hiện

Gốc là **thư mục làm việc của pane đang xem**. Khi thư mục đó nằm trong một repo git, gốc là thư
mục trên cùng của repo, nên Files và Changes bao cả repo. Gốc hiện ở đầu cả hai view, thư mục nhà
viết tắt là `~`.

Thư mục này là của chương trình đang chạy trong pane, nên nó đổi theo lệnh `cd` trong shell. Một
lệnh chỉ ghé qua thư mục khác trong chốc lát thì không làm gốc đổi. Khi gốc thật sự đổi lúc view
đang mở, view tải lại từ gốc mới và báo `The pane's directory changed`.

Các bộ quản lý phiên hỗ trợ:

- **tmux** trên Linux và macOS, cài native hay trong container đều được
- **Herdr** trên mọi hệ điều hành. Herdr phải báo được thư mục của pane (`cwd`); bản Herdr cũ không
  báo thì view hiện `Not supported by this backend`.
- **psmux** trên Windows chưa hỗ trợ: psmux không báo thư mục của pane, nên hai view này không có.

## Files

- Thư mục xếp trước, rồi tới file, không phân biệt hoa thường. Chạm vào thư mục để mở hoặc đóng.
- Mỗi thư mục hiện tối đa 5000 mục. Thư mục dài hơn sẽ ghi là chỉ hiện 5000 mục đầu.
- Thiết bị, socket và link trỏ ra ngoài gốc hiện mờ và không mở được.
- File mở ra thay chỗ cây thư mục, trong một tab (xem
  [Mở nhiều file theo tab](#mở-nhiều-file-theo-tab)), kèm đường dẫn, kích thước, nút chép đường
  dẫn và nút xuống dòng cho dòng dài (trên điện thoại bật sẵn). Dòng dài cuộn ngang trong khung code, không bao giờ
  làm cả trang cuộn ngang.
- Tô màu áp dụng cho các ngôn ngữ và tên file thường gặp (TypeScript, Go, Python, shell,
  Dockerfile, Makefile, YAML, JSON, Markdown và nhiều loại khác). Phần này chỉ tải về lần đầu có
  file cần đến, nên máy nào chưa từng mở Files thì không tải.

| Hiện                                                          | Vì sao                                                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Chữ có màu                                                    | File văn bản tối đa 256 KiB, tối đa 5000 dòng, không dòng nào quá 2000 ký tự                     |
| Chữ thường, không màu                                         | File văn bản lớn hơn (tới 1 MiB), ngôn ngữ chưa hỗ trợ, hoặc tô màu mất quá 3 giây              |
| `Not previewable (binary, special file or larger than 1 MiB)`  | File nhị phân không phải ảnh, file lớn hơn 1 MiB, hoặc thứ không phải file thường                |
| `This file can't be shown`                                     | Đường dẫn Termote không bao giờ trả về (xem bên dưới)                                            |

## Mở nhiều file theo tab

Mở thêm file thì các file đang mở vẫn còn: mỗi file một tab, quay lại tab nào thì file đó vẫn ở
đúng chỗ bạn đang đọc, phần sửa dở chưa lưu cũng còn nguyên.

- **Bấm một lần là mở ở tab xem trước**, tên tab in nghiêng: file kế tiếp mở cùng cách sẽ thế chỗ
  nó. File được giữ ở tab riêng khi bạn bấm đúp vào nó (trên cây hoặc trên tab), bắt đầu sửa, vừa
  tạo nó, hoặc bấm **Keep open** (hình ghim trên thanh của file).
- File đã mở rồi thì app chuyển sang tab của nó, không bao giờ mở thêm tab thứ hai.
- Tab đầu tiên, **Files**, hiện cây thư mục; các file vẫn mở phía sau. Bấm Back khi không còn link
  nào để quay lại cũng về cây thư mục.
- **Đóng tab**: bấm nút ×, bấm chuột giữa, hoặc nhấn Delete khi tab đang được chọn. Tab còn thay
  đổi chưa lưu (có chấm sau tên) thì app hỏi `Discard changes?` trước.
- **Tối đa 10 tab.** Mở thêm thì tab lâu không dùng nhất sẽ đóng, trừ tab đang xem và tab còn thay
  đổi chưa lưu. Nếu mọi tab khác đều còn thay đổi chưa lưu thì app để mở quá 10 tab.
- **Trên điện thoại** không có thanh tab. Nút ghi số file đang mở (`Open files (N)`), nằm trên thanh
  của file và trên cây thư mục, mở ra danh sách các file: chạm một file để xem, giữ nó lại, hoặc
  đóng nó.
- Xoá file trong Termote thì tab của file đó đóng theo; đổi tên file trong Termote thì tab vẫn giữ,
  mang tên mới. File bị thứ khác xoá hay đổi tên thì tab vẫn ở lại, hiện `File not found` kèm nút
  **Close tab**.
- Pane chuyển sang thư mục khác thì các tab mở ở thư mục cũ đóng lại. Tab nào còn thay đổi chưa
  lưu thì app hỏi trước: **Discard and close** bỏ các thay đổi, **Keep** giữ tab lại để bạn chép văn
  bản ra (không lưu được nữa).
- File có thể chứa bí mật thì mỗi tab mới đều hỏi lại. Tab nào bạn đã chọn hiện thì vẫn hiện cho tới
  khi đóng tab.
- Tab chỉ nằm trong bộ nhớ của trang: tải lại app là không còn tab nào.

## Tìm file

Ô **Find a file…** ở đầu Files (trên điện thoại, nằm ngay trên bàn phím) tìm theo tên các file dưới
gốc. Kết quả thay chỗ cây thư mục sau một nhịp ngừng gõ ngắn; mỗi dòng hiện đường dẫn của file.

- Chạm vào một kết quả, hoặc nhấn Enter khi đang chọn nó, để mở file; cây thư mục mở sẵn tới file
  đó, và nút Back đưa bạn về danh sách kết quả. Phím mũi tên chuyển giữa ô nhập và các kết quả,
  Escape xoá nội dung ô.
- File mà git bỏ qua (ignored) chỉ được tìm khi bật **Include ignored** (công tắc cạnh ô nhập, chỉ
  hiện trong repo git). Kết quả loại này hiện mờ, kèm nhãn `ignored`. Thiết bị này nhớ lựa chọn của
  bạn.
- File có tên thường dùng để chứa bí mật có ổ khoá, giống trong cây thư mục. Termote chỉ tìm theo
  tên, không bao giờ tìm trong nội dung.
- Chỉ hiện 200 kết quả đầu (`More than 200 matches — type more to narrow`). Trong repo hoặc thư
  mục rất lớn, việc tìm có thể dừng sớm, và danh sách ghi `Search stopped early in a large tree`.
- Danh sách file được giữ 30 giây; lưu, tạo hoặc xoá một file thì danh sách bị bỏ đi. Nút
  **Refresh** đọc lại nó.
- Ngoài repo git, Termote duyệt thư mục (sâu tối đa 32 cấp, trong 5 giây) và không đi vào thư mục
  là link.

Các thư mục không bao giờ được tìm khi xét file bị git bỏ qua đặt ở mục Files của Settings, ô
`Excluded folders` (xem [Cài đặt](/vi/usage/settings/#thư-mục-loại-trừ)). File mà git theo dõi thì
luôn tìm được, kể cả nằm dưới một trong các thư mục đó.

Những đường dẫn Termote không bao giờ trả về (xem [Không bao giờ hiện](#không-bao-giờ-hiện)) cũng
không bao giờ xuất hiện trong kết quả.

## Sửa file

Nút bút chì (**Edit**) trên thanh của file văn bản biến nội dung file thành một ô nhập văn bản
thường, thay các nút khác bằng **Cancel** và **Save**. Nút này dành cho sửa nhỏ, chẳng hạn đổi
`status: review` thành `status: approved` trong front matter của một bản ghi, khỏi phải nhờ agent
hay gõ `sed`.

- File Markdown được sửa ở văn bản gốc, kể cả khi đang xem trước. File CSV hay TSV đang xem dạng
  bảng thì sửa ngay trong bảng (xem [Sửa trong bảng](#sửa-trong-bảng)); đang xem văn bản gốc,
  hoặc mở từ Changes, thì sửa ở văn bản gốc.
- Ctrl+S (Cmd+S trên macOS) để lưu. Bấm Cancel hoặc Back khi còn thay đổi chưa lưu thì app hỏi
  `Discard changes?` trước.
- Xuống dòng giữ nguyên như file đang dùng: file xuống dòng kiểu Windows (`\r\n`) vẫn giữ kiểu đó.
- Đổi view, chuyển tab, hay đóng rồi mở lại panel, văn bản đang sửa vẫn còn. Mỗi file giữ phần sửa
  dở của riêng nó, nên sửa được nhiều file cùng lúc; file sửa từ Changes dùng chung văn bản với
  chính file đó trong Files. Văn bản chỉ nằm trong bộ nhớ của trang, không bao giờ vào bộ nhớ của trình duyệt, nên đóng hoặc tải lại app là mất (điện thoại có
  thể tự đóng app để chạy nền).
- Trong **Changes**, diff của file mà working tree vẫn còn ở dạng văn bản cũng có nút Edit này
  (ở phía đã đưa vào index thì nút là **Edit working copy**: thứ được lưu là file trong working tree). Lưu xong
  thì diff phần chưa đưa vào index hiện ra, đã đọc lại; nếu lúc đó file đã khớp index thì danh sách hiện
  lại, kèm `No changes left in <file>`.

Khi lưu không thành công, văn bản của bạn vẫn còn trong ô:

| Hiện ra                                               | Nên làm gì                                                                                          |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `The file changed on the host since you opened it`    | Có thứ gì đó (thường là agent) vừa ghi vào file. **Reload** đọc lại file và bỏ văn bản của bạn; **Copy my text** chép văn bản đó ra trước. Lưu không bao giờ ghi đè thay đổi kia. |
| `This pane's folder changed`                           | Pane đã chuyển sang thư mục khác. Chép văn bản của bạn ra, rồi bấm Cancel để xem file ở thư mục mới. |
| `Not sure the file was saved. Saving again is safe.`   | Mất kết nối, hoặc server không trả lời trong 30 giây. Cứ lưu lại: cùng một nội dung thì không tính là xung đột. |
| `The server can't write this file`                     | File chỉ đọc, thuộc người dùng khác, hoặc thư mục chứa nó không ghi được                                    |
| `The file system there is read-only`                   | File nằm trên ổ đĩa hay mount chỉ đọc, ví dụ volume container gắn ở chế độ chỉ đọc                          |
| `The host's disk or quota is full`                     | Ổ đĩa của máy chủ, hoặc hạn mức đĩa của bạn, đã hết chỗ                                                     |

Có những file không có nút Edit, vì server sẽ từ chối khi lưu: liên kết mềm (hay file nằm dưới một
thư mục là liên kết mềm), file có nhiều liên kết cứng, file trộn nhiều kiểu xuống dòng hoặc có ký tự NUL, file
lớn hơn 1 MiB, ảnh, và file trong thư mục dữ liệu hay thư mục upload của chính Termote. File có
thể chứa bí mật thì sửa được sau khi đã bấm hiện nội dung.

<Aside type="caution">
  Lưu là thay file bằng một file mới trong cùng thư mục. Nếu agent ghi đúng file đó vào khoảnh khắc
  giữa lần kiểm tra cuối và lúc thay, thay đổi của agent sẽ mất. File mới giữ quyền truy cập của
  file cũ, nhưng không giữ thuộc tính mở rộng hay ACL.
</Aside>

Phiên chỉ xem (khi đã có quyền này) không có nút Edit. Chừng nào server chưa kiểm quyền, nút này
chỉ được ẩn trong app.

## Tạo file mới

Ở đầu Files có nút **New file** (hình trang giấy kèm dấu cộng). Bấm vào, app hỏi đường dẫn tính từ
thư mục của pane, chẳng hạn `docs/notes/today.md`, và điền sẵn thư mục bạn bấm gần nhất trên cây.
**Create** tạo một file rỗng, tạo luôn các thư mục còn thiếu trên đường dẫn, rồi mở file trong ô
nhập văn bản, ở một tab riêng, để bạn gõ nội dung và bấm **Save**. Nút chỉ hiện khi đang xem cây,
không hiện lúc đang xem một file.

- File hay thư mục đã có thì không bao giờ bị thay: ô báo
  `A file or directory of that name already exists`, kèm nút **Open it** để mở chính nó.
- Tên thường chứa bí mật (ví dụ `.env.local`) thì app hỏi
  `This name usually holds secrets. Create it anyway?` một lần; tạo xong, file mở ra luôn mà không
  hỏi lại có hiện nội dung không.
- Mất kết nối trước khi server trả lời thì ô báo
  `The file may have been created. Refresh to check.`, bấm **Refresh** để đọc lại cây.
- Đóng ô trong lúc **Create** đang chạy không dừng được nó: file vẫn được tạo và hiện trên cây,
  nhưng không mở ra.
- Thư mục đã tạo cho đường dẫn vẫn giữ nguyên khi một bước sau đó lỗi, giống `mkdir -p`. File mới
  để trống cũng vẫn còn đó.

| Hiện ra                                        | Lý do                                                                                               |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `Part of this path is a file, not a directory` | Trên đường dẫn có một chỗ là file chứ không phải thư mục                                            |
| `Part of this path is a symbolic link`         | Trên đường dẫn có một thư mục là liên kết mềm: không bao giờ tạo gì xuyên qua liên kết mềm          |
| `Files can't be created there`                 | Đường dẫn Termote không bao giờ trả về (xem [Không bao giờ hiện](#không-bao-giờ-hiện)), hoặc thư mục dữ liệu hay thư mục upload của chính Termote |
| `The server can't create a file there`         | Thư mục đó không ghi được                                                                           |
| `The file system there is read-only`           | Thư mục nằm trên ổ đĩa hay mount chỉ đọc, ví dụ volume container gắn ở chế độ chỉ đọc               |
| `The host's disk or quota is full`             | Ổ đĩa của máy chủ, hoặc hạn mức đĩa của bạn, đã hết chỗ                                             |
| `This name can't be used`                      | Có phần rỗng (`a//b`, dấu `/` ở cuối), có phần kết thúc bằng dấu chấm hay khoảng trắng, có ký tự điều khiển như dấu xuống dòng, sâu quá 32 cấp hoặc dài quá 1024 byte, hoặc trên Windows có một trong các ký tự `<>:"\|?*` |

<Aside type="caution">
  File mới có thể là file mà công cụ khác tự đọc hay tự chạy, như `.claude/settings.local.json`,
  `.vscode/tasks.json` hoặc một file trong `.github/workflows`. Ai đăng nhập được Termote thì vốn đã
  chạy được lệnh trong terminal, nên tính năng này không cho thêm quyền gì, nhưng hãy xem kỹ thứ mình
  tạo ở những chỗ đó.
</Aside>

Phiên chỉ xem (khi đã có quyền này) cũng không có nút New file; chừng nào server chưa kiểm quyền,
nút chỉ được ẩn trong app.

## Xoá file

Trong Files, xoá được một file hoặc một thư mục **rỗng**, theo ba cách: **Delete** trong menu **⋯**
của một dòng ở cây thư mục (dùng chuột thì nút hiện khi rê chuột hoặc khi có focus; trên màn hình
cảm ứng thì luôn hiện), phím Delete khi dòng đang có focus, hoặc nút **Delete** trên đầu file đang
mở (không hiện khi đang sửa file). Hộp thoại hiện đầy đủ đường dẫn và hỏi trước; **Cancel** đang
có focus, nên nhấn Enter không xoá.

- File bị xoá không mất hẳn: nó được chuyển vào thùng rác của Termote trên máy chủ. Một toast ghi
  `Deleted <name>` kèm nút **Undo** trong 10 giây; Undo đặt file về chỗ cũ (và không bao giờ ghi
  đè thứ gì đang có ở đó). Thư mục rỗng đã xoá thì Undo tạo lại.
- Thùng rác giữ một file 7 ngày, tổng cộng tối đa 1 GiB (file cũ nhất bị xoá trước), và không bao
  giờ xoá file mới hơn một giờ. Ứng dụng không có màn hình xem thùng rác: khi toast đã mất, muốn
  lấy file lại thì vào thư mục thùng rác trên máy chủ (`~/.cache/termote/trash` trên Linux).
- Thư mục không rỗng không xoá được, thư mục gốc cũng vậy.
- Khi xoá, server kiểm tra file vẫn đúng là file bạn đã thấy. Nếu trong lúc đó có thứ gì (thường
  là agent) đã sửa nó thì không xoá gì cả.
- Nếu file nằm trên hệ thống file khác với thùng rác (`/mnt/c` của WSL, một ổ đĩa gắn ngoài,
  `/workspace` của container), không thể chuyển nó vào thùng rác. Hộp thoại khi đó hỏi lần thứ
  hai, `Delete permanently? This cannot be undone.`, và chỉ sau đó mới xoá, không có Undo. Trong
  container, mọi lần xoá dưới `/workspace` đều là xoá vĩnh viễn theo cách này.
- File có tên thường dùng để chứa bí mật được ghi `This is a sensitive file` trong hộp thoại.

| Hiện                                                          | Vì sao                                                           |
| ------------------------------------------------------------- | ---------------------------------------------------------------- |
| `The folder is not empty`                                      | Chỉ xoá được thư mục rỗng                                        |
| `The file changed since it was read`                           | File đã đổi sau khi hộp thoại đọc nó                             |
| `Part of this path is a symbolic link`                         | Không xoá gì qua link, và bản thân link cũng không bị xoá        |
| `This file has several hard links; delete it from a terminal`  | Một tên khác vẫn giữ file lại                                    |
| `The server can't delete this`                                 | File thuộc về người dùng khác                                    |
| `The file system there is read-only`                           | File nằm trên đĩa hoặc mount chỉ đọc                             |
| `Too large to delete here; use the terminal`                   | File lớn hơn 512 MiB                                             |
| `Deleting is not available on this server`                     | Server không có thùng rác dùng được                              |

Phiên chỉ xem (khi vai trò đó có) không có nút Delete; cho tới khi server áp dụng vai trò, nút chỉ
bị ẩn trong ứng dụng.

<Aside type="note">
  `termote uninstall` giữ lại thùng rác và in ra đường dẫn của nó; `termote uninstall --purge`
  xoá cả thùng rác. Xem [Gỡ cài đặt](/vi/installation/native/#gỡ-cài-đặt).
</Aside>

## Đổi tên hoặc chuyển file

Trong Files, đổi tên một file bằng **Rename** trong menu **⋯** của dòng file đó ở cây thư mục,
hoặc bằng nút **Rename** trên đầu file đang mở (nút này không hiện khi đang sửa; file còn thay đổi
chưa lưu thì đổi tên từ dòng của nó trên cây). Trên điện thoại, đặt ngón tay giữ yên trên một dòng
cũng mở menu đó. Hộp thoại hiện đường dẫn tính từ thư mục của pane, phần tên (không kèm đuôi) được
chọn sẵn.

- Sửa phần thư mục trong đường dẫn là chuyển file sang chỗ khác. Thư mục chưa có sẽ được tạo.
- Không bao giờ ghi đè: nếu đã có file hay thư mục mang tên mới, hộp thoại báo và cho nút
  **Open it**.
- Tab đang mở, các thay đổi chưa lưu và trình sửa trong Changes của file đều đi theo đường dẫn mới,
  ở mọi pane đang xem cùng thư mục. Lưu sau đó là ghi vào đường dẫn mới.
- Một toast ghi `Renamed <old> to <new>` (hoặc `Moved <name> to <folder>`) kèm nút **Undo** để đổi
  lại tên cũ. Thư mục đã tạo cho lần chuyển vẫn còn. Nếu server không nhận tên cũ làm tên file mới
  (tên kết thúc bằng dấu chấm hay khoảng trắng) thì không có Undo.
- Sau đó Changes hiện một file bị xoá và một file chưa được git theo dõi, giống như sau `mv`, cho
  tới khi bạn đưa chúng vào index; Termote không chạy `git mv`.
- Chỉ đổi tên được file, không đổi tên thư mục hay link.
- Tên cũ hoặc tên mới là tên thường dùng để chứa bí mật thì app hỏi thêm một lần trước khi đổi.

| Hiện                                                     | Vì sao                                                                      |
| -------------------------------------------------------- | --------------------------------------------------------------------------- |
| `A file or directory of that name already exists`        | Đường dẫn mới đã có thứ khác; không có gì bị ghi đè                         |
| `This file no longer exists`                             | Có thứ đã xoá hoặc chuyển file sau khi cây thư mục được đọc                 |
| `<path> has unsaved changes. Save or discard them first` | File ở đường dẫn mới đang được sửa                                          |
| `The file changed while it was being renamed`            | Có thứ đã thay file trong lúc đổi tên; không có gì bị chuyển                |
| `Can't move a file to another file system`               | Thư mục mới nằm trên đĩa hoặc mount khác; file không bao giờ bị chép        |
| `The file is open in another program on the host`        | Windows: một chương trình khác đang giữ file mở                             |
| `Part of this path is a symbolic link`                   | Không đổi tên gì qua link                                                   |
| `The server can't rename this file`                      | File hoặc thư mục của nó thuộc người dùng khác, hoặc thư mục không ghi được |
| `The file system there is read-only`                     | File nằm trên đĩa hoặc mount chỉ đọc                                        |

Phiên chỉ xem không có nút Rename.

## Tải file về máy

Có thể lưu một bản sao của file về thiết bị đang dùng: **Download** trong menu **⋯** của dòng file
đó ở cây thư mục (trên điện thoại, đặt ngón tay giữ yên trên dòng để mở menu), hoặc nút
**Download** trên đầu file đang mở (trên điện thoại nằm trong menu của phần đầu). Trình duyệt lưu
file như mọi lần tải khác, dưới tên của file; không có gì được mở hay hiện ra, dù file chứa gì.

- Tải được mọi file thường, kể cả file Termote không xem trước được (nhị phân, lớn hơn 1 MiB), tối
  đa **100 MiB**.
- File có tên thường dùng để chứa bí mật thì app hỏi thêm một lần; file đang mở mà bạn đã chọn
  hiện thì tải ngay.
- Chỉ tải được file, không tải thư mục hay link, và không tải qua một thư mục là link.
- Trong app iOS đã thêm vào Màn hình chính, file mở trong bảng chia sẻ: chọn **Lưu vào Tệp**
  (Save to Files). Đóng bảng thì không lưu gì.
- Mỗi lần tải được ghi vào log của server thành một dòng `audit: download` (đường dẫn trong thư
  mục của pane, kích thước và ai tải).

| Hiện                                                   | Vì sao                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------- |
| `<name> is larger than 100 MiB, too large to download` | File vượt giới hạn                                                  |
| `Too many files at once; try again`                    | Đang đọc các lần tải hoặc ảnh khác; thử lại sau chốc lát            |
| `<name> is gone`                                       | Có thứ đã xoá hoặc chuyển file sau khi cây thư mục được đọc         |
| `<name> is not a regular file; not downloaded`         | FIFO, socket hoặc thiết bị                                          |
| `A link on that path; not downloaded`                  | File hoặc một thư mục trên đường dẫn là symbolic link               |
| `<name> can't be downloaded from here`                 | Thư mục của chính Termote, dữ liệu cài đặt, `.git` và kho ảnh tải lên |
| `<name> changed; try again`                            | Có thứ đã thay file trong lúc kiểm tra                              |

Phiên chỉ xem không có nút Download.

## Xem trước Markdown

File Markdown (`.md`, `.markdown`, `.mdx`) mở ra ở dạng đã hiển thị: tiêu đề, danh sách, bảng
(trên điện thoại cuộn ngang được), danh sách việc cần làm, chú thích cuối trang và code. Nút hình
con mắt trên thanh của file chuyển qua lại giữa bản xem trước và mã nguồn; máy này sẽ nhớ lựa
chọn đó. File Markdown lớn hơn 256 KiB mở ở dạng mã nguồn, kèm dòng báo file quá lớn để xem trước.

- **Khối code** được tô màu theo ngôn ngữ ghi sau dấu mở khối (` ```ts `, ` ```bash `,
  ` ```go `...), có nút chép cả khối. Khối viết bằng ngôn ngữ chưa hỗ trợ hiện dạng chữ thường.
  Nút xuống dòng cũng áp dụng cho khối code.
- **Sơ đồ Mermaid** (` ```mermaid `) được vẽ thành ảnh khi bạn cuộn tới: lưu đồ, sơ đồ tuần
  tự, sơ đồ lớp, sơ đồ trạng thái, Gantt và các loại khác. Nút code trên thanh của khối chuyển qua lại giữa sơ đồ
  và mã nguồn; nút chép luôn chép mã nguồn. Sơ đồ rộng thì cuộn ngang. Sơ đồ chỉ là một bức
  ảnh: không bấm được vào node hay link bên trong, và luôn theo giao diện sáng hoặc tối của
  Termote, dù dòng `%%{init}%%` hay khối `---` ở đầu sơ đồ đòi gì. App hiện mã nguồn kèm lý do
  thay cho sơ đồ khi sơ đồ lớn hơn 50 KB, có ảnh hoặc biểu tượng (`@{ img: ... }`, thứ sẽ tải
  một URL), không phải Mermaid hợp lệ, vẽ lâu quá 10 giây, hoặc không tải được bộ vẽ sơ đồ.
  Bộ vẽ chỉ được tải về lần đầu có sơ đồ cần hiện, không tải sẵn khi cài app: nếu đang offline
  mà chưa tải lần nào, sơ đồ hiện dạng mã nguồn kèm dòng `Could not load the diagram renderer`.
  Sơ đồ rất lớn có thể làm trang đứng vài giây trong lúc vẽ.
- **Khối `---` ở đầu file** (thường gặp ở trang tài liệu và trang MDX) hiện thành một khối code.
- **HTML thô và component MDX** hiện nguyên văn bản, không bao giờ được chạy. Ngoại lệ duy nhất
  là khối `<details>` cùng `<summary>` của nó: khối hiện thành một mục chạm vào để mở ra, phần
  Markdown bên trong vẫn hiển thị như thường. Trong các thuộc tính của thẻ, chỉ `open` được giữ;
  `<details>` không có `</details>` đi kèm vẫn hiện dạng văn bản.
- **Ảnh không bao giờ được tải.** Ảnh nằm trong thư mục gốc hiện thành link mở file đó trong
  Files; ảnh trên web hiện thành link tới trang chứa nó.

Link:

- Link tới file khác trong thư mục gốc (`docs/guide.md`, `../README.md`, `/src/main.go`) mở file
  đó ngay trong tab đang xem; `guide.md#install` mở file và nhảy tới tiêu đề đó. Dấu `/` ở đầu
  nghĩa là thư mục gốc. File đã mở ở tab khác thì app chuyển sang tab đó.
- Giữ Ctrl (Cmd trên macOS) rồi bấm, bấm chuột giữa, hoặc nhấn giữ trên điện thoại thì link mở ở
  tab mới.
- Link tới thư mục hiện cây thư mục với thư mục đó đang mở.
- `#tieu-de` cuộn tới tiêu đề trong cùng file.
- Nút quay lại đưa bạn về file chứa link vừa bấm trong tab đó, đúng chỗ đang đọc dở, rồi mới về cây
  thư mục.
- Link tới file không tồn tại báo `Not found`. Link ra ngoài thư mục gốc, hoặc dùng giao thức
  khác `http`/`https` (`javascript:`, `file:`, `data:`), chỉ hiện dạng chữ.
- Link `http`/`https` mở trong tab mới; rê chuột lên sẽ thấy trang mà link dẫn tới.

Trong **Changes**, file Markdown có thay đổi cũng có nút con mắt phía trên diff: bấm vào sẽ thấy
phiên bản hiện tại của file, hiển thị theo cùng các quy tắc trên. File đã bị xoá thì không có bản
xem trước. Link trong đó mở ở Files.

## CSV và TSV dạng bảng

File `.csv`, `.tsv` hay `.tab` mở ra thành bảng: khi cuộn, dòng tiêu đề vẫn nằm trên cùng và cột
số dòng vẫn nằm bên trái; file 1 MiB cuộn mượt như file ngắn. Nút hình con mắt trên thanh của file
chuyển qua lại giữa bảng và văn bản gốc; máy này nhớ lựa chọn đó, tách riêng với lựa chọn của
Markdown. Trong Changes, diff của file CSV hiện dạng văn bản trước; nút con mắt phía trên diff cho
xem phiên bản hiện tại của file dưới dạng bảng, chỉ để đọc (muốn sửa thì bấm Edit). File đã bị xoá
thì không có bảng.

- **Dấu phân cách**: file `.tsv` hay `.tab` luôn đọc theo dấu tab. Với file `.csv`, dấu phân cách
  được đoán từ vài dòng đầu (dấu phẩy, chấm phẩy, tab hoặc gạch đứng); menu **Delimiter** đọc lại
  file theo dấu khác.
- **Dấu ngoặc kép** theo RFC 4180: giá trị nằm trong ngoặc kép có thể chứa dấu phân cách, xuống
  dòng, và `""` để ghi một dấu ngoặc kép. Ô có giá trị xuống dòng hiện `↵` ở chỗ xuống dòng.
- **Header row** (bật sẵn) lấy dòng đầu làm tên cột. Tắt đi thì cột tên là `Column 1`,
  `Column 2`…, còn dòng đầu thành một dòng như mọi dòng khác.
- **Sắp xếp**: bấm tên cột để xếp theo cột đó, bấm lần nữa để đảo chiều, lần thứ ba để về thứ tự
  trong file. Chữ so không phân biệt hoa thường, còn các cụm chữ số so theo giá trị (`item 2` đứng
  trước `item 10`; số thập phân được so từng cụm chữ số, nên `1.5` đứng sau `1.25`). Ô rỗng luôn
  nằm cuối, và dòng tiêu đề không bao giờ bị xếp lẫn.
- **Filter rows** chỉ giữ những dòng có ô chứa chuỗi bạn gõ, không phân biệt hoa thường, và cho
  biết còn lại bao nhiêu dòng (`12 / 340 rows`). Bộ lọc tìm cả trong các cột đang ẩn: khi có cột
  bị ẩn, số đếm ghi rõ điều đó (`12 / 340 rows · 2 columns hidden`).
- **Độ rộng cột**: kéo vạch ở mép phải tên cột, bằng chuột hay ngón tay, để cột đó rộng ra hay
  hẹp lại; kéo không bao giờ sắp xếp bảng. Nhấp đúp hoặc chạm hai lần vào vạch thì cột vừa với các
  giá trị của nó. Với bàn phím, nhấn Tab tới vạch, rồi phím mũi tên trái và phải đổi độ rộng mỗi
  lần 2 ký tự, Home và End đưa cột về hẹp nhất và rộng nhất, Enter cho cột vừa nội dung. Mỗi cột
  rộng từ 4 tới 120 ký tự.
- Nút **Columns** trên thanh có bốn phần. **Fit columns** cho mọi cột vừa với các dòng đang hiện
  (tối đa 1000 dòng, tính từ dòng đầu tiên trên màn hình). **Reset widths** trả mọi cột về độ rộng
  lúc bảng mới mở. **Wrap** liệt kê các cột, còn **Lines** chọn 3, 6 hay 10 dòng (mặc định 3): cột
  được bật Wrap hiện tối đa ngần ấy dòng của mỗi giá trị (chỗ xuống dòng vẫn có `↵`) và tên cột có
  biểu tượng xuống dòng; chỉ cần một cột được bật là mọi dòng cao bằng ngần ấy dòng chữ, giá trị
  dài hơn bị cắt bớt. Giá trị đầy đủ nằm trong bảng nhỏ của ô đó, hoặc trong ô sửa khi đang sửa.
- Mỗi tên cột có nút ⋯ (hiện khi rê chuột, trên màn hình cảm ứng thì luôn hiện); nhấp phải vào
  tên cột cũng mở đúng menu ấy. **Pin column** ghim cột đó, cả tên cột, ở bên trái cạnh số dòng:
  cột vẫn đứng đúng chỗ của nó cho tới khi bảng cuộn ngang tới, rồi dừng lại ở đó, các cột phía
  trước trượt xuống dưới nó. Mỗi lần chỉ ghim được một cột; **Unpin column** trong cùng menu bỏ
  ghim. **Pin first column** trong menu **Columns** ghim cột đầu tiên còn hiện; khi đã có cột được
  ghim, mục này đổi thành **Pinned: tên cột** và bấm vào thì bỏ ghim. Khi số dòng và cột được ghim
  chiếm quá nửa chiều rộng bảng (trên điện thoại, hoặc cột rất rộng), cột đó cuộn theo các cột
  khác để vẫn đọc được bảng. **Hide column** trong menu ⋯ ẩn cột đó, giống **Show** bên dưới; cột
  đang ghim mà bị ẩn thì cũng thôi được ghim.
- **Show** trong menu **Columns** liệt kê các cột, cột nào đang hiện thì có dấu chọn: bỏ dấu chọn
  để ẩn cột đó khỏi bảng và khỏi Records, nơi cũng ghi có bao nhiêu cột đang ẩn. **Show all** hiện
  lại tất cả. Không ẩn được cột cuối cùng còn hiện; ẩn cột đang dùng để sắp xếp thì bảng trở về thứ
  tự trong file. Phím mũi tên, Home, End và Tab trong ô sửa đều
  bỏ qua cột ẩn, và **Fit columns** chỉ chỉnh các cột đang hiện.
- **Records** hiện từng dòng một dưới dạng `cột: giá trị`, có nút trước và sau, dành cho điện
  thoại khi một dòng rộng hơn màn hình. Bấm hoặc chạm số dòng để mở đúng dòng đó trong Records;
  tắt Records thì bảng vẫn ở đúng chỗ bạn đã rời đi.
- Chạm vào một ô (hoặc nhấn Enter trên ô đó) để xem đủ giá trị, kèm nút chép. Mỗi ô hiện tối đa
  1024 ký tự; giá trị đầy đủ chỉ có trong bảng hiện ra khi chạm. Dùng chuột thì khác: nhấp một lần
  chỉ chọn ô, như trong bảng tính, còn nhấp đúp mới mở ô: mở trong bảng nhỏ, hoặc với file sửa được
  thì sửa ngay trong ô (xem mục dưới); giá trị mở từ Records vẫn hiện trong bảng nhỏ.
- Dòng có số ô khác với dòng tiêu đề thì số dòng chuyển màu cam; rê chuột lên số dòng, hoặc trình
  đọc màn hình, sẽ cho biết dòng đó có bao nhiêu ô.
- Trên bàn phím, các phím mũi tên, Page Up và Page Down đi giữa các ô; Home và End tới cột đầu và
  cột cuối của dòng, còn Ctrl+Home và Ctrl+End (Cmd trên macOS) tới ô đầu và ô cuối của bảng, theo
  thứ tự đang hiện.

Sắp xếp, lọc, đổi dấu phân cách, bật tắt dòng tiêu đề, độ rộng cột, các cột bật Wrap, cột ghim và
cột ẩn chỉ đổi cách hiển thị. Không có gì được ghi vào file, và các lựa chọn này mất khi đóng file.
Riêng độ rộng, Wrap, số dòng Lines, cột ghim và cột ẩn vẫn còn khi bạn sang tab khác rồi quay lại,
và về mặc định khi đổi dấu phân cách hay bật tắt dòng tiêu đề.

| Thông báo                                               | Lý do                                                                   |
| ------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Unclosed quote on line N: shown as source`             | Dấu ngoặc kép mở ở dòng đó không bao giờ đóng; file hiện ở dạng văn bản gốc |
| `Showing 200 of N columns. See all in Source`           | Chỉ 200 cột đầu được hiện; văn bản gốc có đủ                             |
| `No rows`                                               | File rỗng                                                               |

<Aside type="caution">
  Giá trị chỉ được hiện dạng chữ, không bao giờ được chạy: công thức như `=HYPERLINK(...)` hiện
  đúng như đã gõ. Những ký tự có thể khiến một giá trị đọc ra thành giá trị khác, như ký tự đảo
  chiều chữ làm `0001` đọc thành `1000`, ký tự điều khiển và khoảng trắng độ rộng 0, đều hiện
  thành dấu như `⟨U+202E⟩`. Nút chép trong bảng của một ô chép chính giá trị đó, gồm cả những ký
  tự kể trên, không kèm dấu ngoặc kép bao quanh nó trong file.
</Aside>

### Tìm trong bảng

Nhấn Ctrl+F (Cmd+F trên macOS) trên bảng, dù đang chỉ xem hay đang sửa, thì một hộp tìm mở ra
ngay dưới thanh trên cùng; chữ tìm lần trước được chọn sẵn để gõ đè. Khác **Filter rows**, hộp tìm
không giấu dòng nào: ô khớp được tô nền, ô khớp hiện tại có thêm viền, và hộp đếm số ô khớp
(`3 of 17`). Nhấn Ctrl+F trong ô lọc, trong ô đang sửa hay trong bảng nhỏ thì vẫn là tìm của
trình duyệt.

- Enter và Shift+Enter trong hộp, hoặc F3 và Shift+F3 ở bất kỳ đâu trong bảng, đưa tới ô khớp kế
  tiếp hay ô trước đó, hết cuối thì vòng về đầu, và cuộn ô đó vào tầm nhìn. Bấm từ hộp thì con trỏ
  vẫn ở trong hộp; bấm từ một ô thì con trỏ sang ô khớp. Hộp đã đóng mà nhấn F3 thì hộp mở lại và
  đi tới ô khớp kế tiếp. Đang sửa trong ô mà nhấn F3 thì giá trị được ghi trước, như khi rời ô.
- Thứ tự ô khớp đi theo từng dòng đúng như đang hiện (sau khi sắp xếp và lọc), trong mỗi dòng thì
  theo các cột đang hiện. Dòng tiêu đề và cột ẩn không được tìm; khi có cột ẩn, hộp ghi rõ điều đó.
- Mặc định không phân biệt hoa thường và khớp một phần giá trị. **Aa** phân biệt hoa thường,
  **ab** có khung chỉ khớp khi cả giá trị trùng, còn **.\*** coi chữ gõ vào là biểu thức chính quy
  (JavaScript, có Unicode); biểu thức sai thì hộp báo `Invalid pattern`. Hộp tìm trên cả giá trị,
  kể cả phần quá 1024 ký tự mà ô không hiện. Ký tự làm chữ bị ẩn hay đảo thứ tự, nếu gõ vào hộp,
  hiện ngay bên dưới dưới dạng `⟨U+XXXX⟩`.
- Sau khi sửa, sắp xếp, lọc hay ẩn cột, bảng tìm lại: ô khớp hiện tại giữ nguyên chỗ nếu ô đó vẫn
  khớp, không thì chuyển sang ô khớp kế tiếp.
- Esc hoặc nút đóng tắt hộp tìm và đưa con trỏ về ô khớp hiện tại.

Biểu thức chính quy, và mọi lần tìm trên file lớn hơn 256 KiB, chạy tách khỏi trang nên bảng không
bao giờ bị treo; lần tìm nào chạy quá 10 giây (lần đầu là 30 giây, trong lúc phần tìm còn đang
tải) thì bị dừng và hộp báo `Search took too long`; biểu thức lồng quá sâu so với khả năng của
trình duyệt thì hộp báo `Search failed`. Hộp đếm tối đa 100.000 ô khớp (`100000+`).

### Chọn, chép và dán

Có chuột và bàn phím thì giữ Shift cùng phím mũi tên, Home, End, Page Up hay Page Down (cả
Ctrl+Home, Ctrl+End) để mở rộng một vùng ô tính từ ô đang chọn; Shift+nhấp, hoặc kéo chuột từ ô
này sang ô khác, chọn các ô ở giữa, và kéo tới gần mép trên hay mép dưới của bảng thì bảng tự cuộn.
Nhấn phím mũi tên không kèm Shift, nhấp một ô hay nhấn Esc thì bỏ vùng chọn. Trên điện thoại không
chọn vùng được.

- Ctrl+C (Cmd+C trên macOS), kể cả khi chỉ xem, chép vùng đang chọn, hoặc ô đang chọn, hoặc cả dòng
  khi đang ở số dòng, theo kiểu bảng tính: các ô cách nhau bằng tab, mỗi dòng một hàng, đúng thứ tự
  đang hiện và bỏ qua cột ẩn. Giá trị được chép đầy đủ, kể cả phần quá 1024 ký tự mà ô không hiện;
  giá trị có tab, xuống dòng hay dấu ngoặc kép được bọc trong ngoặc kép để khi dán vẫn nằm gọn trong
  một ô. Mỗi lần chép tối đa 100.000 ô.
- Ctrl+V khi đang sửa dán một khối chép từ bảng tính hay từ bảng khác, bắt đầu từ ô đang chọn (hoặc
  ô trên cùng bên trái của vùng chọn), theo các dòng và cột đang hiện, thành một thay đổi duy nhất
  mà một lần Ctrl+Z là lùi lại được; ô nhận đúng giá trị đang có thì giữ nguyên. Khối rộng hơn số
  cột còn lại thì bị từ chối. Khối dài hơn số dòng còn lại thì, khi bảng không sắp xếp và không
  lọc, hộp thoại hỏi có thêm số dòng cần thiết vào cuối không; đang sắp xếp hay lọc thì bị từ chối
  kèm lý do. Khi lưu, chỉ các ô được dán là đổi.
- Vùng chọn chứa vừa khít một số nguyên lần khối, cả theo chiều dọc lẫn chiều ngang, thì khối được
  lặp lại cho kín vùng, giống bảng tính: chép một ô thì mọi ô trong vùng đều nhận giá trị đó, chép
  một dòng thì mọi dòng của vùng cùng độ rộng đều nhận dòng đó, còn dòng nào trong khối thiếu ô thì
  các ô thiếu bị để trống. Vùng khác, hoặc số thứ tự dòng khi chưa chọn vùng nào, thì khối chỉ được
  dán một lần, từ ô trên cùng bên trái. Giới hạn 100.000 ô tính theo số ô của vùng được điền.
- Delete hoặc Backspace khi đang sửa xóa trắng mọi ô trong vùng chọn, theo các dòng và cột đang
  hiện, gộp thành một thay đổi mà một lần Ctrl+Z lùi lại được. Mỗi lần xóa tối đa 100.000 ô.
- Không cần cấp quyền clipboard, nên dùng được cả qua HTTP thường trong mạng LAN, và trên máy Mac
  khi không có chữ nào được bôi đen. Dán vào ô đang sửa, ô lọc hay hộp tìm thì chữ vào đúng ô đó.

### Sửa trong bảng

Bấm **Edit** khi file đang hiện dạng bảng thì bảng vẫn giữ nguyên và từng ô sửa được; thanh trên
cùng có **Cancel** và **Save** như với mọi file. Mở từ Changes, hoặc đang xem văn bản gốc, thì
file được sửa dạng văn bản.

- Chạm một ô để đổi giá trị của nó trong một bảng nhỏ hiện lên: giá trị có thể nhiều dòng, và
  những ký tự làm chữ bị ẩn hay đảo thứ tự hiện bên dưới dưới dạng `⟨U+XXXX⟩`. **Apply** đưa giá
  trị vào bảng; ô mà một dòng thiếu cũng đặt được giá trị.
- Dùng chuột thì giá trị được sửa ngay trong ô: nhấp đúp vào ô, hoặc nhấn F2 hay Enter trên ô đang
  chọn. Ô đang sửa cao dần theo nội dung, phủ lên các hàng bên dưới, hiện được tới 20 dòng (dài hơn
  thì cuộn bên trong) và rộng ít nhất 12rem. Nhấp một lần chỉ chọn ô, nên Ctrl+V khi đó dán cả khối
  (xem mục trên); chạm trên màn hình cảm ứng, kể cả của laptop, vẫn mở ô. Đang chỉ xem một file sửa
  được mà nhấp đúp vào ô thì bảng chuyển sang sửa trước. Enter ghi giá trị, Shift+Enter hay
  Alt+Enter xuống dòng, Esc bỏ những gì vừa gõ; bảng vẫn ở chế độ sửa, muốn thoát thì bấm
  **Cancel**. Tab và Shift+Tab ghi rồi sang ô kế tiếp hay ô trước, hết dòng thì sang dòng sau. Bấm
  ra chỗ khác, hoặc cuộn ô ra khỏi màn hình, cũng ghi giá trị. Nút ⤢ trong ô mở bảng nhỏ của ô với
  những gì bạn đang gõ, rộng chỗ hơn và có **Add row below**, **Delete row**. Giá trị dài hơn 1024
  ký tự, hoặc có ký tự làm chữ bị ẩn hay đảo thứ tự, thì mở thẳng trong bảng nhỏ.
- Có bàn phím thì gõ ngay trên ô đang chọn là bắt đầu sửa ô đó, chữ gõ vào thay cho giá trị cũ (Esc
  giữ lại giá trị cũ); đang chỉ xem file thì bảng chuyển sang sửa trước. Giá trị mà ô không sửa tại
  chỗ được thì mở bảng nhỏ với chữ vừa gõ. Delete hay Backspace xoá trắng ô, một lần Ctrl+Z trả lại
  giá trị. Gõ bằng bộ gõ (IME) thì phím đầu tiên mở ô sửa: nếu chữ ghép đầu tiên không hiện trong
  ô, gõ lại chữ đó trong ô. Trên điện thoại, gõ trên ô không làm gì.
- **Insert row above**, **Add row below** (trong bảng nhỏ đó) và nút **Add a row at the end** thêm
  một dòng trống rồi mở ô đầu tiên của nó. **Delete row** hỏi trước khi xoá, và nói rõ khi đó là
  dòng đầu của file, tức dòng tiêu đề lúc **Header row** đang bật. Muốn xoá dòng tiêu đề, hãy tắt
  **Header row** trước: khi đó dòng tiêu đề thành một dòng mở được như mọi dòng khác.
- Khi đang sửa, menu ⋯ của tên cột có thêm các thao tác sửa dưới đây; nhấp phải vào một ô, hoặc
  nhấn Shift+F10 hay phím menu ngữ cảnh trên tên cột hay một ô, cũng mở đúng menu ấy.
  **Insert column left** và **Insert column right** thêm một cột trống: mỗi dòng đủ
  dài để có cột đó nhận thêm một dấu phân cách, ngoài ra không đổi gì; dòng ngắn hơn và dòng trống
  giữ nguyên. Khi **Header row** bật, tên cột mới được hỏi ngay (Esc thì để trống). **Delete
  column** hỏi trước và cho biết bao nhiêu ô có giá trị sẽ mất theo; không xoá được cột cuối cùng.
  Dòng nào chỉ còn một ô rỗng thì ô đó được ghi thành `""` để dòng không thành dòng trống. Mở từ
  một ô thì menu có thêm **Insert row above** và **Insert row below**.
- **Rename column** trong menu đó, F2 trên tên cột, hoặc nhấp đúp vào tên (lần nhấp đầu vẫn sắp
  xếp) cho sửa tên ngay tại chỗ khi **Header row** bật; trên màn hình cảm ứng, hoặc với tên mà ô
  sửa tại chỗ không nhận được, tên mở trong bảng nhỏ, và bảng nhỏ đó không thêm hay xoá dòng nào
  quanh dòng tiêu đề. Khi một cột được thêm, xoá, hoàn tác hay bị bỏ bằng **Cancel**, độ rộng,
  Wrap, cột ẩn và cột đang sắp xếp vẫn đi theo đúng cột của chúng; cột đã xoá mà Undo đưa lại thì
  có lại giá trị, nhưng không có lại độ rộng hay Wrap.
- **Undo** và **Redo**, hoặc Ctrl+Z và Ctrl+Shift+Z (Cmd trên macOS) khi đang ở bảng, lùi và tiến
  qua các thay đổi của bạn; Ctrl+S để lưu. Gõ trong bảng nhỏ, trong ô hay ô lọc thì Ctrl+Z và
  Ctrl+Shift+Z thuộc về chỗ đang gõ; Ctrl+S trong ô thì ghi giá trị rồi lưu file.
- Khi lưu, chỉ ký tự của những ô bạn đã đặt là đổi: giá trị cần ngoặc kép (chứa dấu phân cách,
  dấu ngoặc kép, xuống dòng, hay khoảng trắng ở đầu hoặc cuối) được bọc ngoặc, ô vốn có ngoặc vẫn
  giữ ngoặc, dòng hay cột mới dùng dấu phân cách và kiểu xuống dòng của file. Mọi byte khác giữ
  nguyên.
- Trong lúc sửa không đổi được dấu phân cách. Nếu dấu bạn đang dùng để xem khác dấu dò được trong
  file, Edit hỏi trước: ghi bằng dấu khác có thể làm lệch cột.
- Sắp xếp và lọc vẫn dùng được khi sửa, và không bao giờ đổi file.

Nếu file trên máy đã đổi từ lúc bạn mở, Save báo như vậy và không ghi gì. **Reload and reapply**
đọc lại file rồi áp từng thay đổi của bạn vào đúng dòng đã sửa. Dòng được tìm theo các giá trị
của nó chứ không theo số thứ tự, nên một dòng agent thêm hay xoá phía trên không ảnh hưởng gì.
Thay đổi nào không còn dòng của nó, hoặc khớp với nhiều hơn một dòng, sẽ được liệt kê kèm lý do,
và giá trị của ô đó chép được để đặt lại bằng tay. Các thay đổi nằm sau một lần thêm hay xoá dòng
không áp được cũng được liệt kê, vì chúng có thể nhắm vào chính dòng đó. Cột được thêm hay xoá
thì được tìm lại theo tên ở dòng tiêu đề, dù cột đó đã dời đi đâu; khi **Header row** tắt thì
tìm theo vị trí, miễn file vẫn có đúng số cột như trước. Không còn cột đó, hoặc có hai cột cùng
tên, thì thay đổi ấy được liệt kê, cùng mọi thay đổi sau nó. Khối đã dán cũng tìm lại từng dòng
của nó theo cách đó, và chỉ được áp khi tìm đủ mọi dòng, nên khối có một dòng trùng với dòng khác
(chẳng hạn hai dòng trống) sẽ được liệt kê; các dòng khối đó đã thêm thì được thêm lại vào cuối
file mới. Nếu file đọc lại không
còn là bảng sửa được, không thay đổi nào được áp và Save vẫn tắt. Chưa có gì được lưu cho tới khi
bạn bấm Save.

## Ảnh

File PNG, JPEG, GIF hoặc WebP (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) mở ra thành hình, co vừa
chiều rộng của view, trên nền kẻ ô vuông để thấy được phần trong suốt. Bên dưới hình ghi kích
thước tính bằng điểm ảnh và dung lượng file. Server xem nội dung file chứ không chỉ dựa vào tên: file đặt
tên `.png` mà bên trong là thứ khác thì không được hiện.

File SVG mở ra ở dạng mã nguồn trước, như mọi file văn bản. Nút **Image** trên thanh của file
chuyển qua lại giữa mã nguồn và hình; máy này sẽ nhớ lựa chọn đó. Trong Changes, cũng nút này
chuyển qua lại giữa diff và hình.

**Xem toàn màn hình.** Chạm hoặc bấm vào một ảnh (trong Files, hay bên nào cũng được trong
Changes) hoặc một sơ đồ Mermaid trong bản xem trước Markdown để mở nó toàn màn hình:

- Trên điện thoại: chụm hai ngón để phóng to, một ngón để kéo, chạm hai lần để phóng to (chạm
  hai lần nữa để về vừa màn hình). Trang phía sau đứng yên.
- Trên máy tính: con lăn chuột (hoặc chụm hai ngón trên bàn di chuột) phóng to quanh con trỏ,
  kéo chuột để di chuyển hình, còn các nút hoặc phím `+`, `-`, `0` lần lượt phóng to, thu nhỏ
  và đưa về vừa màn hình.
- Mức phóng đi từ một nửa đến gấp 8 lần cỡ vừa màn hình. Sơ đồ hoặc ảnh SVG được vẽ lại ở cỡ mới
  khi bạn dừng tay, nên vẫn sắc nét.
- Cử chỉ hay nút quay lại, nút đóng và phím Escape đều đóng nó, file vẫn ở nguyên chỗ cũ.

Trong **Changes**, ảnh có thay đổi hiện bản trước và bản sau: trên máy tính đặt cạnh nhau, trên
điện thoại xếp chồng lên nhau.

| Phía                         | Trước  | Sau              |
| ---------------------------- | ------ | ---------------- |
| Chưa đưa vào index (Changes) | index  | thư mục làm việc |
| Đã đưa vào index (Staged)    | `HEAD` | index            |

Ảnh mới chỉ có bản sau (ghi `Added`), ảnh đã xoá chỉ có bản trước (ghi `Deleted`). Ảnh đổi tên
lấy bản trước từ đường dẫn cũ, đường dẫn này ghi cạnh nhãn. Khi có conflict, chỉ hiện file đang
nằm trong thư mục làm việc. Hình được đọc lại khi bạn bấm Refresh hoặc khi trạng thái của file
đổi, chứ không phải 5 giây một lần.

| Hiện ra                                                        | Lý do                                                                    |
| -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `Larger than 10 MiB`                                            | Ảnh lớn hơn 10 MiB không được hiện                                        |
| `Too many pixels to show (over 40 megapixels)`                  | Ảnh (hoặc một khung hình GIF) quá 40 triệu điểm ảnh, điện thoại có thể không chứa nổi |
| `Not previewable (not a PNG, JPEG, GIF, WebP or SVG image)`     | Nội dung không thuộc các loại này (hoặc file SVG không có thẻ `<svg>`)   |
| `Stored in Git LFS: only the pointer is in git`                 | git chỉ giữ con trỏ Git LFS chứ không giữ ảnh; termote không tải ảnh về  |
| `The image could not be decoded`                                | Trình duyệt không đọc được file (file hỏng, hoặc định dạng nó không hỗ trợ) |
| `Busy, try again`                                               | Đang có nhiều ảnh được đọc cùng lúc; nút **Retry** đọc lại ảnh đó         |

Tên file thường chứa bí mật thì được hỏi trước, giống như với văn bản. File SVG mở thẳng bằng địa
chỉ của nó không bao giờ chạy script: server gửi file kèm một chính sách cấm script, và gửi dưới
dạng file tải về.

## Changes

Danh sách lấy theo `git status`, đọc lại mỗi 5 giây khi view đang mở và tab trình duyệt đang hiện.
Danh sách chia nhóm:

- **Conflicts**: file còn xung đột khi merge, chưa giải quyết
- **Staged**: thay đổi đã đưa vào index
- **Changes**: thay đổi trong thư mục làm việc, chưa đưa vào index
- **Untracked**: file mới git chưa theo dõi

Mỗi file có một chữ cái: `M` sửa, `A` thêm, `D` xoá, `R` đổi tên (kèm đường dẫn cũ), `C` sao chép,
`T` đổi loại, `U` xung đột, `?` chưa theo dõi. File vừa có thay đổi đã vào index vừa có thay đổi
chưa vào index nằm ở cả hai nhóm, mở từ nhóm nào thì thấy diff của phía đó. File chưa theo dõi mở ra thành
toàn bộ là dòng thêm.

Diff hiện từng hunk với số dòng cũ và mới (trên màn hình điện thoại hẹp chỉ còn một cột), dòng
thêm nền xanh, dòng xoá nền đỏ, vẫn giữ dấu `+` và `-` để không chỉ dựa vào màu.

| Hiện                             | Vì sao                                                                       |
| -------------------------------- | ---------------------------------------------------------------------------- |
| `Not a git repository`            | Thư mục của pane không nằm trong repo git nào                               |
| `Binary file changed`             | git báo thay đổi nhị phân; không có dòng nào để hiện                         |
| `Diff truncated at 1 MiB`         | Diff của file này dài hơn 1 MiB; chỉ hiện phần đầu                          |
| `Unresolved conflict`             | File đang xung đột được hiện nguyên, đúng như hiện có trong thư mục làm việc |
| `No longer changed`               | Trong lúc diff đang được đọc, git không còn liệt kê phía này của file        |
| `git took too long; trying again` | `git status` chạy quá 10 giây (repo rất lớn); view giãn dần các lần đọc lại  |

Repo con (`submodule`) không được liệt kê, nội dung bên trong cũng không được so sánh.

Diff cũng mở theo tab giống file trong Files (xem
[Mở nhiều file theo tab](#mở-nhiều-file-theo-tab)), nhưng Changes có dãy tab riêng:

- Mỗi phía của một file là một tab: diff đã vào index và diff chưa vào index của cùng một file là
  hai tab, tab phía index có thêm chữ `(staged)`. Tab đầu tiên, **Changes**, hiện danh sách.
- Bấm một lần là mở ở tab xem trước; bấm đúp (trên danh sách hoặc trên tab) hay bấm **Edit** thì
  tab được giữ lại. **Edit** mở trình sửa ngay trong tab đó, chuyển sang tab khác rồi quay lại thì
  trình sửa vẫn còn, kèm phần sửa chưa lưu. Back từ diff về danh sách, tab vẫn mở.
- Khi git không còn liệt kê một phía (đã commit, đã đưa vào index, đã hoàn lại), tab của phía đó
  đóng lại và app báo `No changes left in <file>`. Tab đang sửa thì vẫn ở lại.
- Đóng tab, giới hạn 10 tab, danh sách trên điện thoại, gốc đổi và file có thể chứa bí mật đều như
  trong Files.

Khi danh sách có hơn 15 mục, một ô **Filter changes…** hiện phía trên nó. Ô này giữ lại những file
có đường dẫn chứa chuỗi bạn gõ, không phân biệt hoa thường (với file đổi tên, đường dẫn cũ cũng
được tính). Nhóm không còn mục nào thì ẩn, số đếm là số sau khi lọc, và khi không còn gì thì hiện
`No changes match`. Escape xoá ô. Bộ lọc chỉ nằm trong trang: nó được xoá khi bạn rời view hoặc
khi gốc đổi.

## File có thể chứa bí mật

File có tên thường dùng để chứa bí mật được đánh dấu bằng ổ khoá và chữ `Sensitive`: ví dụ
`.env`, `.env.*`, `*.env` và `.envrc`, khoá riêng (`*.pem`, `*.key`, `*.jks`, `id_rsa*`,
`id_ed25519*`), `.netrc`, `.npmrc`, `.pgpass`, `.my.cnf`, `.vault-token`, `.git-credentials`,
`credentials*`, `auth.json`, `secrets.*`, `.dev.vars`, state và biến của Terraform (`*.tfstate`,
`*.tfvars`) và
mọi thứ trong `.ssh`, `.gnupg`, `.aws`, `.kube`, `.docker`, `.config/gh` hoặc `.config/gcloud`.
Link trỏ tới một file như vậy cũng tính, file đổi tên từ hoặc thành một file như vậy cũng tính.

Khi mở, Termote hỏi trước `This file may contain secrets. Show its contents?`, cả với file lẫn
diff của nó. Câu trả lời không được nhớ: lần sau mở lại, Termote lại hỏi. Server tự kiểm tra lại:
chưa xác nhận thì server không gửi chút nội dung nào.

<Aside type="caution">
  Ổ khoá chỉ là cảnh báo dựa theo tên, không phải bảo đảm. Bí mật nằm trong một file có tên bình
  thường (`prod-creds.yaml`) vẫn hiện mà không hỏi. Ai đăng nhập được Termote đều đọc được mọi file
  trong thư mục của pane.
</Aside>

## Không bao giờ hiện

Một số đường dẫn không bao giờ được trả về (hay được lưu, tạo file trong đó, xoá, hay tìm theo
tên), kể cả khi đã xác nhận:

- Thư mục cấu hình và trạng thái của chính Termote (mật khẩu đã lưu, log) và thùng rác của nó
- `/proc`, `/sys` và `/dev` (biến môi trường của tiến trình và thiết bị)
- Thư mục `.git` của repo, thư mục này cũng không hiện trong Files

Server kiểm mọi đường dẫn so với gốc: `..`, đường dẫn tuyệt đối và link dẫn ra ngoài gốc đều bị từ
chối.

## Termote chạy git ra sao

Termote tự chạy `git status` và `git diff` để lấy dữ liệu cho Changes, và `git cat-file` để đọc
bản trước và bản sau của ảnh. Cấu hình riêng của một repo
không thể khiến Termote chạy chương trình nào: với các lệnh này, Termote tắt bộ theo dõi hệ thống
file, filter driver, công cụ diff bên ngoài và bước chuyển đổi văn bản, đồng thời bỏ qua repo con.
Mỗi lúc chạy tối đa hai lệnh git, mỗi lệnh giới hạn 10 giây.
