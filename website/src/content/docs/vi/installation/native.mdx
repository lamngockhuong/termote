Server native chạy thẳng trên máy, nên các terminal của nó thấy được công cụ của bạn: `claude`, `git`, `gh` và
những lệnh khác. Chính termote truyền luồng terminal (PTY trên Unix, ConPTY trên Windows) tới xterm.js trong PWA,
nên không phải cài thêm tiến trình terminal nào khác.

## Yêu cầu

termote cần một backend terminal: **tmux** (trên Windows là **psmux**) hoặc một server
**[Herdr](https://herdr.dev/#install)** đang chạy (xem [Backend Herdr](#backend-herdr)); chỉ cần một trong hai.

<Tabs>
  <TabItem label="Linux">

    ```bash
    # tmux
    sudo apt install tmux
    # hoặc dùng Herdr: xem https://herdr.dev/#install
    ```
  </TabItem>
  <TabItem label="macOS">

    ```bash
    # tmux
    brew install tmux
    # hoặc dùng Herdr: xem https://herdr.dev/#install
    ```
  </TabItem>
  <TabItem label="Windows">

    ```powershell
    # psmux: tmux-compatible multiplexer for Windows
    winget install psmux
    ```
  </TabItem>
</Tabs>

### Cấu hình tmux (Khuyến nghị)

Khi dùng backend tmux, để copy/paste hoạt động với các nút trên thanh công cụ, thêm dòng này vào `~/.tmux.conf`:

```bash
# Vi mode for copy: Space=start selection, Enter=copy
set-option -g mode-keys vi
# Mouse support (scroll, select) - toggle with Ctrl+b m
set-option -g mouse on
bind m set -g mouse \; display "Mouse #{?mouse,on,off}"
```

Áp dụng cấu hình:

```bash
tmux source-file ~/.tmux.conf
```

Cho phép: **Icon Copy** → di chuyển → **Space** → chọn → **Enter** → **Icon Paste**

<Aside type="tip" title="Copy ra bảng nhớ tạm của hệ thống">
  Khi bật chuột, tmux bắt sự kiện chuột. Để copy ra bảng nhớ tạm của hệ thống:
  - **Giữ Shift** khi chọn chữ (vượt qua tmux, dùng vùng chọn của terminal)
  - Hoặc nhấn **Ctrl+b m** để tạm tắt chuột
</Aside>

## Cài đặt

<Tabs>
  <TabItem label="Linux / macOS">

    ```bash
    curl -fsSL https://termote.ohnice.app/install.sh | sh
    termote start
    ```
  </TabItem>
  <TabItem label="Windows (PowerShell)">

    ```powershell
    irm https://termote.ohnice.app/install.ps1 | iex

    ```
  </TabItem>

Sau đó mở http://localhost:7680 (Windows: http://localhost:7690). Cách cố định phiên bản và vị trí các file nằm ở
trang [Bắt đầu](/vi/getting-started/).

## `termote start` làm những gì

<Steps>
1. **Chọn backend** ở lần đầu: Herdr nếu server của nó trả lời trên socket (`$HERDR_SOCKET_PATH`, nếu không có
   thì `herdr.sock` trong thư mục config của Herdr: `$XDG_CONFIG_HOME/herdr` hoặc `~/.config/herdr`; trên Windows
   là `%APPDATA%\herdr`, kết nối tới `\\.\pipe\` cộng đường dẫn đó), tmux (trên Windows là psmux) nếu đã được cài. Khi có cả hai, nó hỏi bạn; nếu không có terminal để
   hỏi, nó chọn tmux và in ra cách đổi. Khi không có cái nào, nó dừng lại và gợi ý cách cài. Lựa chọn được lưu
   lại và không dò lại nữa, trừ khi bạn truyền `--mux`.

2. **Tạo mật khẩu admin** ở lần đầu (hoặc khi có `--fresh`): gõ một mật khẩu, hoặc nhấn Enter để tự sinh. Mật
   khẩu chỉ được in ra một lần; về sau `termote show-password` sẽ hiện lại.

3. **Kiểm tra cổng và Tailscale trước.** Nếu có gì hỏng, server đang chạy vẫn được giữ nguyên, nên một lần gõ
   sai không cắt kết nối mà bạn có thể đang dùng.

4. **Đăng ký `termote serve` với trình quản lý dịch vụ** rồi khởi động nó (xem bảng dưới), chờ tới khi server
   báo đúng phiên bản này, sau đó in ra các URL, các tên host được phép và thông tin đăng nhập. Nó luôn cảnh báo
   khi tắt xác thực hoặc bật truy cập LAN.

</Steps>

| Hệ điều hành                         | Trình quản lý dịch vụ                                                    | Cách hoạt động                                                                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Linux                                | systemd user unit `~/.config/systemd/user/termote.service`               | Tự chạy lại sau khi sập; tmux cùng các phiên dòng lệnh bên trong vẫn sống qua stop, restart và sập. Chỉ chạy khi bạn đang đăng nhập: `loginctl enable-linger $USER` giữ nó chạy sau khi đăng xuất và khởi động nó lúc bật máy (`start` có in gợi ý này) |
| Linux không có user systemd (WSL2)   | Tiến trình chạy tách rời kèm file PID                                    | Không tự chạy lại sau khi sập hay khởi động lại máy; `start` có báo điều này. Hãy chạy lại `termote start`, hoặc bật systemd trong WSL (`[boot]` `systemd=true` trong `/etc/wsl.conf`) |
| macOS                                | launchd agent `~/Library/LaunchAgents/app.ohnice.termote.plist`          | Tự chạy lại sau khi sập, khởi động khi đăng nhập; tmux vẫn sống                                                                                                        |
| Windows                              | Scheduled Task `Termote` khi đăng nhập, chạy ẩn                          | Không cần quyền quản trị. Nếu chính sách hệ thống không cho tạo Scheduled Task, một trình khởi chạy ẩn trong thư mục Startup được dùng thay (khi đó không tự chạy lại sau khi sập)      |

Unit, plist hay tác vụ đã lập lịch đều không chứa mật khẩu hay bất kỳ biến `TERMOTE_*` nào.

<Aside type="note" title="Windows">
  Phần cài dịch vụ trên Windows mới có từ bản 1.0. Nếu có gì không chạy, hãy báo trên
  [GitHub](https://github.com/lamngockhuong/termote/issues).
</Aside>

## Tùy chọn khởi động

Mọi tùy chọn đều được lưu. Cờ nào bạn không truyền thì giữ giá trị đã lưu, nên `termote start` không kèm cờ nào
sẽ khởi động server y như lần trước. Tùy chọn kiểu bật/tắt được tắt bằng `=false`.

| Tùy chọn                    | Mô tả                                                                  |
| --------------------------- | ---------------------------------------------------------------------- |
| `--port <port>`             | Cổng (mặc định 7680; Windows 7690)                                     |
| `--lan[=false]`             | Lắng nghe trên mọi giao diện mạng thay vì chỉ `127.0.0.1`              |
| `--tailscale <host[:port]>` | Công khai qua [Tailscale HTTPS](/vi/installation/tailscale/) (mặc định 443) |
| `--no-tailscale`            | Ngừng công khai qua Tailscale                                          |
| `--no-auth[=false]`         | Tắt đăng nhập                                                          |
| `--mux <tmux\|herdr>`       | Backend terminal (mặc định: dò tìm ở lần đầu)                          |
| `--allow-host <name>`       | Cho phép thêm một tên trong header `Host` (lặp được, không có ký tự đại diện) |
| `--remove-host <name>`      | Bỏ một tên đã cho phép (lặp được)                                      |
| `--allow-herdr-no-auth`     | Bắt buộc khi dùng `--mux herdr --no-auth`                              |
| `--user <name>`             | Tên đăng nhập (mặc định `admin`; dùng chung với container)             |
| `--fresh`                   | Đặt mật khẩu mới                                                       |

```bash
termote start --lan                  # also reachable from the LAN (saved)
termote start                        # same options as last time
termote start --lan=false            # back to this machine only
termote start --allow-host box.local # accept another host name
termote start --remove-host box.local
termote start --fresh                # new password
termote start --user alice           # log in as alice instead of admin
```

Các tên host luôn được phép gồm địa chỉ nội bộ của máy (`localhost`, `127.0.0.1`), tên Tailscale, các tên trong `--allow-host`, và khi có `--lan` thì cả
địa chỉ mà request đi tới (nhờ vậy vẫn chạy khi IP LAN đổi). Request tới tên khác nhận lỗi 403, trong đó ghi sẵn
lệnh `termote start --allow-host <name>` cần chạy.

<Aside type="caution" title="Dùng một host name riêng cho Termote">
  Trình duyệt gửi cookie của một trang tới mọi cổng của cùng host name. Vì vậy một dịch vụ web khác trên cùng tên
  (một cổng khác của cùng server, một ứng dụng khác trên cùng domain) sẽ nhận cookie session của Termote mỗi khi bạn
  mở nó, tức là có luôn một terminal đã đăng nhập. Trên server còn chạy thứ khác, hãy mở Termote qua một tên chỉ
  mình nó dùng: tên Tailscale, hoặc một tên riêng như `termote.example.com`. Với thiết bị không còn dùng, hãy chọn
  `Log out` trong menu **More**.
</Aside>

## Backend Herdr

Linux, macOS và Windows đều có thể điều khiển workspace của Herdr thay cho tmux (trên Windows là psmux). Herdr phải đang chạy sẵn trên máy này
([cài Herdr](https://herdr.dev/#install)); Termote chỉ giao tiếp với socket của nó. Nếu Herdr đang chạy ở lần
`start` đầu tiên, nó được chọn tự động; nếu không thì chạy:

```bash
termote start --mux herdr
```

<Aside type="caution" title="Herdr hoạt động khác tmux">
  - Chọn tab hoặc pane trên PWA **không** thay đổi nội dung đang hiện trên desktop của Herdr,
  mà chỉ đổi pane mà client đang nhận luồng. Không có nút "hiện trên desktop".
  - Mỗi pane có một huy hiệu trạng thái agent (`idle`/`working`/`blocked`/`done`), được làm mới
  tối đa một lần trong mỗi khoảng làm mới đã cấu hình; trạng thái không được đẩy về ngay lập tức.
  - Đây là Herdr trên máy của bạn. Container chạy Herdr riêng của nó, xem
  [Cài đặt Container](/vi/installation/docker/#backend-terminal).
  - `--mux herdr --no-auth` bị từ chối nếu không kèm `--allow-herdr-no-auth`. Herdr để lộ mọi
  workspace trên máy chứ không riêng pane mà PWA đang hiện, nên muốn chạy không mật khẩu thì
  phải chủ động bật tùy chọn này.
</Aside>

## Quản lý server

```bash
termote status          # what the running server reports (version, backend, pid)
termote stop            # stop it; it starts again at the next login
termote restart         # stop and start with the saved options
termote logs            # recent lines of every log
termote logs server     # server log only
termote logs follow     # tail live (Ctrl+C to stop)
termote logs clean      # delete the log files
termote show-password   # print the saved username and password
```

Dịch vụ chạy `termote serve`, lệnh này đọc cấu hình đã lưu. Khi đã có file cấu hình, các biến môi trường
`TERMOTE_*` bị bỏ qua, và `serve` xóa chúng khỏi môi trường của mình để không terminal nào thừa hưởng chúng.

## Cập nhật

```bash
termote update                   # newest stable 1.x release
termote update --version 1.0.1   # a specific version
termote update --force           # reinstall the current version
```

`update` tải bản phát hành về và kiểm tra `.sha256`, và từ bản 1.10.0 trở đi kiểm cả chữ ký của bản phát hành: một
tệp nén không được khoá phát hành của Termote ký sẽ bị từ chối, kể cả khi mã băm khớp. Sau đó nó cài bản mới cạnh bản hiện tại, chuyển sang bản mới, khởi động lại
dịch vụ rồi chờ tới khi server báo phiên bản mới và tiếp tục trả lời. Nếu không được như vậy, nó chuyển về bản
trước và khởi động lại bản đó. Bản hiện tại và bản trước đều được giữ lại; cấu hình và phần đăng ký dịch vụ không
đổi. Lệnh này chạy được ngay cả khi gõ trong một pane của Termote.

`update` từ chối chạy trong thư mục mã nguồn clone bằng git (ở đó hãy dùng `git pull && make build`) và với binary không do
trình cài đặt đặt vào.

## Gỡ cài đặt

```bash
termote uninstall
```

Lệnh này gỡ phần đăng ký dịch vụ, ánh xạ Tailscale của Termote, lệnh `termote` và thư mục cài. Cấu hình
(`~/.config/termote`) và log (`~/.local/state/termote`) vẫn còn; `uninstall` in ra cả hai đường dẫn để bạn tự xóa.
Trên Windows, `%APPDATA%\termote` và `%LOCALAPPDATA%\termote\state` được giữ lại.

## Ngăn macOS ngủ

macOS tự động ngủ sau một thời gian không hoạt động, làm ngắt các phiên terminal từ xa. Dùng `caffeinate` để giữ máy thức trong khi Termote đang chạy:

```bash
# Prevent system sleep (runs until you press Ctrl+C)
caffeinate -s

# Or run in background
caffeinate -s &

# Stop background caffeinate
pkill caffeinate
```

<Aside type="tip">
  Dùng `caffeinate -s` (chỉ chặn hệ thống ngủ) thay vì `-d` (chặn màn hình tắt); truy cập từ xa không cần màn
  hình bật.
</Aside>

## Khắc phục sự cố

### Chẩn đoán nhanh

```bash
termote status          # is it running, which version and backend
termote logs server     # last server log lines
```

### Sự cố thường gặp

| Sự cố                                    | Cách xử lý                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| `termote: command not found`             | Mở terminal mới, hoặc thêm `~/.local/bin` vào PATH như trình cài đặt đã in ra                |
| Không tìm thấy backend terminal          | Cài tmux (Windows: `winget install psmux`) hoặc khởi động Herdr, rồi chạy `termote start`    |
| Cổng đang bị dùng                        | `start` báo tên cổng; dừng chương trình kia hoặc chọn `termote start --port <port>`         |
| Host bị từ chối (403)                    | Chạy lệnh `termote start --allow-host <name>` mà thông báo lỗi ghi                           |
| Không giải mã được mật khẩu đã lưu       | File `secret` đã bị xóa hoặc thay: `termote start --fresh`                                   |
| Dừng khi bạn đăng xuất (Linux)           | `loginctl enable-linger $USER`                                                               |
| Không chạy sau khi khởi động lại (WSL2)  | Ở đó không có user systemd: chạy lại `termote start`, hoặc bật systemd trong WSL             |
| PWA cache cũ                             | menu More (⋯) → `Clear cache & reload` để làm mới                                                |

### Kiểm tra API

API nằm sau phần đăng nhập (`termote show-password` in ra mật khẩu):

```bash
curl -u admin:<password> http://localhost:7680/api/mux/health   # or the name set with --user
```
