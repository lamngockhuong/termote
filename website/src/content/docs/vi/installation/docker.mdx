`termote container up` chạy server trong container thay vì trên máy: termote (PWA + luồng terminal + API) và một
backend terminal (tmux hoặc Herdr) được đóng gói chung, kèm một thư mục workspace được mount từ máy. Hãy dùng cách
này khi các terminal không cần công cụ trên máy (như `claude` hay `git` đã cài trên máy).

## Yêu cầu

- Podman (được ưu tiên khi có cả hai) hoặc Docker, kể cả Docker Desktop hay Podman Desktop trên macOS và
  Windows.
- Lệnh `termote`, cài như ở trang [Bắt đầu](/vi/getting-started/). Không cần chạy `termote start`.

## Bắt đầu nhanh

<Steps>
1. Khởi động container

   ```bash
   termote container up
   ```

2. Mở http://localhost:7680 và đăng nhập bằng `admin` với mật khẩu được in ra.

3. (Tùy chọn) Mở cho mạng LAN; tùy chọn này được lưu như mọi tùy chọn khác

   ```bash
   termote container up --lan
   ```

</Steps>

## Cách container chạy

- Container dùng `ghcr.io/lamngockhuong/termote:<version>`, trong đó `<version>` là phiên bản của binary
  `termote`, nên container luôn khớp với lệnh đã khởi động nó. `container up` tải bản đó về, thay container
  `termote` cũ nếu có rồi chờ tới khi server trả lời.
- Container chạy dưới user và group của bạn, với `--restart unless-stopped`, và mount thư mục workspace (mặc định
  `~/termote-workspace`, tự tạo nếu chưa có) vào `/workspace`. Nó cảnh báo khi workspace chứa thư mục nhạy cảm
  như `.ssh` hay `.aws`.
- Mật khẩu và cấu hình đi qua biến môi trường của tiến trình `docker`/`podman` (`-e TÊN`, không kèm giá trị), nên
  chúng không bao giờ xuất hiện trên dòng lệnh hay nằm trong file nào trên đĩa (`docker inspect` vẫn thấy, như với
  mọi biến môi trường).
- Cấu hình container được lưu riêng với các tùy chọn `termote start` của bản native, nhưng hai bên dùng chung mật
  khẩu admin: mật khẩu mới (`--fresh`) áp dụng cho cả hai, và server native nhận nó ở lần `termote restart` tới.
- Cổng mặc định của container là 7680. Nếu server native đang giữ cổng đó, `container up` từ chối và gợi ý dùng
  `--port`.
- Khi chạy từ thư mục mã nguồn clone bằng git, hoặc với `--build`, nó tự dựng `termote:local` từ Dockerfile
  thay vì tải về.

## Backend terminal

Image có sẵn cả tmux lẫn [Herdr](https://herdr.dev), nên không phải cài hay dò gì thêm. Lần `container up` đầu tiên
không có `--mux` sẽ hỏi bạn muốn dùng backend nào; nếu không có terminal để hỏi, nó dùng tmux và in cách chuyển
sang Herdr. Lựa chọn được lưu cùng cấu hình container, tách khỏi `--mux` của bản native:

```bash
termote container up --mux herdr   # workspace Herdr và huy hiệu trạng thái agent
termote container up               # giữ backend đã lưu
termote container up --mux tmux    # quay lại tmux
```

<Aside type="caution" title="Herdr trong container">
  - Herdr chạy ngay bên trong container, nên chỉ thấy các terminal của container, không thấy server Herdr hay
  các agent đang chạy trên máy của bạn.
  - Trong container không có client Herdr nào gắn vào, nên pane giữ nguyên kích thước do Herdr đặt; PWA co giãn
  terminal cho vừa kích thước đó chứ không đổi kích thước pane.
  - `--mux herdr --no-auth` bị từ chối nếu không kèm `--allow-herdr-no-auth`, giống `termote start`.
</Aside>

<Aside type="note" title="Sau khi khởi động lại máy">
  Docker có tiến trình nền tự chạy lại container sau khi khởi động lại máy. Podman chạy dưới user thường thì không
  có tiến trình nền đó, nên container vẫn dừng; muốn nó chạy lại sau mỗi lần khởi động, hãy chạy nó dưới dạng systemd unit
  [Quadlet](https://docs.podman.io/en/latest/markdown/podman-systemd.unit.5.html).
</Aside>

## Tùy chọn

Giống `termote start`, mọi tùy chọn đều được lưu, cờ nào bạn không truyền thì giữ giá trị đã lưu, và tùy chọn kiểu
bật/tắt được tắt bằng `=false`.

| Tùy chọn                    | Mô tả                                                                  |
| --------------------------- | ---------------------------------------------------------------------- |
| `--port <port>`             | Cổng trên máy (mặc định 7680)                                          |
| `--lan[=false]`             | Mở cho mạng LAN (mặc định: chỉ máy này)                                |
| `--tailscale <host[:port]>` | Công khai qua [Tailscale HTTPS](/vi/installation/tailscale/) (mặc định 443) |
| `--no-tailscale`            | Ngừng công khai qua Tailscale                                          |
| `--no-auth[=false]`         | Tắt đăng nhập                                                          |
| `--mux <tmux\|herdr>`       | Backend terminal (hỏi ở lần đầu; không có terminal thì dùng tmux)      |
| `--allow-herdr-no-auth`     | Bắt buộc khi dùng `--mux herdr --no-auth`                              |
| `--allow-host <name>`       | Cho phép thêm một tên trong header `Host` (lặp được, không có ký tự đại diện) |
| `--remove-host <name>`      | Bỏ một tên đã cho phép (lặp được)                                      |
| `--workspace <dir>`         | Thư mục được mount vào `/workspace` (mặc định `~/termote-workspace`)   |
| `--fresh`                   | Đặt mật khẩu mới (dùng chung với server native)                        |
| `--build`                   | Tự dựng từ mã nguồn clone bằng git thay vì tải về                      |

<Aside type="note" title="Windows và --lan">
  Trên Windows, cổng của container chỉ mở trên localhost; `--lan` thêm một quy tắc chuyển tiếp cổng `netsh` và
  một quy tắc tường lửa, nên Windows sẽ hỏi quyền quản trị. `container down` gỡ chúng đi.
</Aside>

## Quản lý container

```bash
termote container status    # is it running, and what the server reports
termote container logs      # recent log lines
termote container logs -f   # follow the logs (Ctrl+C to stop)
termote container down      # remove the container (and its Tailscale mapping)
```

`termote stop`, `restart` và `uninstall` chỉ tác động lên server native; container có lệnh riêng.

## Cập nhật

`termote update` cập nhật lệnh, và phiên bản container đi theo lệnh. Chạy lại `container up` để container dùng
bản mới, với cấu hình đã lưu:

```bash
termote update
termote container up
```

## Ngăn macOS ngủ

macOS tự động ngủ sau một thời gian không hoạt động, làm ngắt các phiên terminal từ xa, kể cả khi container đang chạy. Dùng `caffeinate` để giữ máy thức:

```bash
# Prevent system sleep (runs until you press Ctrl+C)
caffeinate -s

# Or run in background
caffeinate -s &

# Stop background caffeinate
pkill caffeinate
```

<Aside type="tip">
  Dùng `caffeinate -s` (chỉ chặn hệ thống ngủ) thay vì `-d` (chặn màn hình tắt); truy cập từ xa không cần màn
  hình bật.
</Aside>

## Khắc phục sự cố

### Gỡ lỗi bên trong container

```bash
docker exec -it termote /bin/sh
# Inside container:
ps aux                        # Check processes (termote, tmux)
```

Nếu bạn dùng Podman, thay `docker` bằng `podman`.

### Sự cố thường gặp

| Sự cố                             | Cách xử lý                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------- |
| Không có podman lẫn docker        | Cài một trong hai, rồi chạy lại `termote container up`                                      |
| Cổng đang bị dùng                 | Thường là server native: `termote container up --port <port>`, hoặc chạy `termote stop` trước |
| Không tải được bản container      | Bản thử nghiệm chỉ có bản container sau khi được phát hành; hãy cài một bản ổn định         |
| Server không trả lời              | `termote container logs` cho biết lý do                                                     |
| Mất sau khi khởi động lại (Podman)| Podman chạy dưới user thường thì không tự chạy lại: chạy lại `termote container up`, hoặc dùng unit Quadlet |
| Host bị từ chối (403)             | Thêm tên mà thông báo lỗi gợi ý: `termote container up --allow-host <name>`                 |
| PWA cache cũ                      | Settings → "Clear Cache & Reload" để làm mới                                                |

### Kiểm tra API

```bash
curl -u admin:<password> http://localhost:7680/api/mux/health
```

## Gỡ cài đặt

```bash
termote container down
```

Lệnh này xóa container; thư mục workspace và cấu hình đã lưu vẫn còn. Muốn gỡ cả lệnh, hãy chạy
`termote uninstall` (xem trang [Native](/vi/installation/native/#gỡ-cài-đặt)).

## Phát triển

`docker-compose.yml` trong repository chỉ dành cho phát triển từ một checkout. Mọi người khác dùng
`termote container up`.
